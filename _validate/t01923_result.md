## 根因

本单的判据是「**人耳** A/B 能否接受 64k@32000 作为长期默认档」，而本环境没有耳朵——
T01871 交出的只有 segSNR/LSD 这类客观指标（+1.41dB 不代表听众不觉得闷），
所以这一格同样填不了，属环境事实。

真正卡住的不是「听不了」，而是**连该听什么都没有被定义过**：原任务要求「3 个衔接点 + 片头 BGM 垫乐段 + 齿音段」，
但这三类锚点在 597s 的成品里到底在哪几秒，此前只能靠人耳去拖进度条找。本单把这件事做成可执行物料：
锚点用算法定位、三版对齐电平、标签随机盲化，听众只需要按表填。

## 影响范围

- 只新增 `_validate/` 下的物料与脚本，**不改生产代码、不改 `.env`、不写库、不触发 TTS/LLM 付费链路**；
- 服务于 `backend/app/core/audio_profile.py` 的 `DEFAULT_AUDIO_PROFILE` 是否维持 `standard` 这一决策；
- 与 T01922 是同一决策的两个必要条件（真机能放 ≠ 放着好听），两者都过才动默认档。

## 验证（实测证据）

A. 客观先验（参考=同段线上原码流解码 PCM，分析窗 8.0s/clip，5 段全出数）：

| clip | 锚点 | 64k@44100 segSNR/p10/LSD | 64k@32000 segSNR/p10/LSD | 6–9k / 9–12k 频带差 |
|---|---|---|---|---|
| clip01 | 衔接点 570.4s | 22.61 / 11.99 / 5.790 | **24.50** / 13.66 / 5.804 | -0.37,-0.46 / -0.35,-0.38 |
| clip02 | 衔接点 339.9s | 24.51 / 13.02 / 6.990 | **26.12** / 15.13 / **6.926** | -0.43,-0.50 / -0.42,-0.57 |
| clip03 | 衔接点 457.1s | 22.41 / 12.18 / 5.702 | **24.51** / 14.49 / 5.817 | -0.33,-0.38 / -0.28,-0.48 |
| clip04 | 片头 BGM 1.0s | 23.12 / **13.48** / **4.667** | 24.16 / 13.25 / 5.480 | -0.38,-0.50 / -0.38,-0.44 |
| clip05 | 齿音段 419.2s | 20.90 / 11.62 / 5.445 | **21.93** / **14.12** / **5.167** | -0.35,-0.34 / -0.30,-0.47 |

   - 五段上 32k 的 segSNR 全部高于 44.1k（**+1.03~+2.10dB**）；p10 仅 clip04 略低（13.25 vs 13.48）；
   - **有效频带（≤12kHz）两档差 ≤0.1dB**，差异全在 12k 以上的空频带（内容本就 <10kHz）；
   - 唯一在两档间反向变差的是 clip04 的 LSD（4.667→5.480，+0.81），加上 clip05 是全场 segSNR 最低
     （21.93）——所以**优先让人耳判的是「片头 BGM 是否变糊」和「齿音是否变钝」**，
     这两格已在记录表里标成重点；
   - 数字不替代耳朵，只用于提示「听不出差别是正常的，因为差得确实小」。

B. 生成过程自证：脚本 `exit=0`，15 个盲听文件 + key + 表全部落盘；
   `published` 版走 `-c copy`（零重编，帧头实测 MPEG-1 III/44100/128k），
   两个 64k 版由同一份源 PCM 编出（同代横向对比成立）。
