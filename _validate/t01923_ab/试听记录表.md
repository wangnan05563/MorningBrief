每个 clip 的三个版本（顺序已随机打乱，不同 clip 的字母含义不同，别凭第一组猜）：

| 版本代号 | 是什么 | 作用 |
|---|---|---|
| `published` | 线上成品原码流逐帧拷贝（`-c copy`，零重编） | **用户现在的听感**（128k@44100） |
| `64k44100` | 同段解码后重编 64k@44100 | T01871 之前的旧口径（同码率对照） |
| `64k32000` | 同段解码后重编 64k@32000 | **当前默认档 standard** |

三版电平已统一到 `published` 的 RMS 后再编，避免「响的那版听着更好」这种假优势。

## 二、客观先验（只用来提示「哪段最值得仔细听」，不是结论）

分析窗 = 8.0s/clip；参考 = 该 clip 的线上原码流解码 PCM；数值越高越好（segSNR），LSD 越低越好，
`band_delta` 是「参考比候选多多少 dB 能量」（正=候选丢得多）。

| clip | 锚点 | 64k@44100 segSNR / p10 / LSD | **64k@32000** segSNR / p10 / LSD | 6–9k / 9–12k 频带差（44.1k vs 32k） |
|---|---|---|---|---|
| clip01 | 衔接点 @570.4s | 22.61 / 11.99 / 5.790 | **24.50 / 13.66 / 5.804** | -0.37/-0.46 vs -0.35/-0.38 |
| clip02 | 衔接点 @339.9s | 24.51 / 13.02 / 6.990 | **26.12 / 15.13 / 6.926** | -0.43/-0.50 vs -0.42/-0.57 |
| clip03 | 衔接点 @457.1s | 22.41 / 12.18 / 5.702 | **24.51 / 14.49 / 5.817** | -0.33/-0.38 vs -0.28/-0.48 |
| clip04 | 片头 BGM @1.0s | 23.12 / 13.48 / 4.667 | **24.16 / 13.25 / 5.480** | -0.38/-0.50 vs -0.38/-0.44 |
| clip05 | **齿音段 @419.2s** | 20.90 / 11.62 / 5.445 | **21.93 / 14.12 / 5.167** | -0.35/-0.34 vs -0.30/-0.47 |

三个要点：

1. **有效频带（≤12kHz）里两档差别 ≤0.1dB** —— 降采样率没有在可闻频带上「少东西」；
2. 五个 clip 上 32k 的 segSNR 都高于 44.1k（+1.03~+2.10dB），p10 除 clip04 外也更高，与 T01871 A 段一致；
3. **clip05（齿音段）是全场最差的素材**（segSNR 20.9/21.9、LSD 最小的一档却在齿音上）——
   如果耳朵能听出 32k 的问题，最可能在这里；clip04 的 LSD 在两档间差 0.8（4.667→5.480），
   是 LSD 变差的唯一一段，**BGM 垫乐是第二重点**。

> 12k 以上的数字（如 16–20k +27dB）属于「空频带里的噪声底」，不参与听感判断，别拿来当结论。

判定口径（对完 `_blind_key.json` 的答案再下结论）：

- **维持 standard**：≥3 位听众里至少 2 位「无法稳定分辨」或分辨了但认为 32k 不差；

## 四、诚实边界（结论里要带上）

1. **人耳部分本环境无法代做**——包是 AI 生成的，判定必须由真人听完给出，`verified` 不能标 true；
2. 两个 64k 版本是从已发布成品（本身已是 128k MP3）**解码后再编，带一世代际**；
   干净的同代对比要等新链路真跑产出真实成品（前置 T01696，涉及付费 TTS，需授权）；
   即便如此，「32k vs 44.1k 同码率」这一对是**同一代内横向比**，代际只抬高了两者的共同基线，不影响相对结论；
3. 锚点是能量/谱心自动定位的近似，若真人认为「这不像 BGM 垫乐段/不像衔接点」，
   可直接改 `plan` 里的时间点重跑脚本（`_validate/t01923_ab_package.py`，改 `anchors` 即可）。
