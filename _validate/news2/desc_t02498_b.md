来源：T02498（FR-UX-304 登录失败可见）

## 问题

T02498 把失败原因做到了「看得见、留得住、能就地改」，但看不到的是**下一步该干什么**：

- 连续输错时，每次都是同一句「用户名或密码错误」，用户无法区分「密码错」与「账号不存在」
  （后端有意统一文案防账号枚举，这是对的，不能改），也没有任何找回/求助入口。
- 未确认后端是否存在失败计数与锁定策略：若账号会被锁定，页面却从不告知，
  用户只会以为「系统坏了」；若不锁定，也应明确「不会锁定，可重试」。
- 无节流/退避：可以无限快速重试（密码填充脚本无所谓，但真实用户手抖连点同样没有任何反馈差异）。

## 要做的事

1. 先查清事实再动 UI：`backend/app`（auth 路由 / user service）确认是否有失败计数、
   锁定阈值、解锁方式；把结论写进本单回传的「根因」。
2. 登录页在连续失败 ≥3 次时，在常驻横幅下方追加一行引导（不动横幅本身、不新增 toast）：
   - 有锁定策略 → 显示「还可尝试 N 次 / 已锁定请 X 分钟后重试或联系管理员」，
     并把后端的剩余次数/解锁时间如实透出（需要接口补字段则一并补，注意不要泄露账号存在性）。
   - 无锁定策略 → 显示「账号密码由管理员分配，忘记密码请联系管理员」，并给出联系人/入口
     （与 FR-UX-404 关于页的真实外链联动，若届时才有地址则先占为「联系管理员」文案）。
3. e2e 覆盖：第 3 次失败出现引导、成功后引导消失；断言不出现第二条提示出口。

## 验收

- 引导文案与后端真实策略一致（禁止显示不存在的「N 次后锁定」）。
- 新增/修改用例随 `tests/login-error-visible.spec.js` 或新 spec 落库，`npm run build` 通过。
