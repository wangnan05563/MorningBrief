来源：T02500（FR-UX-401 路由 meta 菜单校验脚本）

## 问题（本单留下的口径缺口）

T02500 的门禁能校验「引导路由键、引导 aria-label 选择器、帮助文档里 `进入「X」`/`「X」页面`
式菜单引用、侧栏分组、移动端手写入口」，但帮助文档的引用口径仍是**自然语言启发式**：

- `docSections` 是 Help.vue `<script setup>` 里的手写数组，条目与路由之间**没有结构绑定**
  （没有 `routes: ['/channels']` 这类字段）。
- 因此门禁只能用正则识别「进入「X」」「「X」页面」这两种句式当作菜单指引，
  非这种写法的指引（例如「侧栏 → 云端存储 → 文件管理」、「同页顶部切换」）漏检；
  而按钮名之类的「」（「审核通过」「驳回」「重试」）靠句式排除，属易碎的约定。
- 章节本身的标题（如「音频存储（COS）」）与真实菜单标题（云端配置 / 文件管理）对不上，
  「哪个章节讲哪个页面」目前只存在于人的理解里。

## 要做的事

1. 给 `docSections` 每个 section 增加 `routes: ['/cos-config', '/cos-files']` 字段
   （值必须是真实路由路径），章节标题与内容文案随之对齐；`quickstart` 这类跨页章节可留空数组。
2. 门禁改读结构化字段：section.routes 必须命中真实路由（新增一条 error 口径），
   原「进入「X」」正则保留为兜底但不作为唯一依据。
3. 帮助文档目录（页面左侧章节列表）可选做「按 meta.group 分组展示」，
   与侧栏同一分组顺序，避免用户在一个地方看到 8 组、另一个地方看到 15 篇。
4. `node --test scripts/validate-nav.test.mjs` 补一条「section.routes 指向不存在路由时报错」用例。

## 验收

- 帮助文档每个章节都能声明它对应的路由，门禁按声明校验；`npm run validate:nav` 与 `npm run build` 通过。
- 新增/修改的章节引用错误能被门禁抓出来（用一条临时改坏的 routes 验证后回滚）。
