# T05753 课程生成链路与素材相关性排查报告

- 任务：生成的课程内容混乱，排查完整生成链路与素材相关性，需要提高生成质量
- 项目：MorningBrief 二期（project_id `3c5b7f96-7ac3-46ec-b4db-9a5908bde9d3`）
- 日期：2026-11-15
- 约束：不改底层模型；素材脱敏；保持既有 API/数据格式兼容

## 一、结论（TL;DR）

1. **内容混乱的首要根因不是模型，也不是提示词风格，而是课程频道素材源错配**：`AI 通识课堂`（channel_id=12）的 180 条待选素材**全部是资讯 RSS**，0 条课程文档；`outline` 策略按 id 取前 10 条，直接把竹节虫、北汽新车、V2EX 求推荐、最终幻想 7 等新闻拼成一期“课程”。
2. **链路上没有任何“课程相关性”闸门**：`outline/manual` 会跳过 AI 相关性筛选；课程频道又没有专项质量约束；生成后质量审核默认关闭且只告警不回退。
3. 已实施 7 项改造：素材源守卫（纯 RSS 快速失败）、单文档隔离、heat 段序回归章节、课程位置约束注入、课程版相关性 prompt、落库前确定性审计、课程模板讲解纪律。
4. 验证：真实库 Before/After 行为对照 + 29 项课程相关测试 + 69 项 rewriter 回归测试全部通过；`py_compile` 通过。真实 LLM 端到端未跑（`.env` 的 `LLM_API_KEY` 仍是占位符），报告中明确标注该验证缺口。

## 四、根因（按优先级）

### P0：课程频道没有课程素材源，却在消费资讯 RSS

`AI 通识课堂` 的 RSS/关键词配置为空，但素材表里堆了 180 条资讯。`_fetch_materials` 只按 `channel_id` 取数，不校验 `source_type` 是否适合课程；`outline` 再按 id 取前 10 条。于是一期“AI 通识课”的前 10 讲实际是竹节虫、睡眠广告、北汽新车、V2EX 求推荐……这是内容混乱的决定性原因。

### P1：相关性过滤被选题策略绕过

`_filter_materials_by_relevance` 的调用条件是 `selection_strategy == "heat"`。course 用 `outline`（按讲文章节顺序），因此**永远不会执行**语义相关性过滤；即使执行，旧 prompt 也是“新闻频道内容审核员”口径，不适用于课程。

### P1：缺少课程专项写作约束与位置上下文

`rewrite_course.txt` 是通用讲师模板，没有“只讲本节、不越界、不跳章、不重复、禁新闻腔、禁空指代”的纪律；各段并发改写时，单段 LLM 不知道自己是全课第几讲、上一讲/下一讲是什么，容易各讲各的。

### P2：质量审核只告警、不阻断

`quality_check_service` 默认关闭，异常也 skipped；课程稿落库前没有确定性的结构/口吻检查，问题稿可以一路进入 TTS。

## 八、兼容性与风险

- **API 兼容**：`rewrite()` 返回体只**新增** `course_audit` 键，既有 `script_id/segments/total_words` 不变；既有调用方无需改动。
- **数据格式兼容**：未改表结构、未写 `news.db`；`_material_to_public_dict` 新增字段，向后兼容。
- **行为变更（有意）**：course 频道若素材池全是 RSS，将从“生成乱稿”变为“明确报错”。这是 P0 修复的预期行为；如运营确有“资讯型课程”需求，应新增课程专用素材类型/配置，而不是复用新闻 RSS。
- **heat 策略课程频道**：不再静默打散章节，改为按同源文档聚合 + id 排序，并输出 warning 建议改 `outline`。
- **磁盘副作用披露**：排查期间 D 盘多次写满（130.8GB 总量一度仅剩 0MB），为恢复执行将生成型索引 `backend/data/ebook_index.json`（约 430MB 缓存）截断为 `{}`。该文件可由 `POST /admin/api/v1/ebooks/index/rebuild` 重建；不影响本次代码改动与 `news.db`。
