## 1. 引言

### 1.1 编写目的

V1.2 基线定义了「AI 工作流 → 审核 → 发布 → 小程序播放」的全栈 MVP，V1.3 补充补齐了小程序端缺失功能（多频道切换、搜索、收藏、订阅消息、倍速、睡眠定时、隐私合规等），使小程序成为「可上线的资讯音频小程序」。

但当前小程序在**产品形态**上仍被「新闻」强约束：
- 内容组织以「今日节目 / 历史节目」为唯一心智模型，所有频道（无论资讯还是课程）都按「按日定时产出的一期音频」来展示；
- 频道接口（`GET /api/v1/channels`）**不含任何业务类型标识**，小程序无法区分「资讯频道」与「课程频道」；
- 缺乏「课程 / 章节 / 资料库 / 学习进度」这类面向「专业资料 → 语音学习」等扩展业务的语义与界面。

随着《业务范围扩展实施计划》落地后端 MVP（T1–T12：文档上传解析、素材去重置、选题策略 `outline`/`manual`、关广告、手动触发），系统将能产出「课程型频道」（每门课程 = 一个 Channel，每章 = 一次 workflow 产出的一期音频）。**本说明书定义小程序端为消费这类扩展业务所需的最小适配需求**，使同一个小程序既能听新闻、也能学课程，复用同一套播放/订阅/收藏/评论内核。

### 1.4 术语与缩略语

| 术语 | 含义 |
| --- | --- |
| 频道（Channel） | 系统的「内容产品配方」容器（`channel` 表），每个频道独立配置提示词/BGM/选题策略/是否投广告。资讯与课程均为频道的实例 |
| 频道类型（channel_type / kind） | **本文档新增概念**：区分频道业务形态的取值，如 `news`（资讯，按日节目）、`course`（课程，按章节）、`audiobook`（有声读物）等；后端 `channel` 表新增字段承载 |

| 学习进度 | 用户对某课程频道下各章节的收听完成情况；由既有 `playlogs` 进度能力聚合得到 |
| 学习中心 | 小程序内「我的课程」聚合页，展示已订阅/在学的课程与继续学习入口 |

### 1.6 业务背景与目标

现有系统本质是「内容生产流水线 + 媒体播放产品」，新闻只是当前的内容配方。将业务扩展到「专业领域资料 → 语音学习」是**配置化为主、小改造为辅、前端重皮肤为主要成本**的演进（详见《业务范围扩展可行性评估》）。

小程序端目标：在不引入多套 App 的前提下，让同一小程序承载「资讯」与「课程/资料」两类（未来可更多）业务，用户在一处完成「发现频道 → 订阅 → 收听/学习 → 追更」的闭环。

## 2. 总体约束与设计原则

### 2.1 继承的非功能约束（V1.2）

小程序端必须继承 V1.2 已确认的架构硬约束，**不引入多租户/横向扩容假设**：

1. **单机 SQLite + 单 worker + 进程内缓存**：读 p50≈16ms、写 ~15–26 req/s 的吞吐天花板；接口设计须以「读多写少、热点缓存」为前提（如频道列表 60s 缓存已存在，应保留并扩展）。
2. **复用优先**：播放/订阅/收藏/评论/历史/进度/搜索等内核**零改动复用**，不对扩展业务另起一套播放引擎。
3. **动态频道**：频道增删与顺序由后端 `display_order` 控制，小程序不应写死频道列表（V1.3 已落地胶囊切换，本说明书延续并扩展为分组）。

### 2.2 频道类型模型（核心概念）

> 这是本次适配的基石：后端 `channel` 表新增 `channel_type` 字段（默认 `news`），C 端频道接口随行返回；小程序据此选择渲染形态。

| channel_type | 业务语义 | 一期组织形态 | 小程序主界面 |
| --- | --- | --- | --- |
| `news` | 资讯（存量兼容） | 按日节目（今日/历史） | 「今日节目」列表（沿用 V1.3） |
| `course` | 课程（首个扩展场景：专业资料语音学习） | 按章节（每章一期） | 「课程主页」：封面 + 章节列表 + 学习进度 |
| `audiobook` | 有声读物（未来同构扩展） | 按章节 | 同 `course` 形态，文案差异 |
| （预留） | 其他同构场景 | — | 按 `channel_type` 映射 UI 皮肤 |

**关键决策**：频道类型由**后端配置**决定，小程序仅做「类型 → 皮肤」映射，不感知具体业务规则（如「课程怎么生成」是后端的事）。新增业务类型时，小程序仅需扩展一个皮肤分支 + 复用内核，无须改播放链路。

### 2.3 适配范围边界（对齐 M1/M2/M3）

| 阶段 | 范围 | 小程序侧工作量 | 验收 |
| --- | --- | --- | --- |
| **M1** 后端全链路 | 文档上传 → 自动生成可播放语音课（API 验证） | 几乎无（仅联调频道类型字段） | 后端 T1–T12 |
| **M2 产品化（本文档主战场）** | admin-web 课程页 + 小程序多频道皮肤 | 课程主页/章节/学习中心/订阅适配/搜索筛选 | 本文档 FR-MC-01~12 |
| **M3 平台化（P2，非默认）** | 多租户隔离 + MySQL/Redis | 不在本说明书范围 | 另立项 |

## 3. 现状分析（小程序端）

### 3.1 已具备的多频道基础（可直接复用）

| 能力 | 现状 | 对多频道适配的价值 |
| --- | --- | --- |
| 频道列表接口 | `GET /api/v1/channels` 返回 `id/name/description/is_subscribed/display_order` | 仅需扩展 `channel_type` 等字段即可驱动分组 |
| 频道切换胶囊 | `pages/index` 顶部胶囊 + `pages/channels` 订阅页（V1.3 FR-SUP-03） | 复用为「频道/分组切换」入口 |
| 按频道过滤的今日/历史 | `GET /api/v1/episodes/today?channel_id=` `/history?channel_id=` | 课程频道可复用 `history` 接口按 `published_at` 取章节列表 |
| 播放内核 | `services/audio.js` 全局单例（倍速/睡眠/续播/队列） | 课程章节直接复用，无需改造 |
| 订阅/收藏/评论/历史 | 均已可用（V1.3 补齐） | 课程频道复用同一套用户关系 |
| 搜索 | `GET /api/v1/episodes/search?keyword=` | 跨类型搜索直接复用 |

### 3.2 待改造 / 缺失点（面向扩展业务）

| 编号 | 缺口 | 现状 | 影响 |
| --- | --- | --- | --- |
| GAP-MC-01 | 频道无类型标识 | `channels` 接口无 `channel_type`，小程序无法区分新闻/课程 | 课程只能当成「新闻」展示，语义错乱 |
| GAP-MC-02 | 无课程/章节心智模型 | 全站只有「今日节目/历史节目」 | 课程用户找不到「目录」「学到第几章」 |
| GAP-MC-03 | 无学习进度 | `playlogs` 仅存播放位置，无「章节完成度/课程完成度」聚合 | 用户无法感知学习进展 |
| GAP-MC-04 | 无学习中心 | 仅有 `profile` 页（统计恒为 0，GAP-11 待修） | 已订阅课程散落，无「继续学习」聚合 |
| GAP-MC-05 | 订阅消息模板固化 | 仅「新节目上线」语义 | 课程应提示「新课/新章上线」 |
| GAP-MC-06 | 文案/皮肤强新闻化 | 「今日要闻」「新闻主播」等字眼写死在多处 | 课程场景文案违和 |
| GAP-MC-07 | 搜索/筛选未带类型 | 搜索结果无类型标签，无法按「课程/资讯」过滤 | 跨业务发现效率低 |
| GAP-MC-08 | 专业内容合规提示缺位 | 无「内容由 AI 生成，仅供参考，专业问题请咨询专业人士」类提示 | 医疗/法律类课程有合规风险 |

## 4. 功能性需求

> 优先级：P0 = MVP 必需；P1 = 产品化增强；P2 = 可选/未来。
> 所有 FR 复用既有内核（播放/订阅/收藏/评论/历史/搜索），仅新增「类型分支 + 课程语义 UI」。

### 4.1 FR-MC-01 频道类型数据模型与 C 端频道接口扩展

- **优先级**：P0
- **描述**：后端 `channel` 表新增 `channel_type`（默认 `news`，枚举 `news`/`course`/`audiobook`），C 端 `GET /api/v1/channels` 响应随行返回该字段及课程展示所需元信息；小程序据此渲染。
- **前置**：《业务范围扩展实施计划》T5（`selection_strategy`/`enable_ad` 已落地）已实现频道可配置化，本 FR 在其基础上补类型字段。
- **处理**：
  1. 后端 `Channel` 模型增加 `channel_type: Mapped[str] = mapped_column(String(16), default="news", comment="频道业务类型：news/course/audiobook")`；存量频道回填 `news`。
  2. `GET /api/v1/channels`（及带订阅态版本）响应对象增加字段（见 §6.1）。
  3. 小程序 `services/api.js#fetchChannels` 解析新字段并缓存于 `globalData.channelsMeta`（按 `id` 索引），供各页 O(1) 查类型。
- **输出/后置**：小程序任意页面均可 `channelType(id)` 拿到类型，决定走「今日节目」还是「课程主页」分支。
- **验收**：
  - 无 `channel_type` 字段的存量频道默认按 `news` 渲染，行为不变（向后兼容）；
  - 将某频道在后端置为 `course` 后，小程序频道列表/胶囊正确显示「课程」标识且点击进入课程主页。

### 4.2 FR-MC-02 首页频道分组与分类 Tab

- **优先级**：P0
- **描述**：首页顶部胶囊（V1.3 `onSwitchChannel`）在「我的偏爱 / 全部 / 各频道」基础上，**按 `channel_type` 分组展示**，让用户按业务类型快速定位；频道顺序仍由后端 `display_order` 控制。
- **处理**：
  1. `loadChannels()` 拿到列表后，按 `channel_type` 聚类：`资讯` 组（`news`）、`课程` 组（`course`/`audiobook`）等；分组标题由前端映射（可后端扩展 `type_label`）。
  2. 胶囊横向滚动，组间以分组标题/分隔线区隔；「全部」仍保留（聚合所有类型今日内容）。
  3. 点击课程类频道 → 进入课程主页分支（FR-MC-03）；点击资讯类 → 走既有「今日节目」分支。
- **验收**：
  - 资讯频道与课程频道在胶囊中分组清晰、不混淆；
  - `display_order` 调整后端顺序后，小程序无需发版即生效（延续 V1.3 动态频道原则）。

### 4.3 FR-MC-03 课程频道：课程主页与章节列表

- **优先级**：P0
- **描述**：当进入 `channel_type='course'` 的频道时，展示「课程主页」而非「今日节目」：课程封面/简介 + 章节列表（按 `published_at` 升序）+ 每章学习状态。
- **前置/复用**：复用 `GET /api/v1/episodes/history?channel_id={courseId}&sort_order=asc` 取章节（课程频道每章一期，正序即章节序）；`cover_url` 来自 `episode.cover_url`（若无则用频道默认封面）。
- **处理**：
  1. 新增页面或复用 `detail` 改造成「课程主页」容器（`pages/course/course` 或 `pages/channels` 详情态）。推荐新增 `pages/course/course` 独立页，参数 `?channelId=`。
  2. 课程主页区块：
     - 头部：课程封面、课程名（取频道 `name`）、简介（频道 `description`）、已学进度（FR-MC-04）。
     - 章节列表：每行 = 一章（标题=`episode.title`、时长=`duration`、状态=未学/学习中/已学完、上次学到位置）。
     - 操作：整体「继续学习」（跳到首个未学完章节并 seek 到进度）、「从头播放」。
  3. 章节行点击 → 复用 `detail` 播放页（FR-MC-04 适配），播放内核零改动。
- **验收**：
  - 课程频道主页正确展示章节顺序（第一章在最上）；
  - 章节行显示学习状态且与 `playlogs` 一致；
  - 「继续学习」跳转到正确章节与正确续播位置。

### 4.4 FR-MC-04 章节播放与学习进度

- **优先级**：P0
- **描述**：课程章节复用既有播放页（`pages/detail`），并在其上叠加「学习进度」语义：标记章节完成、聚合课程完成度。
- **复用**：`services/audio.js`（播放/倍速/睡眠/续播）、`services/local-data.js`（进度双写）、`playlogs` 上报/读取。
- **处理**：
  1. 章节完成判定：复用播放进度——单章播放进度 ≥ 95%（或自然播放结束 `onEnded`）即标记「已学完」，写入 `playlogs` 进度（既有机制已覆盖位置上报，需后端/前端约定「完成」阈值，建议 0.95）。
  2. 课程完成度聚合：前端基于「该课程章节总数 × 各章已学完标记」计算百分比；为性能与准确性，建议后端新增 `GET /api/v1/courses/{channel_id}/progress`（返回 `{total, learned, percent}`），前端首屏读缓存、播放结束后再拉（**P1，MVP 可纯前端聚合**）。
  3. `detail` 页在课程章节场景：隐藏「今日要闻」式文案，改显示「第 X 章 / 共 Y 章」与课程名；播放结束自动提示「下一章」或「课程已学完」。
- **验收**：
  - 听完一章后，课程主页该章状态变「已学完」、课程完成度 +1；
  - 退出重进后进度持久（依赖 `playlogs` + 本地 TTL 缓存，沿用 V1.3 续播机制）；
  - 播放结束自动连播下一章（复用 `audio.js` 队列 + `setQueue`）。

### 4.5 FR-MC-05 学习中心「我的课程」

- **优先级**：P1
- **描述**：在 `profile` 或新增「学习中心」入口，聚合用户已订阅/在学的课程频道，提供「继续学习」列表。
- **复用**：`subscriptions`（已订阅频道）、`playlogs`（进度）、`GET /api/v1/courses/{id}/progress`（P1）。
- **处理**：
  1. 入口：在 `pages/profile` 增加「我的课程」卡片（或底 tab「学习」），列出 `is_subscribed && channel_type in (course,audiobook)` 的频道。
  2. 每个课程卡：封面、名称、学习进度条（百分比）、「继续」按钮（跳课程主页并定位首章）。
  3. 未订阅任何课程时显示引导（去频道广场订阅）。
- **验收**：
  - 已订阅课程出现在学习中心，进度与课程主页一致；
  - 点击「继续」直达正确章节与续播位置。

### 4.6 FR-MC-06 频道/课程订阅与订阅消息适配

- **优先级**：P1
- **描述**：复用 V1.3 订阅能力（`subscribeChannel`/`unsubscribeChannel` + `wx.requestSubscribeMessage`），并让订阅消息模板适配业务类型。
- **处理**：
  1. `pages/channels` 与课程主页的订阅按钮复用既有逻辑；订阅课程频道后，该频道新章节上线可推送。
  2. 订阅消息模板文案按 `channel_type` 区分：资讯→「今日节目已更新」；课程→「新课/新章节已上线」。模板 id 由后端下发的 `subscribe_template_id`（按类型）决定，小程序不写死。
  3. 推送触发点：课程频道 `publish_episode` 成功后（后端既有发布链路）触发通知（后端职责，本 FR 仅定义小程序接收与跳转：点击通知跳课程主页）。
- **验收**：
  - 订阅课程频道后收到「新课上线」类通知；
  - 点击通知正确跳转到对应课程主页。

### 4.7 FR-MC-07 跨频道类型搜索与筛选

- **优先级**：P1
- **描述**：复用 `GET /api/v1/episodes/search`，搜索结果携带 `channel_type` 与频道名，支持按类型筛选。
- **复用**：V1.3 `pages/search` 与 `searchEpisodes`。
- **处理**：
  1. 搜索结果项增加「频道类型标签」（资讯/课程）与频道名，视觉区分。
  2. 搜索页增加类型筛选器（`全部/资讯/课程`），筛选条件透传后端（建议后端 `search` 支持 `channel_type` 参数，属后端小改造，记为依赖项 D1）。
  3. 课程类搜索结果点击 → 课程主页对应章节；资讯类 → 既有详情页。
- **验收**：
  - 搜索「合同法」既能命中资讯也能命中课程，结果带类型标签；
  - 按「课程」筛选仅剩课程章节结果。

### 4.8 FR-MC-08 文案与视觉皮肤通用化

- **优先级**：P0（基础，否则课程场景违和）
- **描述**：将散落在各页的强新闻化文案/图标抽象为「按 `channel_type` 映射」的资源，避免课程场景出现「今日要闻」「新闻主播」。
- **处理**：
  1. 建立 `skin` 映射（`utils/skin.js`）：`news`→{列表标题「今日节目」、空态「今日节目暂未上线」、图标…}；`course`→{列表标题「课程章节」、空态「课程章节尚未生成」、图标…}；未来类型加分支即可。
  2. 扫描并替换 `index/detail/channels` 等页写死的「今日要闻」「新闻」字眼，改为按 `skin(channelType)` 取值。
  3. 课程封面默认图、章节占位图等视觉资源补充。
- **验收**：
  - 课程频道全流程无「新闻」违和文案；
  - 切换频道类型时皮肤随之切换，无残留。

### 4.9 FR-MC-09 课程离线下载（可选 P2）

- **优先级**：P2
- **描述**：课程具「反复学习」属性，离线价值高于资讯。复用既有音频缓存能力（如有）或新增下载管理。
- **处理**：课程主页提供「下载整门课程 / 下载本章」；下载管理在 `profile` 或独立页；受 V1.2 单机约束，下载仅限本机存储，不涉及服务端。
- **验收**：无网络时可播放已下载章节；存储占用可读可清理。
- **说明**：与 V1.3 GAP-13「离线收听」宣称但未实现相关联，可一并规划。

### 4.10 FR-MC-10 埋点与学习统计

- **优先级**：P1
- **描述**：复用 V1.3 `utils/tracker.js`（已埋点但部分无调用），补齐课程场景事件，并修复 `profile` 统计恒为 0（GAP-11）。
- **处理**：
  1. 课程关键事件：`course_view`(课程主页曝光)、`chapter_play`、`chapter_finish`、`course_subscribe`、`continue_learn`。
  2. `profile` 统计从 `playlogs`/`progress` 聚合（学习时长、已学课程数、完成章节数），修复恒为 0。
- **验收**：课程播放产生埋点；`profile` 学习统计非空且准确。

### 4.11 FR-MC-11 合规与内容提示（专业/医疗/法律）

- **优先级**：P0（合规红线）
- **描述**：专业资料语音学习（尤其医疗/法律/财经）须明示「AI 生成、仅供参考」，并保留人工审核链路（后端 `review` 已具备）。
- **处理**：
  1. 课程主页/详情页显式展示「本内容由 AI 生成，仅供学习参考，专业问题请咨询持证专业人士」类提示条（文案随类型可配，医疗/法律更强提示）。
  2. 后端 `channel` 可配 `disclaimer_level`（none/normal/strong），小程序按级展示提示强度（**依赖项 D2：后端加 `disclaimer_level` 字段**）。
  3. 与 V1.3 隐私协议弹窗（GAP-13）协同：首次进入课程前确保已授权。
- **验收**：医疗/法律类课程显示强提示；提示不遮挡核心播放操作但不可误关。

### 4.12 FR-MC-12 频道动态增删与配置下发

- **优先级**：P0
- **描述**：延续 V1.3「频道动态增删、顺序由 `display_order` 控制」原则，确保新增课程频道时小程序无需发版。
- **处理**：所有频道驱动 UI 均基于 `GET /api/v1/channels` 实时返回（含 `channel_type`）；新类型皮肤采用「未知类型 → 回退 `news` 皮肤 + 控制台告警」的防御式兜底，避免新增类型导致崩溃。
- **验收**：后端新增一个 `course` 频道并发布章节后，小程序无需更新即可在分组中显示并可正常学习。

## 6. 数据契约与接口定义

### 6.1 `GET /api/v1/channels`（扩展字段，向后兼容）

既有响应 `list[].{id,name,description,is_subscribed,display_order}` **新增**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `channel_type` | string | `news`/`course`/`audiobook`，缺省按 `news` |
| `type_label` | string | 分组展示名，如「资讯」「课程」「有声读物」 |
| `cover_url` | string? | 频道/课程封面（课程主页头部用） |
| `disclaimer_level` | string? | `none`/`normal`/`strong`，合规提示强度（FR-MC-11，D2） |
| `selection_strategy` | string? | `heat`/`outline`/`manual`，供前端展示「更新方式」 |
| `episode_count` | int? | 该频道已发布章节/节目总数（课程主页/学习中心用，可选） |

> 未携带上述字段的存量后端：小程序 `fetchChannels` 对缺失字段给安全默认值（`channel_type='news'`、`type_label='资讯'`）。

### 6.2 课程章节获取（复用既有接口）

- 章节列表：`GET /api/v1/episodes/history?channel_id={courseId}&sort_order=asc` → 返回按 `published_at` 升序的章节数组（复用 V1.3 history 分页）。
- 章节详情/播放：`GET /api/v1/episodes/{id}` 与 `/{id}/script`（既有，复用）。
- 增强（P1，建议）：`GET /api/v1/courses/{channel_id}/progress` → `{ total, learned, percent, last_chapter_id, last_position }`，用于学习中心与课程主页（FR-MC-04/05）。

### 6.3 学习完成态约定

- 复用 `POST /api/v1/playlogs/progress`（既有）上报位置；新增语义约定：当上报 `position/duration ≥ 0.95`（或 `onEnded` 自然结束）时，前端标记该章「已学完」，并（P1）同步一个低频「完成」事件到服务端（建议 `playlogs` 增加 `completed` 标记字段，依赖项 D3）。
- 章节顺序以 `episode.published_at` 升序为准；若后续引入 `chapter_no`（T12 增强），以 `chapter_no` 优先。

### 6.4 错误码（沿用 V1.2，新增可选）

| 场景 | 处理 |
| --- | --- |
| 课程频道暂未生成章节 | 课程主页空态「课程章节尚未生成，敬请期待」（skin 映射） |
| 章节音频丢失 | 复用 V1.3 `playError` 提示机制 |
| 未知 `channel_type` | 回退 `news` 皮肤 + 控制台 warn，不崩溃 |

## 7. 验收标准与里程碑（对齐 M1/M2/M3）

| 里程碑 | 范围（本文档） | 验收标准 | 依赖 |
| --- | --- | --- | --- |
| **M1 后端全链路**（非本文档主战场） | 仅联调字段 | 后端产出 `course` 频道章节，C 端接口返回 `channel_type` | 实施计划 T1–T12 |

## 8. 风险与边界（必须如实告知）

1. **规模天花板 ≠ 功能障碍**：单机 SQLite 串行写 ~15–26 req/s、读 p50≈16ms，适合单/少租户中小规模。多租户 SaaS 化才是 MySQL/Redis 的真正理由（P2 非默认），**不在本适配阶段启动**。学习进度高频写须严格节流（NFR-MC-02）。
2. **皮肤是主要成本**：后端复用度高（约 80%），小程序 M2 工作量集中在「课程主页/章节/学习中心/皮肤通用化/订阅适配」前端，**不触碰播放内核**。
3. **合规是红线**：医疗/法律/财经类课程必须保留/强化人工审核（后端 `review` 链路）并展示 AI 生成提示（FR-MC-11），否则有平台合规风险。
4. **改造面可控**：小程序改动集中在 `services/api.js`（字段解析）、`utils/skin.js`（新增）、`pages/index`（分组+分支）、新增 `pages/course`（课程主页）、`pages/channels`/`pages/profile`/`pages/search` 适配。**不重写播放器、不另起音频引擎。**
5. **依赖后端字段**：`channel_type`（必需）、`disclaimer_level`（P0 合规）、`courses/{id}/progress`（P1）、`search?channel_type`（P1）需后端在 M2 同步落地（见《业务范围扩展实施计划》配套后端改造）。
