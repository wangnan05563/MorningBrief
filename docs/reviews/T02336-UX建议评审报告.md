**五条最重要的评审发现**

1. **R3 是唯一会不可逆毁数据的一类，且原始修法不安全**：只在前端跳过 `***` 不够；`import_rows` 的 replace 仍是 `INSERT OR REPLACE`（SQLite 整行删插），会把未提交的敏感列置空；审计又记录全量 `values`，等于把新密钥明文写入 `audit_log`。必须四件事一起改（脏字段提交 + 后端拒绝 + 导入 upsert + 审计脱敏）。
2. **R1 的「静默丢弃」是有意设计**：`message.js` 在 `document.hidden` 或 `_isRestoring` 时跳过 `ElMessage`，是为了避免后台标签页插入 DOM 唤醒最小化窗口。原始建议「直接恢复提示」会破坏该意图；正确修法是可见性感知的 FIFO 队列 + 恢复后聚合补发。
3. **R7 的应急停服牵出权限模型缺口**：现状只有 admin/operator，移动 SRS 却要求 `super_admin` + 二次验证；且维护状态检查在 DB 故障时按非维护放行，停服可能失效。`reason = value.trim()` 只是最小修复，权限口径必须由产品决策。
4. **R4 的「第 4 个审核 tab」与 SRS 冲突**：需求规格明写三栏（`docs/需求规格说明书.md:400`），后端却有 4 态（含 `replaced`）。推荐并入「已通过」并加子筛选，而不是新增第 4 个 tab。
5. **高危里也有误报与降级**：M78「工作流无重试入口」不成立（详情页有「从指定步骤重跑」，后端 `/retry` 已接通）；另有 C5、C68、J20、J32、J48、J66、J77、M33、M54 九条建议降为 M。PRD 已排除 M78，并按 M 级处理降级项。

**放行条件**

1. PRD 只收录修订后的修法（已落实到 `docs/需求规格说明书-UX优化.md`）。
2. DEC-UX-001～005 在对应 FR 实施前拍板。
3. M78 不进入实施范围；9 条降级项不单独作为 P0 依据；低危只作附录打磨清单。
4. R3、R1、R6、R7 在编码前补技术方案或实测（R6 需实测 Tailscale Funnel 对 120s+ 请求的行为）。
5. 视觉、小程序真机、暗色/375px 相关结论需按 NFR-UX-04 实测，不把源码推断当已验证事实。

### 1.2 评审问题

对每条建议回答四个问题：

1. **问题是否真实**：证据指向的代码/文案/行为现在是否仍存在（是否已被并发修复）。
2. **修法是否正确**：是否解决根因、是否引入新风险、是否过度设计。
3. **优先级是否成立**：高危是否满足「功能不可用 / 数据被误读 / 不可逆风险 / 首次用户走不通」。
4. **是否与既有规格/产品决策冲突**：SRS、详细设计、移动端消息中心、权限模型。

### 1.3 不在本次范围

- 不做视觉走查实测（配色、间距、暗色主题只能从模板与样式推断）。
- 不验证真实接口响应、微信真机渲染、公网网关超时（分别标注「需实测确认」）。
- 不修改 T02323 原文；所有修订只体现在 PRD 与本报告。

## 5. 七大根因复验

### R1 静默失败 / 错误被吞成空态或正常态

- **问题成立**：`utils/message.js:13-28` 在 `document.hidden` 或 `_isRestoring` 时跳过 `ElMessage`；`api/index.js:87-95` 的全局错误提示因此失效；多页 `catch {}` 后落空态。
- **原建议的问题**：直接取消隐藏拦截会插入 DOM，可能唤醒最小化窗口，违背既有设计意图。
- **修订后修法**：success/error/warning 入 FIFO，去重、上限 5、TTL 60s；`visibilitychange` 恢复且 `_isRestoring` 结束后聚合补发；`confirm/prompt` 保持 reject、绝不回放；loading 不入队。更稳的替代是复用移动端常驻消息中心（`mobile.py:51`、`views/mobile/Message.vue`），但需跨端接口，列为 DEC-UX-004。

### R2 配置加载失败回落默认值后保存即覆写

- **问题成立**：`CosConfig.vue:198-209` 的 catch 空处理 + `:242-245` 草稿恢复；`handleSave` 无条件提交 bucket/cdn_domain；`cos_config_service.py:139-143` 以 `bucket or ""` 覆写。Tunnel 同类（`Tunnel.vue:446-448`、`:521-534`；`tunnel_service.py:249-261`）。
- **修订后修法**：加载失败显示页内错误态 + 重试，禁用保存；草稿恢复必须标记「配置未加载，保存会覆盖」并默认不恢复。PATCH/乐观锁属契约变更，暂不做。

### R3 脱敏值回写 / 不可逆数据毁损

- **问题成立且最严重**：`db_admin_service.py:298-315` 的 `update_row` 只过滤 `valid_cols`，不识别 `"***"`；前端整行预填（`DatabaseAdmin.vue:390,496-503`）会把脱敏值当真实值提交；`import_rows:466-468` 用 `INSERT OR REPLACE`，SQLite 整行删插；`routers/admin/db_admin.py:150` 审计记录全量 `values`，含明文密钥。
- **原建议的问题**：简单「跳过 `***`」会静默掩盖意图，且对 `ai_config.config_value` 不能按列一刀切（`db_admin_service.py:113-114` 整列命中，真实脱敏按 `config_key` 动态判断 `:134-137`）；只改前端仍可被直接调接口绕过。
- **修订后修法**（四件事必须一起做）：
  1. 前端脏字段 diff，敏感列只读且不提交；
  2. 后端拒绝脱敏哨兵并返回字段级错误「敏感字段请走专用重置通道」；
  3. `import_rows` 改 `ON CONFLICT DO UPDATE` 仅更新显式列；
  4. 审计 `detail.values` 脱敏；删除/导入令牌改服务端配置校验。
- **风险**：R3 若只做前端，仍可绕过；必须先出技术方案。

### R4 枚举 / 引导 / 文档漂移

- **问题成立**：`guideConfig.js:69-71` 的 `[aria-label="立即触发一期工作流"]` 命不中，`WorkflowList.vue` 实际按钮 `aria-label="手动触发"`（`IconButton.vue:20,64`）；兜底 `.top-bar .el-button` 会命中「重置」。审核后端 4 态（`models/review.py:13-25`）对前端 3 tab（`ReviewList.vue:4-6`）；SRS 明写三栏（`docs/需求规格说明书.md:400`），详细设计却有 `replaced`（`docs/详细设计说明书.md:510`）。帮助文档多处指向不存在菜单/功能虚标。
- **修订后修法**：引导锚点最短改 `[aria-label="手动触发"]` 并删错误兜底，长期用 `data-guide`；审核状态**先定产品口径**（DEC-UX-001，推荐并入「已通过」加子筛选），不要直接加第 4 个 tab；文档以路由 `meta` 为单一事实源做构建期校验。

### R5 统计口径与单位误读

- **问题成立**：`models/play_log.py:32` 的 duration 是秒，`stats_service.py:53-56,86-87` 原样返回，`StatsOverview.vue:84` 与移动端 `Home.vue:54` 标「分钟」；`completion_rate` 卡片 ×100（`StatsOverview.vue:83,140`）、趋势按 0~1 却标「%」（`:99`）、移动端直接拼 `%`（`Home.vue:52`）。
- **原建议的问题**：改后端单位会破坏既有契约。
- **修订后修法**：前端统一格式化，两处标签都改；后端补 `unit/scale` 元数据（响应层，不改表）；三处刻度一致。违反 SRS「指标计算口径明确」（`docs/需求规格说明书.md:430`），必须修。

### R6 长任务 / 流式基本能力缺失

- **问题成立**：`KnowledgeQA.vue:498` 的 `/ai/chat` 未设超时；前端全局 15s（`api/index.js:18`）先掐断，后端 `LLM_TIMEOUT_SEC` 默认 30（`config.py:216`），UI 上限 120（`AIConfig.vue:131`）。
- **修订后修法**：前端显式 `{ timeout: 130000 }`，留响应余量，勿与后端同时到点；提供「停止生成」；公网经 Tailscale Funnel（`api/cos.js:5-6`），反代超时无法静态确认，须实测（DEC-UX-003）；若网关低于 120s，只能流式/异步。

### R7 高危动作缺确认或点了没反应

- **问题成立**：`ManageAlert.vue:50-62` 解构出 `value` 却使用未定义的 `v`，裸 `catch { return }` 吞掉 → 移动端应急停服确认无反应；`:41-44` reload 失败回落 `enabled:false`，显示「运行正常」；后端维护检查异常按非维护放行（`mobile_service.py:337-343`、`workflow_scheduler.py:614-624`），DB 故障时停服失效；`:359-377` 重复调用重复审计。
- **原建议的问题**：只修 `reason` 取值不够；权限模型缺口（SRS 要求 `super_admin` + 二次验证，`docs/运营端移动端适配-需求规格说明书.md:159,211`；现状仅 admin/operator，`models/admin_user.py:13-21`；接口只校验 reason，`routers/admin/mobile.py:129-140`）必须产品决策。
- **修订后修法**：`reason = value.trim()`；状态读取失败显示「状态未知」；停服幂等（已停服不重复写审计）；恢复入口与倒计时；权限方案列 DEC-UX-002（A 维持现状 + 二次确认 / B 引入 `super_admin` + 2FA）。
