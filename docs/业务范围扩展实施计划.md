# 20_News / MorningBrief 业务范围扩展实施计划

> 配套文档：《业务范围扩展可行性评估》（同目录 `业务范围扩展可行性评估.md`）
> 计划目标：把"专业领域资料 → 语音学习"做成**最小可行产品（MVP）**，验证后端复用率约 80% 的结论，并为后续平台化预留扩展缝。
> 计划日期：2026-08-11
> 方法：基于 `backend/app/` 代码实读，所有改造点精确到文件 / 函数 / 行。

---

## 一、总体策略

**核心判断**：本系统本质是「内容生产流水线 + 媒体播放产品」，新闻只是当前的内容配方。扩展为「资料 → 语音产品」是**配置化为主、小改造为辅、前端重皮肤为主要成本**的工程演进。

实施原则（按优先级）：
1. **复用优先**：LLM 改写、TTS 合成、音频拼接、COS、审核、播放/订阅/评论、调度引擎、限流预算全部零改动复用。
2. **最小闭环先行**：先跑通「上传文档 → 自动生成可播放语音课」后端全链路（可用 API 验证），再投入前端皮肤。
3. **改造点集中在两处**：输入适配层（文档上传 + 选题策略）+ 文案模板（课程口吻）。其余靠 Channel 配方配置化。
4. **规模边界不前置**：单机 SQLite + 单 worker + 进程内缓存的硬约束（V1.2）**不在 MVP 阶段打破**；多租户 SaaS 化（MySQL/Redis）列为独立阶段 P2，仅当真正需要平台化时启动。

## 三、MVP 任务清单（精确到文件 / 函数 / 行）

### 阶段 1 — 输入适配器（核心新增，约 3–4 人日）

**T1. 文档解析服务（新增）**
- 新增 `services/document_ingest.py`：解析 PDF / Word / Markdown / 网页 → 切分为章节段落（依赖 PyMuPDF / python-docx / markdown）。
- 输出：章节列表 `[{seq, title, content}]`，按文档大纲顺序保留。
- 文件落盘：上传原文件存 COS（`cos_storage_service.upload`，已有）或本地临时目录；仅存文本进库，避免大对象入库。

**T2. 素材去重键改造（关键耦合点）**
- 现状：`Material.url` 是 `unique=True`（`models/material.py:45`）；`create_material` 用 `url` 查重（`routers/admin/materials.py:156-158`）。专业资料无 URL，直接冲突。
- 方案（推荐，兼容存量）：
  - 保留 `url` 字段，**对 `source_type="list"` 用合成 URL**（如 `list://{channel_id}/{content_hash[:16]}`），不复用新闻 URL 语义。
  - 新增 `dedup_key` 字段（`source_type` + `content_hash`；rss 用 url，list 用 hash）。`simhash` 字段已存在（`models/material.py:52`）可作标题指纹，正文去重用新增 `content_hash`（SHA256 前 16 位）。
  - `create_material` 查重逻辑改为按 `(source_type, dedup_key)` 判重，而非仅 `url`。
  - 同步：`workflow_scheduler` 中 `CrawlerDedup` 逻辑对 list 类型跳过（文档不走爬虫去重）。
- 备选（更干净但改动大）：去掉 `url` 唯一约束，唯一约束移到 `(channel_id, dedup_key)`。

**T3. 文档上传 API（新增）**
- `routers/admin/materials.py` 新增 `POST /admin/api/v1/materials/upload`（multipart：file + channel_id + 可选 category）。
- 流程：调 `document_ingest` 解析 → 逐章节 `create_material`（source_type="list", channel_id=课程频道, dedup_key=hash）→ 返回素材 ID 列表。
- 鉴权：复用 `require_admin`。

**T4. 选题策略插件（关键耦合点）**
- 现状：`_select_top_materials` 按 `heat_score` 降序（`rewriter.py:948,1499`），是新闻语义；学习场景应是大纲顺序。
- 改造：`_select_top_materials(materials, top_n, strategy)` 抽象为策略分支：
  - `heat`（默认，存量兼容）：保持现状。
  - `outline`：按 `Material.seq` / 插入顺序 / `category` 顺序选题（文档章节顺序）。
  - `manual`：按运营在后台指定的素材 ID 列表选题。
- 策略来源：`Channel` 新增可选字段 `selection_strategy`（默认 `heat`），`rewrite()` 读取 `channel_prompts` 后传入。

**T5. 新增 Channel 字段**
- `models/channel.py` 增加 `selection_strategy: Mapped[Optional[str]]`（枚举 heat/outline/manual，默认 None→heat）。
- 迁移：存量频道回填 NULL，行为不变。

### 阶段 2 — 频道配方与文案（配置化，约 1 人日，几乎零代码）

**T6. 课程重写模板（新增文件）**
- 新增 `workflow/llm/prompts/rewrite_course.txt`：通用知识讲解口吻（保留 JSON 输出格式要求 + 字数 ±10% 约束，因 `rewriter._build_prompt` 依赖 `{words_per_segment}` 等占位符）。
- 频道配置 `rewrite_template` 指向此文件即可，无需改 `rewriter.py`。

**T7. 课程开场白/结尾文案（配置）**
- 新增课程默认 intro/outro 文案（放 `prompts/` 或 Channel 模板库）。
- 通过频道 `intro_prompt` / `outro_prompt` 覆盖（已支持，`rewriter.py:1051-1052` 频道级优先于写死的 `INTRO_TEXT/OUTRO_TEXT`）。
- 关闭"结尾思考问题"：`Channel.enable_thinking_question=0`（学习场景可保留为"课后思考题"，按需）。

**T8. 关闭广告（零成本）**
- 广告在 `concat.py:296-297` 由 `AdService.get_active_placements(episode_date)` 控制：**不投放广告位即不插入**。课程频道不配置广告位即可。
- 可选增强：新增 `Channel.enable_ad`（默认 1 兼容，课程频道设 0），在 `concat.py` 跳过 `AdService` 调用，避免误投放。

### 阶段 3 — 编排打通（复用 + 微小改造，约 1–2 人日）

**T9. 手动触发入口（复用 + 小封装）**
- 复用 `workflow_scheduler` 手动触发能力（`trigger_lock` 已防 cron/手动竞态）。
- 新增 `POST /admin/api/v1/workflows/trigger`（`channel_id`, `source="upload"`），或复用现有手动触发接口，声明 `episode_date` + `channel_id` 入队执行 `crawl(跳过)→rewrite→tts→stitch→review→publish`。
- 文档上传场景：`crawl` 步骤跳过（素材已在 T3 入库），从 `rewrite` 开始。

**T10. outline 选题时的关联微调**
- `rewrite()` 走 `selection_strategy="outline"` 时：按 `Material.seq` 排序选题（T4）；跳过 `_filter_materials_by_relevance`（相关性筛选是新闻语义，按大纲顺序无需，`rewriter.py:1505` 加 `strategy != "outline"` 守卫）。
- `_fetch_materials` 当前按 `crawled_at` 当日筛选（`rewriter.py:1128`）：文档上传需放宽——按 `channel_id` + `status=pending` 取全部（或最近 N 天），不强制当日。用 `Channel.material_lookback_days` 或新增 `source_type="list"` 跳过当日约束。

**T11. 复用 TTS / stitch / COS / 审核 / 发布**
- `tts_factory.get_tts_provider()` 自动按配置选引擎（课程用童声/长辈缓速=换 Provider 或 voice 参数）。
- `stitch.concat` 拼接（T8 已关广告）。
- `ContentService.publish_episode` 发布（`internal/workflow.py:90`）。专业/医疗/法律内容**保留人工审核**（走 `review` 链路，是合规加分项）。

**T12. episode_date 语义化（MVP 简化）**
- 最小闭环：直接复用 `episode_date` 作为"课程发布日"，每门课程=一个 Channel，每章=一次 workflow。
- 增强（可选，非 MVP）：Workflow/Episode 新增 `chapter_no` / `course_id` 字段，把"按日节目"语义化为"按章节课程"。

### 阶段 4 — 前端最小展示（主要工作量，约 1–2 周）

**T13. admin-web「资料库/课程」**
- 新增页面：文档上传、素材列表（复用 materials 组件）、手动触发生成、语音课列表（复用 episodes/workflow 组件）。
- 频道管理新增 `selection_strategy` / `enable_ad` 表单字段。
- 复用现有 `api/cos.js`、`api/materials.js`、`routers/index.js` 注册。

**T14. 小程序「课程」tab**
- 复用 `episodes` / `play` 组件，文案从"今日新闻"改为"课程/章节"。
- 复用 `display_order`（`channel.py:61`）控制 tab 顺序，无需改小程序排序逻辑。

## 四、验证方案（MVP 验收）

1. **端到端跑通**：上传一份 PDF → T3 入库章节素材 → T9 手动触发 → `rewrite`（课程模板）→ `tts`（朗读音色）→ `stitch`（无广告）→ `publish` → 小程序/API 可播放。
2. **去重验证**：重复上传同一文档，T2 判定 `dedup_key` 重复，仅入库一次。
3. **选题验证**：`selection_strategy="outline"` 时按文档章节顺序生成，非热度。
4. **回归压测**：`scripts/jmeter_test/loadtest_async.py` 跑异步回归，确认进程内约束下读 p50≈16ms、写 ~15–26 req/s 无劣化（`scripts/jmeter_test/cleanup_seed.py` 回滚种子数据）。
5. **合规验证**：医疗/法律内容走人工审核（review 链路），替换敏感词策略（专业域词库）。

## 六、风险与边界（必须如实告知）

1. **规模天花板 ≠ 功能障碍**：单机 SQLite 串行写 ~15–26 req/s、读 p50≈16ms，适合单/少租户中小规模。多租户 SaaS 化才是 MySQL/Redis 的真正理由（P2 非默认），**不在 MVP 阶段启动**。
2. **前端皮肤是主要成本**：admin-web（8000+ 文件）+ 小程序是新闻专属皮肤，M2 工作量主要来自前端；后端复用度高。
3. **合规**：专业/医疗/法律领域内容有合规风险，必须保留/强化人工审核（本系统已有 review 链路，是加分项），并替换敏感词策略。
4. **改造面可控**：所有代码改动集中在 `services/document_ingest.py`（新增）、`models/material.py`（去重键）、`models/channel.py`（2 字段）、`routers/admin/materials.py`（上传+查重）、`workflow/llm/rewriter.py`（选题策略分支）、`workflow/stitch/concat.py`（可选关广告）。**不触碰 TTS / LLM / COS / 调度核心**。

## 七、其他同构场景（复用同一 MVP 基座）

| 场景 | 复用点 | 差异点 |
|---|---|---|
| 企业内训/制度宣贯语音化 | 文档适配器 T1–T3 | 仅换 Channel 配方 + 音色 |
| 儿童/老人有声读物 | TTS 音色（童声/长辈缓速）+ intro/outro | 纯配置 |
| 法律法规/政策速读 | LLM 换强推理模型 + 收紧敏感词 | 配置 + 审核策略 |
| 多语种资料朗读 | Edge/Kokoro 多语种 | TTS 层天然支持 |
| 播客/自媒体成片 | 复用拼接+BGM，保留广告位 | 甚至可保留变现 |

**非同构、不建议复用**：强交互对话式 AI 助教、实时音视频通话、复杂关系检索 RAG 问答库——超出"生产流水线"范畴，本系统对话/检索能力为空白。
