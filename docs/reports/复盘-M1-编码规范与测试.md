# M1 业务范围扩展 会话复盘：编码规范与测试方法论

> 来源：2026-08-11 前后「专业资料 → 语音课」业务范围扩展 M1 实施过程中真实解决的若干问题。
> 目的：按用户要求的**四维复盘**（成功步骤 / 不确定性与失败点 / 可抽象固定流程与判断逻辑 / 适用与不适用场景），
> 将 M1 经验提炼为可复用的编码规范与测试方法论，并系统性沉淀进四个项目技能：
> `news-code-dev`（编码标准）、`news-backend-code-review`（后端审查）、`news-frontend-code-review`（前端审查）、`news-auto-testing`（自动化测试）。
> 全部规则参数化进 `config.yaml` / `project-config.json`，技能本身**零硬编码业务值**，并遵循"通用泛化、适配不同业务场景"原则。

## 二、开发维度四维复盘（→ news-code-dev / 后端审查 / 前端审查）

### 维度 1：成功执行开发任务的完整步骤

1. **先定全链清单**：新增任何"运营可调 / 前端可见 / 影响处理"的模型字段，先列全链 6 层（model 列 → 幂等迁移 → service create/update → router schema+validator → 序列化 → 前端控件），逐层打勾。
2. **update 用 `_UNSET` 哨兵**：含语义化清空值（如 `None`=继承动态）的 update 字段，默认参数用 `_UNSET = object()`，仅 `is not _UNSET` 时写入，杜绝"未传=清空"语义丢失（R227）。
3. **内部导入走定义子模块**：`flag_modified` 等从 `sqlalchemy.orm.attributes` 导入，不依赖包根 re-export（R228）。
4. **配置优先于动态默认**：选址/默认值选择中，显式/持久化值（DB 字段 / Settings 单例）必须赢过动态默认（R229）。
5. **loguru 用 `{}`**：所有日志占位用 `{}` 而非 `%d/%r/%s`（R232）。
6. **去重口径先定后写**："与频道无关 / 与频道相关"是设计决策，先固定再实现（R233）。
7. **对称函数成对实现**：create/persist、upload/download、get/set 成对补齐（R237）。

### 维度 2：开发执行中的不确定性与失败点

- **分层字段静默失效**：只加 model 字段、漏 router 透传 → 字段"存不进 / 用不了"，无报错，最难排查（M1 #1/#2）。
- **loguru `%` 误用**：printf 风格在 loguru 下既不报错也可能输出错乱，仅在运行时触发异常（M1 #3）。
- **去重口径歧义**：list 全局去重 vs 频道级去重未固化 → 同文档跨频道 409 引发"是否 bug"争论（M1 #8）。
- **对称函数只实现一半**：成对 API 只做一侧 → 功能残缺（M1 #9）。
- **配置开关硬编码**：新功能仅靠 `if DEBUG:` / 环境变量分支 → 无法灰度/回退（R230）。

### 维度 3：可抽象的固定流程与判断逻辑

- **分层字段全链校验（R231）**：grep 新字段名，确认它在 model / 迁移 / service / router schema / 序列化 / 前端控件 6 层都存在；缺一层即缺陷。
- **loguru 占位符扫描（R232）**：grep `logger\.(debug|info|warning|error|exception)\(` 的格式化串，发现 `%` 或 `{}` 计数≠参数数即告警。
- **去重口径断言（R233）**：查重条件（`dedup_key` / `content_hash` / `url`）须与既定口径文档一致。
- **函数对称性扫描（R237）**：grep 新增对称函数名，确认对侧实现存在、签名对称、错误处理对称。
- **配置优先纪律（R229）**：任何"显式 vs 默认"选择，断言显式值优先。

### 维度 4：适用与不适用场景

| 标准 | 适用 | 不适用 |
|------|------|--------|
| R231 分层字段全链 | 新增运营可调/前端可见/影响处理的模型字段 | 纯计算派生字段、纯日志字段 |
| R232 loguru 占位符 | 所有 loguru 调用 | 标准库 logging（`%`）、已 f-string 插值 |
| R233 去重口径 | 任何"已存在则跳过/409"查重逻辑 | 允许重复的业务场景 |
| R234 测试 DB 隔离 | 任何 TestClient 集成测试 | 纯函数单测（无 app/DB 导入） |
| R235 序列化键对齐 | 任何响应序列化 + 消费者 | 内部临时 dict |
| R236 e2e 一键脚本 | 将手动 e2e 步骤脚本化 | 一次性临时探针 |
| R237 函数对称性 | 任何成对 API/工具函数 | 单方向函数 |

## 三、测试维度四维复盘（→ news-auto-testing）

### 维度 1：成功执行测试任务的完整步骤

1. **判定改动轨（双轨）**：`backend/**/*.py` → pytest（阶段 99）；`admin-web/src/**` / `miniprogram/**` → 编译/Playwright；两者皆有 → 全量。
2. **隔离环境**：pytest 前 `unset` safe-delete 守卫变量 或 设独立 `TEMP`（如 `backend/.pytest_tmp`）避开 FAIL CLOSED 守卫。
3. **TestClient 进程内零污染（M1 #5/#6）**：在 `import app` **之前** monkeypatch `app.paths.resolve_db_path` 指向临时 DB 副本；`dependency_overrides` 同时注册 `require_admin` + `get_current_admin`。
4. **定向 → 相关 → 全量**：先跑新增/改动用例，再相关子集，最后全量收敛。
5. **失败判别**：单跑失败用例——通过=flake（修根因）/失败=真缺陷（定位修复）；分类 `真缺陷/flake/环境制品`。
6. **序列化键对齐断言（M1 #7）**：断言读取的键名须与序列化键一致（`name` 非 `step_name`）。
7. **新字段全链 pytest（M1 #1/#2）**：为新可控字段写 `tests/test_*_field.py`，逐级断言 model→迁移→service→router→序列化；配合 `scripts/e2e_course_channel.sh` 做真 HTTP 闭环。
8. **闭环**：修复后三级复跑至全绿，flake 必须修根因复跑确认稳定。

### 维度 2：测试执行中的不确定性与失败点

- **TestClient 污染真实库**：import 后才 mock `resolve_db_path` → 异步引擎已连真实 `news.db`，用例写操作污染生产数据（M1 #5）。
- **401 误报**：只覆盖 `require_admin`，列表/详情路由用 `get_current_admin` 直接 `Depends` → 全部 401（M1 #6）。
- **断言键名错配**：序列化键为 `name`，测试读 `step_name` → 断言失败但字段其实正常（M1 #7）。
- **分层字段"看似有测实无覆盖"**：只测 service 层，未测 router 透传 → model 有字段但接口不返回（M1 #1/#2）。
- **loguru `%` 运行期异常**：静态 py_compile 通过，`pytest` 运行到日志行才抛 `not all arguments converted`（M1 #3）。
- **e2e 不可复跑**：散落 curl 步骤漏执行 → 回归靠人记（M1 #4）。

### 维度 3：可抽象的固定流程与判断逻辑

- **TestClient 隔离固定式（T29 / R234）**：import 前 monkeypatch `resolve_db_path` + 临时副本 + 双 auth override；任缺一项判为隔离缺陷。
- **序列化键断言对齐（T30 / R235）**：断言键名须与序列化 schema 字段名一致；grep 测试断言键 vs schema 输出键。
- **分层字段全链 pytest（T31 / R231）**：新字段测试须覆盖 6 层；任一层缺失的字段须在测试中暴露。
- **loguru 占位符测试（T32 / R232）**：grep 测试代码 + 业务代码中 `logger.*(` 的 `%` 误用。
- **e2e 一键脚本合规（T33 / R236）**：`bash -n` 通过 + 业务参数参数化 + 零污染（先备份再回滚种子）。

### 维度 4：适用与不适用场景

| 流程 | 适用 | 不适用 |
|------|------|--------|
| T29 TestClient 隔离 | 任何 TestClient 集成测试 | 纯函数单测（无 app/DB 导入） |
| T30 序列化键断言 | 响应序列化 + 测试/前端消费者 | 内部临时 dict |
| T31 分层字段全链 pytest | 新增可控/可见模型字段 | 纯计算派生字段 |
| T32 loguru 占位符 | 所有 loguru 调用测试/扫描 | 标准库 logging |
| T33 e2e 一键脚本 | 将手动 e2e 脚本化 | 一次性临时探针 |

## 五、通用性与泛化说明

- 全部新增规则**不绑定 M1 具体业务**：字段名、`%` 误用、key 名、脚本路径、DB 路径均通过 `config.yaml` / `project-config.json` 的 `scan_dirs` / `scan_files` / 正则 / 参数列表管理，迁移到任意 FastAPI + SQLAlchemy + Vue 项目只需改配置。
- **分层字段全链**范式适用于任何"新增模型字段需端到端生效"的后端；**TestClient 隔离**范式适用于任何"测试不能污染真实库"的 FastAPI 项目；**e2e 一键脚本**范式适用于任何需可复跑回归的手工验证。
- 所有新增审查维度在对应 `config.yaml` 均有节点（无硬编码新增），报告违规标注 `[V3.6 新增]`，修复建议优先指向 news-code-dev 的 R 编号，保持与整体工作流一致。
