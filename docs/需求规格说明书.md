## 1. 引言

### 1.1 编写目的

本说明书旨在为「20_News 语音新闻播报微信小程序」MVP 版本的开发、测试与验收提供明确、可验证的依据。文档面向开发团队，明确：

- 产品要做什么、不做什么（MVP 边界）；
- AI 内容生产工作流的技术规格与接口契约；
- 微信小程序端的功能与交互要求；
- 非功能性约束（性能、可用性、合规性等）；
- 验收标准。

读者读完后应能够：独立完成所负责模块的设计、开发、联调与自测，并对照本文档完成验收。

### 1.2 项目背景

资讯消费场景正在从「看」向「听」迁移。通勤、驾车、家务、运动等碎片化场景下，用户无法持续盯着屏幕，但仍希望高效获取当日资讯。当前市场存在以下矛盾：

1. **传统新闻 App 的「听新闻」入口深、体验割裂**：多为单篇 TTS 朗读，缺乏完整节目化编排；
2. **播客内容优质但更新慢、门槛高**：每日人工录制成本高，难以做到日更且覆盖多品类；
3. **AI 工作流技术已成熟**：爬虫、LLM、TTS 的端到端自动化已具备生产级可行性，可显著降低日更成本。

本项目旨在通过一套**全自动 AI 内容生产工作流**，每日定时生产 10 分钟高质量语音新闻节目，发布到微信小程序，让用户「打开即听、听完即走」。

## 2. 项目概述

### 2.1 产品定位

**一句话定位**：每天 10 分钟，AI 生产的语音新闻早报，打开微信小程序即听。

**产品形态**：微信小程序 + 后端 AI 内容生产服务 + 运营后台。

**差异化**：
- 节目化编排（非单篇朗读），10 分钟完整体验；
- 全自动 AI 生产，零人工录制，可日更；
- 微信小程序原生入口，免下载、即开即用。

### 2.2 目标用户

| 用户群 | 占比预估 | 核心诉求 | 使用场景 |
| --- | --- | --- | --- |
| 通勤白领 | 50% | 高效获取当日要闻 | 地铁/公交上，碎片化时间 |
| 驾驶人群 | 20% | 安全听新闻，不分散注意力 | 开车通勤、长途驾驶 |
| 中老年用户 | 20% | 视力弱，偏好听 | 居家、晨练 |
| 内容消费者 | 10% | 节目化体验，类似播客 | 做家务、运动、睡前 |

### 2.3 核心价值主张

1. **省时**：10 分钟覆盖当日全部要闻，比刷信息流节省 80% 时间；
2. **省力**：打开即播，无需选择、无需操作；
3. **高质量**：AI 改写稿 + 真人音色克隆，听感接近专业电台；
4. **免费**：用户免费收听，商业化通过广告实现。

### 2.4 业务范围（MVP 边界）

#### 2.4.1 包含（In Scope）

- 每日 1 条 10 分钟综合播报音频，所有用户听相同内容；
- 全自动 AI 工作流：爬取 → 改写 → TTS 合成 → 广告植入 → 发布；
- 微信小程序端：播放、历史回听、基础个人中心；
- 后台管理：内容审核、广告管理、基础数据统计；
- 商业化：开头 5s + 中间 30s + 结尾 10s 三段式广告植入；
- **V1.1 新增部署形态**：单机 exe（PyInstaller + Inno Setup 安装包），用户双击安装即可使用，无需 Docker/MySQL/Redis/Nginx 等环境依赖；
- **V1.1 新增混合架构**：单机 exe 负责 AI 内容生产 + 运营后台；云函数 + COS 负责 C 端小程序接口，解决微信小程序合法域名需公网 HTTPS 的合规要求。

#### 2.4.2 不包含（Out of Scope，留待后续版本）

- 品类订阅、个性化推荐；
- 多档分时发布（早/午/晚）；
- 用户注册登录体系（MVP 用微信授权即可）；
- 评论、点赞、社区 UGC；
- 数字人视频版播报；
- iOS/Android 原生 App；
- 付费会员、知识付费内容；
- **V1.1 明确排除**：Linux 服务器部署、Docker 容器化部署、多用户多机协作（MVP 仅支持单机单用户使用）。

### 2.5 竞品分析摘要

| 竞品 | 形态 | 核心优势 | 可吸收的优秀功能 | 我们的差异 |
| --- | --- | --- | --- | --- |
| 今日头条「听新闻」 | App + 小程序 | 内容池大、入口多（首页左滑、耳机图标、独立频道） | 多入口触达、老年版大字简化交互 | 头条是单篇朗读，我们是节目化编排 |
| 腾讯新闻小程序 | 小程序 | 实时更新、品牌信任 | 实时播报、小程序原生体验 | 我们聚焦 10 分钟节目，非实时滚动 |
| 小宇宙 App | 播客客户端 | UGC 社区、内容深度 | 节目订阅、播放进度记忆、倍速播放 | 我们是 AI 自动生成，非 UGC |
| 喜马拉雅新闻频道 | 音频平台 | 主播资源、内容丰富 | 主播 IP 化、广告自然植入 | 我们零人工录制，可日更 |
| 书尖 AI 等通勤听书小程序 | 小程序 | 通勤场景聚焦 | 锁屏继续播放、后台播报 | 我们是新闻资讯，非听书 |

**竞品功能取舍**：

| 功能 | 是否采纳 | 理由 |
| --- | --- | --- |
| 多入口触达（首页+搜索+分享卡片） | ✅ 采纳 | 提升触达效率，符合小程序生态 |
| 锁屏继续播放 / 后台播报 | ✅ 采纳 | 通勤核心场景刚需 |
| 播放进度记忆 | ✅ 采纳 | 10 分钟内容易被打断，需断点续播 |
| 倍速播放（1.0/1.25/1.5/2.0） | ✅ 采纳 | 满足不同用户效率需求 |
| 历史回听 | ✅ 采纳 | 内容资产复用 |
| 老年版大字模式 | ❌ 暂不采纳 | MVP 聚焦核心闭环，留待 V2.0 |
| 个性化推荐 | ❌ 暂不采纳 | 需用户画像积累，MVP 用统一播报 |
| 评论社区 | ❌ 暂不采纳 | 社区运营成本高，MVP 不做 |
| 数字人视频 | ❌ 暂不采纳 | 视频生产链路复杂，留待 V2.0 |

## 3. 用户角色与场景

### 3.1 用户角色定义

| 角色 | 描述 | 权限 |
| --- | --- | --- |
| 普通用户（C 端） | 通过微信小程序收听播报的用户 | 播放、暂停、回听历史、个人中心 |
| 运营人员（B 端） | 通过 Web 后台管理内容与广告的运营 | 内容审核、广告管理、数据查看 |
| 系统调度（自动） | 定时触发 AI 工作流的自动化角色 | 触发爬取、生成、发布 |

### 3.2 典型使用场景

**场景 1：通勤早间收听**
> 用户早 7:30 出门坐地铁，打开微信小程序，首页即展示今日播报卡片，点击播放按钮，10 分钟节目开始播放。中途到站换乘，锁屏后音频继续播放。到公司时刚好听完。

**场景 2：驾驶途中收听**
> 用户开车上班，上车前在小程序点击播放，连接车载蓝牙后听播报。中途接电话暂停，挂断后自动续播。

**场景 3：错过当日补听**
> 用户白天忙碌未听，晚上做家务时打开小程序，从「历史」中找到今日播报，边做家务边听。

**场景 4：运营审核异常内容**
> 早 6:00 AI 工作流生成今日播报，运营人员收到审核通知，登录后台试听音频、查看改写稿，发现某条新闻敏感，标记替换，重新触发合成。

**场景 5：广告主投放**
> 运营人员在后台为某品牌创建 30s 语音广告素材，设置投放周期与投放位置（开头/中间/结尾），系统自动在次日播报中植入。

## 4. 功能需求

### 4.1 功能架构

V1.1 采用混合架构：单机 exe 负责生产端 + 运营后台；云函数 + COS 负责消费端。

```
┌──────────────────────────────────────────────────────────────┐
│  消费端：微信小程序（C 端，公网访问）                          │
│  播放页 │ 历史回听 │ 个人中心 │ 微信授权登录                  │
└──────────────────────────────────────────────────────────────┘
                          ▲
                          │ HTTPS（微信合法域名要求）
                          ▼
┌──────────────────────────────────────────────────────────────┐
│  云端：腾讯云                                                  │
│  ┌────────────────┐    ┌────────────────────────────────┐    │
│  │ 云函数 SCF     │    │ COS + CDN                      │    │
│  │ /episodes/today│───▶│ 音频文件                       │    │
│  │ /episodes/list │    │ 节目元数据 JSON                │    │
│  │ /playlogs      │    │ 封面图                         │    │
│  │ /feedbacks     │    │ playlogs / feedbacks JSON      │    │
│  └────────────────┘    └────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────┘
                          ▲
                          │ HTTPS（发布时上传音频+元数据）
                          │
┌──────────────────────────────────────────────────────────────┐
│  生产端：单机 exe（用户本机，PyInstaller 打包）               │
│  ┌──────────────────────────────────────────────────────┐    │
│  │ FastAPI 单体应用 + APScheduler                       │    │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐             │    │
│  │  │ AI 工作流│ │ 运营后台 │ │ 发布服务 │             │    │
│  │  │ 爬虫/LLM/│ │ Vue3 SPA │ │ 同步至   │             │    │
│  │  │ TTS/拼接 │ │ (内嵌)   │ │ COS      │             │    │
│  │  └──────────┘ └──────────┘ └──────────┘             │    │
│  └──────────────────────────────────────────────────────┘    │
│  ┌────────────────┐    ┌────────────────────────────────┐    │
│  │ SQLite         │    │ 内存缓存                       │    │
│  │ 11 张业务表    │    │ (cachetools.TTLCache)          │    │
│  └────────────────┘    └────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────┘
                          │ HTTPS
                          ▼
┌──────────────────────────────────────────────────────────────┐
│  外部云服务                                                    │
│  通义千问 API (LLM) │ 阿里云 TTS API │ 腾讯云 COS+CDN        │
└──────────────────────────────────────────────────────────────┘
```

**架构说明**：
1. **生产端（单机 exe）**：AI 工作流、运营后台、SQLite 全部内嵌于 exe 中，用户双击安装即用，零环境依赖；
2. **消费端（云函数 + COS）**：C 端小程序只与云端通信，满足微信合法域名要求；单机 exe 在发布时将音频与节目元数据 JSON 上传到 COS；
3. **数据同步**：审核通过后由单机 exe 主动推送至 COS，C 端无实时回写需求（播放进度、反馈由云函数写入 COS 对象）。

### 4.2 AI 内容生产工作流

#### FR-WORKFLOW-01：定时调度触发

| 项 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 每日固定时间自动触发内容生产工作流 |
| 触发时间 | 每日 05:00（北京时间），预留 1 小时用于生成+审核+发布，07:00 前完成发布 |
| 触发方式 | Cron 定时任务，支持手动重跑 |
| 失败重试 | 单步骤失败重试 3 次，间隔 5 分钟；全流程失败需告警通知运营 |
| 验收标准 | 连续 7 天准时触发，无遗漏 |

#### FR-WORKFLOW-02：新闻素材爬取

| 项 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 爬取前一日全网上架的资讯内容，作为改写素材 |
| 数据源 | RSS 源（不少于 20 个，覆盖时政/科技/财经/社会/国际等品类）；公开新闻列表页（如新浪、网易、澎湃、36氪等公开列表）；不爬取付费墙内容 |
| 爬取范围 | 前一日 00:00 - 24:00 发布的文章 |
| 单次爬取量 | 100 - 200 篇原始素材 |
| 去重 | 基于标题相似度 + URL 去重，保留每主题 1-3 篇代表 |
| 合规处理 | 遵守 robots.txt；不爬取明确禁止转载的源；保留原始 URL 用于溯源 |
| 存储字段 | 素材 ID、源、标题、正文、发布时间、原始 URL、爬取时间、品类标签 |
| 验收标准 | 单次爬取成功率 ≥ 95%；素材去重后保留 50-100 篇 |

#### FR-WORKFLOW-03：AI 改写生成播报稿

| 项 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 基于爬取素材，由 LLM 改写生成 10 分钟可播报稿 |
| 改写策略 | 事实摘要 + 背景补充 + 简短评论；不允许编造未在素材中出现的事实 |
| 稿件结构 | 开场白（30s）+ 5-6 条新闻（每条约 90s）+ 结尾（30s），总字数约 2000-2200 字（按 200-220 字/分钟语速估算） |
| 品类覆盖 | 每期覆盖 4-6 个品类，每品类 1-2 条，按当日热度排序 |
| 风格要求 | 口语化、适合播报、避免书面化长句；中性客观，不含主观立场 |
| 敏感词过滤 | 输出前过敏感词词表，命中则替换或剔除该条 |
| 溯源 | 每条新闻保留对应原始素材 URL，便于审核溯源 |
| 输出字段 | 稿件 ID、生成时间、全文、分段结构（含每段时长估算）、引用素材列表、品类标签 |
| 验收标准 | 人工抽检可读性评分 ≥ 4/5；无事实编造；字数控制在 2000-2200 字 |

#### FR-WORKFLOW-04：语音合成（TTS）

| 项 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 将改写稿合成为 10 分钟语音 |
| 音色方案 | 使用阿里云内置优质神经语音（推荐小芸女声），带情感语调；不做本地音色克隆 |
| 音色样本 | MVP 不需要样本；如需定制音色，阿里云支持上传样本训练（按次付费，二期评估） |
| 技术选型 | 阿里云语音合成 API（长文本 API，支持 SSML），详见 HLD 3.4 |
| 输出格式 | MP3，码率 128kbps，采样率 44.1kHz，单声道 |
| 时长要求 | 9分30秒 - 10分30秒（含广告位预留） |
| 质量要求 | 无明显机械音、断句自然、数字与英文读法正确、无爆音 |
| 合成耗时 | 单次 ≤ 2 分钟（云端 API 并发合成 5-6 段） |
| 验收标准 | MOS 评分 ≥ 4.0/5.0；时长偏差 ±30s 内 |

#### FR-WORKFLOW-05：广告植入

| 项 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 描述 | 在音频中植入三段式广告 |
| 广告位 | 开头：5-10s 品牌口播；中间：5分钟处 30s 主广告；结尾：10s 尾版+下期预告 |
| 广告素材 | 由运营后台上传的 MP3 音频，统一格式（码率/采样率与主音频一致） |

### 6.2 数据存储

V1.1 数据存储分为生产端（单机 exe）与消费端（云端）两层：

**生产端数据存储（单机 exe 内）**：

| 数据类型 | 存储方案 | 说明 |
| --- | --- | --- |
| 结构化业务数据 | SQLite | 11 张表（user/admin_user/episode/script/material/ad_material/ad_placement/play_log/workflow/workflow_step/review），替代 V1.0 的 MySQL |
| 缓存 | Python 内存缓存（cachetools.TTLCache） | 节目列表、广告投放、限流计数等，替代 V1.0 的 Redis |

| 后台操作审计 | SQLite `audit_log` 表（二期） | 替代 Elasticsearch |
| 音频文件 | 腾讯云 COS + CDN | 单机 exe 上传到 COS |
| 封面图 | 腾讯云 COS | 每日自动生成或模板生成 |
| 爬取素材原文 | SQLite `material` 表（content TEXT） | 替代 MongoDB，素材结构固定 |

**消费端数据存储（云端）**：

| 数据类型 | 存储方案 | 说明 |
| --- | --- | --- |
| C 端节目元数据 | COS 对象 `episodes/meta/{date}.json` | 云函数直接读取 |
| C 端历史列表索引 | COS 对象 `episodes/index.json` | 云函数直接读取，每次发布时单机 exe 更新 |
| C 端播放进度回写 | COS 对象 `playlogs/{user_id}/{episode_id}.json` | 云函数写入，单机 exe 不消费（C 端用户进度不影响生产端） |
| C 端用户反馈 | COS 对象 `feedbacks/{ticket_id}.json` | 云函数写入，定期同步至单机 SQLite（手动或定时拉取） |
| C 端 JWT 黑名单 | COS 对象 `jwt_blacklist/{jti}.json` | 单机 exe 与云函数各自独立鉴权，黑名单不共享 |

**V1.0 → V1.1 存储变更对照**：

| 数据类型 | V1.0 方案 | V1.1 方案 | 变更原因 |
| --- | --- | --- | --- |

| 爬取素材 | MongoDB | SQLite material 表 | 素材结构固定，无复杂检索需求 |
| 审计日志 | Elasticsearch | SQLite audit_log（二期） | 单机场景无需全文检索，SQL 查询足够 |
| C 端数据 | 单机后端直接提供 | 云函数 + COS | 微信合法域名需公网 HTTPS，单机无法满足 |

## 7. 技术架构（概要）

### 7.1 系统架构

V1.1 采用混合架构，生产端与消费端分离：

```
┌──────────────────────────────────────────────────────────────┐
│  消费端：微信小程序（C 端，公网 HTTPS）                       │
│  播放页 │ 历史回听 │ 个人中心 │ 微信授权登录                  │
└──────────────────────────────────────────────────────────────┘
                          ▲
                          │ HTTPS（必须公网，微信合法域名要求）
                          ▼
┌──────────────────────────────────────────────────────────────┐
│  云端：腾讯云                                                  │
│  ┌──────────────────────┐  ┌──────────────────────────────┐  │
│  │ 云函数 SCF           │  │ COS + CDN                    │  │
│  │ /episodes/today      │  │ 音频文件                     │  │
│  │ /episodes/history    │  │ 节目元数据 JSON              │  │
│  │ /episodes/{id}       │  │ 封面图                       │  │
│  │ /playlogs/progress   │  │ playlogs / feedbacks JSON    │  │
│  │ /feedbacks           │  │                              │  │
│  └──────────────────────┘  └──────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
                          ▲
                          │ HTTPS（发布时单机 exe 主动上传）
                          │
┌──────────────────────────────────────────────────────────────┐
│  生产端：单机 exe（用户本机，Windows 10）                     │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  FastAPI 单体应用 + APScheduler                        │  │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐               │  │
│  │  │ AI 工作流│ │ 运营后台 │ │ 发布服务 │               │  │
│  │  │ 爬虫/LLM/│ │ Vue3 SPA │ │ 同步至   │               │  │
│  │  │ TTS/拼接 │ │ (内嵌)   │ │ COS      │               │  │
│  │  └──────────┘ └──────────┘ └──────────┘               │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌──────────────────┐    ┌────────────────────────────────┐  │
│  │ SQLite           │    │ 内存缓存                       │  │
│  │ 11 张业务表      │    │ (cachetools.TTLCache)          │  │
│  └──────────────────┘    └────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
                          │ HTTPS
                          ▼
┌──────────────────────────────────────────────────────────────┐
│  外部云服务                                                    │
│  通义千问 API (LLM) │ 阿里云 TTS API │ 腾讯云 COS+CDN        │
└──────────────────────────────────────────────────────────────┘
```

**架构关键点**：
1. **消费端与生产端解耦**：C 端小程序只与云函数通信，不依赖单机 exe 在线；
2. **单机 exe 离线可用**：除上传 COS / 调用 LLM/TTS API 外，全部在本机完成；
3. **零中间件依赖**：无 MySQL/Redis/Nginx/MongoDB/Elasticsearch，全部用 SQLite + 内存缓存替代。

### 7.2 技术选型

#### 7.2.1 推荐方案（V1.1）

| 层级 | 选型 | 理由 |
| --- | --- | --- |
| 小程序 | 微信原生开发（WXML/WXSS/JS） | MVP 功能简单，无需跨端框架增加复杂度 |
| 生产端后端 | Python（FastAPI + uvicorn） | AI 生态完善，与爬虫/LLM/TTS 同语言降低维护成本 |
| 消费端后端 | 腾讯云函数 SCF（Python 3.10） | Serverless 免运维，按量付费，自动满足公网 HTTPS |
| 业务数据库 | SQLite（aiosqlite 驱动） | V1.0 的 MySQL 改为 SQLite：单机单用户场景无需独立数据库服务，零运维 |
| 缓存 | cachetools.TTLCache（内存） | V1.0 的 Redis 改为内存缓存：单机场景无高并发需求 |
| 对象存储 | 腾讯云 COS + CDN | 与微信生态集成最佳，CDN 加速音频分发；同时承载 C 端元数据 JSON |
| 爬虫 | httpx + feedparser + newspaper3k | V1.0 的 Scrapy+Playwright 改为轻量化方案：MVP 仅爬 RSS + 列表页，无需浏览器渲染；降低 PyInstaller 打包复杂度 |
| LLM | 通义千问 API（qwen-max） | MVP 阶段直接用 API，无需自研部署 GPU |
| TTS | 阿里云语音合成 API（小芸音色） | V1.0 的 CosyVoice 本地部署改为云端 API：单机无独立 GPU，CPU 推理不可接受 |
| 音频处理 | FFmpeg | 业界标准，拼接/转码/静音处理 |
| 调度 | APScheduler（Python） | 嵌入 FastAPI 进程，无需独立调度服务 |
| 后台前端 | Vue 3 + Element Plus | 构建产物由 FastAPI StaticFiles 挂载，无需独立 Web 服务器 |
| 打包分发 | PyInstaller + Inno Setup | V1.0 的 Docker Compose 改为单机 exe：双击安装，桌面快捷方式启动 |

#### 7.2.2 替代方案

- 若通义千问 API 成本过高或稳定性不足，可切换智谱 GLM API、DeepSeek API；
- 若阿里云 TTS 音色不满意，可切换腾讯云 TTS 或 Azure TTS；
- 若用户后期需要多人协作或多机部署，可平滑回退到 V1.0 的 Docker + MySQL + Redis 架构（SQLAlchemy ORM 兼容切换）。

## 8. 接口需求

### 8.1 C 端接口（小程序 ↔ 云函数，V1.1 由腾讯云 SCF 提供）

> V1.1 变更：C 端接口从单机后端迁移到云函数，接口规格保持兼容。云函数直接读取 COS 中的节目元数据 JSON，无需单机 exe 在线。

#### 8.1.1 用户登录

```
POST /api/v1/auth/login
Request: { code: string }
Response: { token: string, expires_in: number, user: { openid, nickname, avatar } }
```

说明：云函数调用微信 `code2session` 换 openid，JWT 签发与验签在云函数侧独立完成。

#### 8.1.2 获取今日节目

```
GET /api/v1/episodes/today
Response: {
  id, date, title, duration, audio_url, cover_url,
  categories: string[], status: 'published'
}
```

说明：云函数读取 `COS://episodes/meta/{today}.json`，找不到返回 404。

#### 8.1.3 获取历史列表

```
GET /api/v1/episodes/history?page=1&size=20
Response: { total, list: [{ id, date, title, duration, cover_url, categories }] }
```

说明：云函数读取 `COS://episodes/index.json` 并按分页返回。

#### 8.1.4 获取节目详情

```
GET /api/v1/episodes/{id}
Response: { id, date, title, duration, audio_url, cover_url, script, categories }
```

说明：云函数读取 `COS://episodes/meta/{date}.json`。script 字段为懒加载，仅在用户点击「查看文稿」时请求。

#### 8.1.5 上报播放进度

```
POST /api/v1/playlogs/progress
Request: { episode_id, position, duration, completed: boolean }
Response: { success: true }
```

说明：云函数将进度写入 `COS://playlogs/{user_id}/{episode_id}.json`。单机 exe 不消费此数据（C 端用户进度不影响生产端）。

#### 8.1.6 提交反馈

```
POST /api/v1/feedbacks
Request: { content: string, contact?: string }
Response: { success: true, ticket_id: string }
```

说明：云函数写入 `COS://feedbacks/{ticket_id}.json`，单机 exe 可定时拉取同步至本地 SQLite。

### 8.2 内部接口（运营后台 ↔ 单机 exe 后端）

> V1.1 变更：内部接口仅在单机 exe 内提供，运营人员通过浏览器访问 `http://127.0.0.1:8000/admin/`。

#### 8.2.1 触发工作流

```
POST /api/internal/workflow/trigger
Request: { date: string, source: 'cron' | 'manual' }
Response: { workflow_id, status: 'running' }
```

#### 8.2.2 查询工作流状态

```
GET /api/internal/workflow/{workflow_id}
Response: {
  status: 'running' | 'success' | 'failed',
  steps: [{ name, status, started_at, finished_at, error? }],
  episode_id?: string
}
```

### 10.5 语音风格与广告植入推荐说明

#### 10.5.1 语音风格推荐：阿里云内置优质神经语音

**推荐理由**：
1. 10 分钟时长的语音播报对听感要求极高，单一 TTS 音色容易疲劳，需选择成熟稳定的神经语音方案；
2. V1.2 采用阿里云内置优质神经语音（推荐小芸女声），无需本地 GPU，云端 API 并发合成 5-6 段，单次合成 ≤ 2 分钟；
3. 阿里云语音合成支持 SSML（语音合成标记语言），可通过 SSML 标签控制停顿、语速、情感，听感接近专业电台；
4. MVP 简化：先选定 1 个内置音色（小芸），全档播报统一使用，零训练成本、零运维成本；
5. 后续 V2.0 可评估阿里云定制音色（上传样本训练）或切换其他 TTS 供应商。

**实施建议**：
- 选用阿里云小芸女声作为 MVP 默认音色；
- 通过 SSML 标签控制开场白/新闻正文/结尾的语速与情感；
- 后续 V2.0 可评估多角色轮播或定制音色。

#### 10.5.2 广告植入推荐：开头 5s + 中间 30s + 结尾 10s 三段式

**推荐理由**：
1. 完全无广告商业化空间不足，难以覆盖内容生产成本；
2. 纯中间插播用户体验割裂，开头与结尾无引导显得突兀；
3. 三段式平衡体验与变现，总时长 45s，占 10 分钟的 7.5%，符合行业惯例（电台广告占比 8-12%）。

**分段设计**：
- **开头 5-10s**：品牌口播（如「20_News 由 XX 赞助播出」），轻量引导，不打断内容期待；
- **中间 30s**：5 分钟处插播主广告，利用注意力转换点（听众此时已适应内容，注意力略有松懈，广告打断感弱）；
- **结尾 10s**：尾版 + 下期预告 + CTA（如「明日 7 点，继续听」），引导复访。

**平滑处理**：
- 广告前后各加 0.5s 静音过渡；
- 广告音频与主音频码率/采样率一致，避免拼接处爆音。
