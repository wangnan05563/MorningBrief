# 素材多输入渠道说明（有声读物 / 课程）

> 适用范围：本系统的「有声读物」与「课程」模块共用同一套 **频道 + 素材池 + 语音流水线**
> （crawl → rewrite → tts → stitch → review → publish）。「素材」是流水线的输入单元，
> 本文档说明可通过哪些**渠道**把内容送进素材池，以及各渠道的**适用场景**与**数据格式要求**。

---

## 0. 总览

| 渠道 | source_type | 去重方式 | 入口（运营后台） | 是否需 URL |
|------|-------------|----------|------------------|-----------|
| RSS 通用资讯源 | `rss` | URL 唯一 | 频道配置 → RSS 源 | 是（feed 地址） |
| 书籍 RSS 预制源 | `book_rss` | URL 唯一 | 频道配置 → 书籍 RSS 源（仅有声读物） | 是（feed 地址） |
| 本地文件上传 | `list` | 内容哈希 | 素材录入 → 本地文件上传 | 否（自动合成） |
| 云端存储导入（COS） | `cos` | 内容哈希（按 key） | 素材录入 → 云端存储导入 | 否（对象 key） |
| 手动录入 | `list` | 内容哈希 | 素材录入 → 手动录入 | 否（自动合成） |
| API / 网页 URL 拉取 | `api` | URL 唯一 | 素材录入 → API·URL 拉取 | 是 |
| 二维码 / 链接分享 | `qrcode` | URL 唯一 | 素材录入 → 二维码·链接分享（预览后转手动） | 是 |

> 说明：有声读物在系统中**不是独立模块**，而是 `channel_type = audiobook` 的一种频道；
> 书籍 RSS 直接喂 `audiobook` 频道，复用与课程完全相同的素材/流水线机制，改动最小。

---

## 1. RSS 通用资讯源（`rss`）

- **适用场景**：课程/资讯类频道从外部新闻、博客、行业站点的 RSS/Atom feed 自动采集。
- **数据格式**：标准 RSS 2.0 / Atom，`<item>`/`<entry>` 含 `title` + `link` + `description`/`content`。
- **配置方式**：运营后台「频道管理 → 编辑频道 → RSS 源」多选（源来自预制 `rss.yaml`，
  也可由爬虫巡检 URL 可达性）。crawler 启动时按频道白名单过滤通用源。
- **去重**：按条目 `link`（URL）唯一；同一 URL 二次抓取自动跳过。

---

## 2. 书籍 RSS 预制源（`book_rss`）——有声读物专属

- **适用场景**：有声读物频道从「书 / 章 / 书评」类 feed 采集内容。预制源面向 audiobook，
  与通用资讯 RSS 隔离，避免新闻源混入有声读物。
- **预制清单**（`backend/app/workflow/crawler/sources/book_rss.yaml`，运营可自由增删）：
  | 源名称 | 品类提示 | 权威度 |
  |--------|----------|--------|
  | 豆瓣读书-最新书评 | 书评 | 0.85 |
  | 豆瓣读书-新书速递 | 新书 | 0.85 |
  | 书格-古籍善本 | 古籍 | 0.80 |
  | Kindle伴侣-电子书资讯 | 电子书 | 0.78 |
  | 看理想-人文谈话 | 人文 | 0.78 |
  | 机核-游戏文化播客 | 游戏文化 | 0.80 |
- **配置方式**：运营后台「频道管理 → 编辑有声读物频道 → 书籍 RSS 源」多选；
  crawler 仅对 `channel_type = audiobook` 的频道合并这些源。
- **数据格式**：标准 feed；条目即书/章，`article_parser` 会尽力提取 author / book 等元数据。
- **去重**：按条目 URL 唯一。

---

## 3. 本地文件上传（`list`）

- **适用场景**：运营已有现成文稿（`.txt` / `.md`），希望直接转成有声读物/课程章节。
- **数据格式**：
  - 支持 `.txt` / `.md`（零依赖解析）；`.pdf` / `.docx` / `.html` 需安装对应解析库（见报错提示）。
  - 文档按 Markdown 标题分章，无标题则按空行分段；超长章节自动切块（≤1200 字）保持顺序。
- **入口**：素材录入页「本地文件上传」Tab，选择频道 + 上传文件。
- **去重**：按章节**正文内容哈希**（`content_hash`）去重，重复上传自动跳过；
  URL 由系统合成（`list://{channel_id}/{hash[:16]}`），无需用户提供。

---

## 4. 云端存储导入（COS）（`cos`）

- **适用场景**：团队素材已存于对象存储（COS），按对象 key 取回后解析为章节，避免本机中转。
- **前置条件**：后台「云端存储」已配置 Bucket / SecretId / SecretKey 且通过连接测试。
- **数据格式**：同本地文件（`.txt` / `.md` 等），按 key 取回二进制后走同一解析器。
- **入口**：素材录入页「云端存储导入」Tab，填写对象 key + 目标频道。
- **去重**：按对象 key 的内容哈希去重；URL 合成 `cos://{channel_id}/{key[:16]}`。

---

## 5. 手动录入（`list`）

- **适用场景**：少量零散内容、或对上述自动渠道拉取结果的人工补录/修订。
- **数据格式**：表单填写 `标题` + `正文` + 可选 `分类`；无文件、无 URL。
- **入口**：素材录入页「手动录入」Tab。二维码分享预览后「转为手动录入」也会回填此表单。
- **去重**：按正文内容哈希去重；URL 合成 `list://{channel_id}/{hash[:16]}`。

---

## 6. API / 网页 URL 拉取（`api`）

- **适用场景**：
  - 对接 CMS / 知识库 / 第三方接口返回的文章页或 JSON；
  - 复用 `article_parser.extract` 抓取并解析正文（支持文章页与多数 API 返回内容）。
- **数据格式**：传入一个**可公开访问的文章页或 API URL**；系统自动提取 `title` + `content`
  （`og:image` 作封面）。无法提取正文时返回 400，建议改用「手动录入」。
- **入口**：素材录入页「API·URL 拉取」Tab，填写 URL + 目标频道。
- **去重**：按 URL 唯一；重复 URL 自动跳过。

---

## 7. 二维码 / 链接分享（`qrcode`）

- **适用场景**：运营扫码或收到分享链接后，先**预览**内容再决定是否入库，避免自动入库脏数据。
- **交互**：素材录入页「二维码·链接分享」Tab 粘贴链接 → 拉取预览（标题/正文）→
  点「转为手动录入（qrcode）」回填手动表单 → 人工复核后提交。
- **数据格式**：同 API 拉取（一个可访问 URL）；预览不入库，正式入库标记 `source_type = qrcode`。
- **去重**：按 URL 唯一。

---

## 8. 实施要点（开发者）

- **source_type 枚举**（`app/models/material.py::MaterialSourceType`）：
  `rss / list / book_rss / cos / api / qrcode`。DB 层**不再保留** `ck_material_source_type`
  约束（旧库由启动期迁移 `_migrate_material_source_type_constraint` 删除），枚举扩展无需迁移；
  合法性统一在 `materials` 路由层校验。
- **去重核心**（`app/routers/admin/materials.py::_persist_material`）：
  `list`/`cos` 走 `(source_type, dedup_key)`，`rss`/`book_rss`/`api`/`qrcode` 走 `url` 唯一键。
- **书籍 RSS 加载**（`app/services/rss_source_service.py`）：`load_book_rss_sources()` 与
  `load_rss_sources()` 对称，供 crawler 与 `GET /admin/api/v1/channels/book-rss/sources` 复用。
- **前端入口**：`apps/admin-web/src/views/channel/CourseMaterials.vue`（素材录入 5 Tab）；
  有声读物频道编辑页 `ChannelManagement.vue` 提供「书籍 RSS 源」多选。
- **测试**：`backend/tests/test_book_rss_sources.py`（预制源加载）、
  `backend/tests/test_material_source_types.py`（多 source_type 入库与去重）。
