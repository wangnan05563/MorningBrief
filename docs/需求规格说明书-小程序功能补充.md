## 1. 引言

### 1.1 编写目的

V1.2 基线需求规格说明书定义了 MVP 阶段的核心闭环（AI 工作流 → 审核 → 发布 → 小程序播放），但小程序端在落地过程中暴露出三类问题：

1. **半成品断裂**：收藏、反馈、设置、关于四个页面代码已写好，但未注册到 `app.json`，且 `api.js` 未导出对应函数、后端无 C 端路由，导致功能完全不可用；
2. **设置项形同虚设**：倍速、自动连播、WiFi 限制、新节目通知等设置写入 localStorage 后无任何代码读取应用；
3. **与管理端能力不对齐**：管理端已具备多频道架构（`channel_id` / `rss_sources` / `keywords` / 频道级提示词 / 频道级 BGM），但小程序端仅有"今日节目"单条展示，无法体现多频道内容供给；
4. **竞品标配缺失**：搜索、分类筛选、睡眠定时、倍速 UI、订阅消息、隐私协议合规等同类小程序标配功能缺失。

本文档旨在系统性补充上述缺失功能的需求规格，作为 V1.2 基线的增量补充，指导小程序端从"能播放的 demo"推进到"可上线的资讯音频小程序"。

| 术语 | 含义 |
| --- | --- |
| 半成品断裂 | 指页面代码已存在但未注册到 `app.json`、或 API 函数未导出、或后端路由未实现，导致功能无法使用的状态 |

### 2.2 管理端能力对齐缺口

> 数据来源：`admin-web/` 全量源码审计

管理端已具备的能力中，小程序端尚未对齐的部分：

| 管理端能力 | 实现位置 | 小程序端现状 | 对齐缺口 |
| --- | --- | --- | --- |
| **多频道架构** | `ChannelManagement.vue` | 小程序仅有"今日节目"单条展示 | 小程序无法按频道浏览/筛选/订阅 |
| 频道级 RSS + 关键词 | Channel.rss_sources / keywords | — | 小程序无需感知，但频道作为内容分类需暴露给用户 |
| 频道级 BGM / 提示词 | Channel.bgm_path / intro_prompt | — | 生产端能力，小程序不直接消费 |
| **素材管理** | WorkflowDetail 折叠面板 | 小程序无素材溯源展示 | 用户无法查看新闻来源（合规风险） |
| **工作流监控** | WorkflowList / WorkflowDetail | — | 运营侧能力，小程序不需对齐 |
| **AI 配置** | AIConfig.vue | — | 运营侧能力，小程序不需对齐 |
| **审核管理** | ReviewList / ReviewDetail | — | 运营侧能力，小程序不需对齐 |
| **广告管理** | AdMaterials / AdPlacements / AdSchedule | 小程序仅播放成品音频 | 无需对齐（广告已内嵌于音频） |
| **数据统计** | StatsOverview | 小程序 profile 收听统计恒为 0 | 需对齐：小程序需展示用户个人收听统计 |
| **队列管理** | QueueManagement | — | 运营侧能力，小程序不需对齐 |
| **通知管理** | NotificationConfig（钉钉） | 小程序无订阅消息 | 需对齐：小程序需对接微信订阅消息推送给 C 端用户 |
| **用户反馈查看** | 后端有 `/admin/api/v1/feedbacks` | 小程序反馈页断裂 | 需对齐：小程序反馈需写入后端，管理端可查看 |
| **收藏** | 后端有 `Favorite` 模型（但无 C 端路由） | 小程序收藏页断裂 | 需对齐：补齐 C 端 favorites 路由 |
| **数据库维护** | DatabaseAdmin | — | 运营侧能力，小程序不需对齐 |

**核心对齐结论**：管理端已构建完善的多频道生产与运营能力，但小程序端作为消费侧，仅暴露了"今日节目 + 历史列表"两个内容入口，未能将多频道内容供给转化为用户可感知的浏览/筛选/订阅能力。同时收藏、反馈、个人统计三类用户侧功能虽后端模型已存在，但 C 端路由与小程序页面均断裂，需补齐。

### 2.4 微信小程序平台能力边界（2026）

| 能力 | 状态 | 对本项目的约束/机会 |
| --- | --- | --- |
| 后台音频播放 `BackgroundAudioManager` | ✅ 支持 | 已实现，锁屏/后台播放正常 |
| 订阅消息 `wx.requestSubscribeMessage` | ✅ 支持 | 需对接，用于新节目上线通知 |
| 隐私协议 `wx.requirePrivacyAuthorize` | ✅ 强制 | 2026 年必须接入，否则限制敏感接口 |
| 更新管理 `wx.getUpdateManager` | ✅ 支持 | 需接入，发版后强制用户更新 |
| 头像昵称填写 `chooseAvatar` + `nickname` | ✅ 支持 | 需对接，替代旧的 `wx.getUserProfile`（已废弃） |
| 文件下载 `wx.downloadFile` | ✅ 支持 | 离线缓存可基于此实现（P2） |
| 本地存储 `wx.setStorageSync` | ✅ 支持（10MB 上限） | 设置项、播放进度缓存可用 |
| 视频/直播 | ✅ 支持 | 本项目不需要 |
| 分享朋友圈 `onShareTimeline` | ✅ 支持 | 需补充，扩大触达 |
| 扫码/识别二维码 | ✅ 支持 | 本项目不需要 |
| 音频倍速 `playbackRate` | ✅ 支持 | 需在播放器 UI 暴露 |
| 网络类型 `getNetworkType` | ✅ 支持 | WiFi 限制功能可基于此实现 |

**关键约束**：
1. **隐私合规**：2026 年微信要求所有涉及用户信息的小程序首次交互前必须弹窗隐私协议，否则限制调用 `wx.login`、`wx.getUserInfo` 等敏感接口，严重者下架；
2. **订阅消息一次性**：`wx.requestSubscribeMessage` 每次授权仅允许发送一条模板消息，需在用户触发时请求（如点击"订阅"按钮），不能一次性永久订阅；
3. **本地存储 10MB 上限**：离线缓存音频不可行（单条 10 分钟音频约 5-10MB），离线方案需用 `wx.downloadFile` + 文件系统管理（P2 评估）。

### 3.4 用户故事总览

**作为通勤白领**：
- 我希望能在播放器内直接切换倍速，这样可以根据通勤时间灵活调整；
- 我希望能按频道筛选历史节目，这样能快速找到想听的科技/财经内容；
- 我希望能收藏感兴趣的节目，这样能反复收听；
- 我希望能设置睡眠定时，这样睡前听不会一直播放。

**作为中老年用户**：
- 我希望能看到清晰的收听统计，这样有成就感；
- 我希望能通过订阅消息收到新节目通知，这样不会错过；

```
  body: { touser, template_id, page, data }
```

*数据模型*：新增 `Subscription` 模型：`id` + `user_id` + `template_id` + `subscribed_at` + `used`（0/1）+ `sent_at`。

## 8. 数据模型变更

### 8.1 新增模型

#### 8.1.1 Subscription（订阅消息记录）

> 用于 FR-SUP-12 微信订阅消息推送

```python
# backend/app/models/subscription.py
class Subscription(Base):
    __tablename__ = "subscription"
    id: int (PK)
    user_id: int (FK → user.id)
    template_id: str (微信订阅消息模板 ID)
    subscribed_at: datetime (用户授权时间)
    used: int (0=未推送, 1=已推送)
    sent_at: datetime (实际推送时间, nullable)
    
    UNIQUE(user_id, template_id, subscribed_at)  # 同一用户同一模板多次授权
    INDEX idx_subscription_used (used)  # 按未推送查询
```

#### 8.1.2 ChannelSubscription（频道订阅）

> 用于 FR-SUP-17 订阅频道/关注

```python
# backend/app/models/channel_subscription.py
class ChannelSubscription(Base):
    __tablename__ = "channel_subscription"
    id: int (PK)
    user_id: int (FK → user.id)
    channel_id: int (FK → channel.id)
    created_at: datetime
    
    UNIQUE(user_id, channel_id)  # 不可重复订阅
    INDEX idx_channel_sub_user (user_id)
```

## 11. 附录

### 11.1 竞品调研详情

#### 11.1.1 喜马拉雅

- **形态**：App + 微信小程序
- **核心功能**：频道订阅、个性化推荐、下载离线、倍速（0.75-2.0）、睡眠定时、播放列表、评论点赞、咔嚓录音、助眠白噪音、趣配音
- **优势**：主播 IP 化、内容丰富、广告植入自然、社区氛围成熟
- **可吸收**：频道订阅、倍速、睡眠定时、播放列表
- **不采纳**：助眠白噪音（与新闻定位不符）、趣配音（UGC 与 AI 生产定位不符）

#### 11.1.2 蜻蜓FM

- **形态**：App + 微信小程序（2017 年首批入驻小程序）
- **核心功能**：电台直播、有声书、分类浏览、订阅、下载、倍速、定时关闭
- **优势**：电台直播资源、有声书库丰富
- **可吸收**：分类浏览（对应本项目频道筛选）、定时关闭

#### 11.1.3 得到

- **形态**：App + 微信小程序
- **核心功能**：知识付费课程、听书、订阅、倍速、文稿同步、笔记、分享卡片
- **优势**：知识付费闭环、文稿同步体验好
- **可吸收**：文稿同步（已实现）、分享卡片（已实现）

#### 11.1.4 小宇宙

- **形态**：App
- **核心功能**：播客订阅、播放进度记忆、倍速、章节标记、评论、时间戳书签
- **优势**：UGC 社区氛围、播放器体验优秀
- **可吸收**：播放进度记忆（已实现）、章节标记（对应本项目分段展示）

#### 11.1.5 腾讯新闻小程序

### 11.2 风险清单

| 风险 | 等级 | 应对措施 |
| --- | --- | --- |
| 隐私协议未接入被微信限功能 | 高 | Phase 1 首要任务 FR-SUP-05 |
| 订阅消息一次性授权导致推送率低 | 中 | 每次用户打开小程序时引导重新订阅 |
| 多频道内容供给不足（频道数 < 3） | 中 | 首页降级为单频道模式，保持现状 |
| 搜索结果为空（节目积累不足） | 低 | MVP 仅搜标题，后期接入全文检索 |
| 离线缓存占用过多本地存储 | 低 | 限制最多 5 期，超出提示清理 |
| 微信基础库版本要求（2.32.3+） | 低 | 在 `app.json` 配置 `libVersion`，低版本提示升级 |
