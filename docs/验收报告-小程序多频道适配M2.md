## 2. 后端改造清单

### 2.1 数据模型迁移
- `Channel` 模型新增字段（启动迁移 `_migrate_channel_schema` 幂等落地，存量频道回填 `news`）：
  - `channel_type`（默认 `news`，枚举 `news`/`course`/`audiobook`）
  - `type_label`（分组展示名）
  - `cover_url`（频道/课程封面）
  - `disclaimer_level`（合规提示强度 `none`/`normal`/`strong`）
- 复用既有 `display_order`（V1.3 频道动态排序）。

### 2.2 接口扩展
- `GET /api/v1/channels`（及带订阅态版本）：响应随行返回 `channel_type` / `type_label` / `cover_url` / `disclaimer_level` / `selection_strategy` / `episode_count`（SRS §6.1）。
- 新增 `GET /api/v1/courses/{channel_id}/progress` → `{total, learned, percent, last_chapter_id, last_position}`：
  - `total` = 该频道已发布章节数；`learned` = 用户 `completed==1` 或 `position/duration ≥ 0.95` 章节数；
  - 频道不存在 → 404；**非课程类频道（news 等）→ 404**（明确语义边界，仅服务 course/audiobook）。
- `GET /api/v1/episodes/search`：新增 `channel_type` 参数（`pattern="^(news|course|audiobook)$"`）。

### 2.3 搜索能力修复（关键 bug）
- FTS5 默认 `unicode61` 分词器**不索引中文（CJK）**，原实现仅在 FTS5 抛异常时降级 → 中文搜索静默返回空。
- 修复：`search_episodes` 在 FTS5 命中为空时也降级到 `LIKE`（LIKE 是 FTS5 超集，空结果补查无副作用）；FTS5/LIKE 两条路径均用 `LEFT JOIN channel`（避免无 `channel_id` 的遗留节目被丢弃）。
- `audiobook` 在「课程」筛选下通过聚合组 `_CHANNEL_TYPE_GROUP={'course':['course','audiobook']}` 一并命中（与前端"课程"筛选口径一致）。

## 3. 小程序改造清单

### 3.1 类型/皮肤抽象（FR-MC-01 / FR-MC-08）
- `utils/skin.js`：建立 `SKINS` 皮肤映射（`news`/`course`/`audiobook`）+ `TYPE_LABELS`；`normalizeType` 对**未知/缺失类型一律回退 `news` 皮肤 + `console.warn` 告警**（FR-MC-12 防御式兜底核心）；`getChannelTypeLabel` / `getDisclaimerText` / `getDisclaimerLevel` / `isCourseType`。
- `services/api.js`：`fetchChannels` 经 `normalizeChannel` 归一化（补 `channel_type` 缺省 `news`、`disclaimer_level` 缺省 `none`、`type_label` 推导），按 `id` 索引缓存于 `globalData.channelsMeta`，各页 O(1) 查类型；`channelType(id)` 取类型。

### 3.2 首页分组（FR-MC-02 / FR-MC-12）
- 首页胶囊按 `channel_type` 分组（资讯 / 课程），组序固定，课程类走课程主页分支（`onSwitchChannel`）。
- 分组逻辑使用 `skin.normalizeType` 归一化（FR-MC-12 加固）：后端新增未在小程序定义的类型时归入资讯组显示，不丢失、不崩溃。

### 3.3 课程主页与章节（FR-MC-03 / FR-MC-04 / FR-MC-05）
- 新增 `pages/course/course`：课程封面/简介 + 按 `published_at` 升序章节列表（复用 `history` 接口）+ 每章学习状态（未学/学习中/已学完，阈值 0.95）+ 整体「继续学习 / 从头播放」。
- `detail` 页叠加章节语义：`isCourse` 时显示「第 X 章 / 共 Y 章」与课程名，完播自动连播下一章（`audio.js` 队列 + `setQueue`）。
- `profile`「我的课程」卡片：列出 `is_subscribed && isCourseType` 的频道，展示进度条与「继续」入口。

### 3.4 订阅与订阅消息（FR-MC-06）
- 课程主页订阅按钮复用 `subscribeChannel` / `unsubscribeChannel` + `wx.requestSubscribeMessage`。
- 订阅消息模板按 `channel_type` 区分（资讯「今日节目已更新」/ 课程「新课上线」），模板 id 由后端下发 `subscribe_template_id`，小程序不写死；点击通知经 `app.js` 三级兜底路由（ct → 缓存 → 拉列表判定）跳课程主页。

### 3.5 跨类型搜索（FR-MC-07）
- `pages/search`：类型筛选条（全部/资讯/课程）+ 结果项类型标签（`skin.getChannelTypeLabel`）与频道名 + 课程类结果路由课程主页。
- `services/api.js#searchEpisodes` 第 4 参 `channelType` → 后端 `channel_type`。

### 3.6 离线下载（FR-MC-09，P2）
- `services/download.js`：按 `openid` 持久化下载登记表（`news_downloads_{openid}`，本地存储，V1.2 单机约束），支持增删查/按频道清空/统计占用/退出登录清理；删除联动物理文件 `removeSavedFile`。
- `services/audio.js`：`_pickPlayableUrl` 新增离线下载命中分支（离线播放自动生效）；`downloadEpisode`（幂等、选源、进度回调、`saveFile` 持久化、防并发）+ `cancelDownload`。
- `pages/course/course`：「下载整门课程 / 下载本章」按钮与状态；`pages/download/download` 管理页（按课程分组、占用显示、单条/按课程/全量清理、点击离线播放）；`app.json` 注册 + `profile`「我的下载」入口。

### 3.7 埋点与统计（FR-MC-10，P1）
- 五类课程事件复用 `utils/tracker.js`：`course_view` / `chapter_play` / `chapter_finish`（detail 完播且 `isCourse`）/ `course_subscribe` / `continue_learn`。
- 修复 `profile` 统计恒为 0（GAP-11）：`local-data.js#getLocalStats` 本地聚合（收听秒数/期数/完播数/收藏数），`profile.loadStats` 在后端返回全 0/异常时统一用本地兜底。

### 3.8 合规提示（FR-MC-11，P0）
- `skin.js`：`DISCLAIMER_COPY`（`none`/`normal`/`strong`）。
- `course` 页与 `detail` 页均展示合规提示条（`wx:if disclaimerText`，`strong` 红底强提示，无关闭按钮不可误关，不遮挡播放操作），文案按 `channel.disclaimer_level` 分级。

## 5. 已知约束与后续建议

### 已知约束
- **离线下载仅本机存储**：受 V1.2 单机约束，不涉及服务端同步；换设备/清缓存需重新下载。
- **课程进度服务端读 `play_progress` 快照**：作为 MVP 兜底（COS→DB 聚合前为滞后数据）；前端 `fetchCourseProgress` 仍优先本地 `localData` 聚合，后端不可用时优雅降级，与「C 端进度真相源=小程序本地」设计一致。
- **合规提示依赖后端配置 `disclaimer_level`**：未配置（默认 `none`）则不强提示；医疗/法律/财经课程需在后端显式置 `strong` 并保留 `review` 人工审核链路（NFR-MC-07）。

### 类型扩展注册契约（FR-MC-12 设计约束）
审计确认：在既有三类型词汇（news/course/audiobook）内，**无需发版**即可显示与学习——`audiobook` 已是一级支持类型。但若要引入**全新第 4 种类型**，需按以下 5 个注册点同步登记（均为显式白名单，非自动推断）：
1. `miniprogram/utils/skin.js` → `SKINS` + `TYPE_LABELS`（皮肤/标签/胶囊角标/合规等级映射）。
2. `backend/app/routers/admin/channels.py` → `channel_type` 校验白名单（`not in ("news","course","audiobook")`）。
3. `backend/app/routers/api/episodes.py` → `GET /search` 的 `channel_type` Query `pattern`（正则 `^(news|course|audiobook)$`）。
4. `backend/app/routers/api/courses.py` → 课程进度端点类型元组（`not in ("course","audiobook")`）。
5. `backend/app/services/content_service.py` → `_CHANNEL_TYPE_GROUP`（搜索聚合组，决定「课程」筛选是否展开含该类型）。

> 设计权衡：未知/未登记类型一律 `normalizeType` 回退 `news` + 控制台告警（FR-MC-12 防御兜底），避免崩溃；新类型必须显式登记上述 5 点，而非"完全免改"。
