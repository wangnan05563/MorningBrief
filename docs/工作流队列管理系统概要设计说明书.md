## 1. 引言

### 1.1 编写目的

本说明书在《工作流队列管理系统需求规格说明书》V1.1 基础上，完成队列管理子系统的总体架构与模块级设计，作为后续详细设计与编码的依据。文档目标：

- 明确队列子系统在现有 V1.2 混合架构中的定位与模块边界；
- 给出队列调度、频道管理、可视化界面三大核心模块的设计方案、关键流程、对外接口；
- 定义数据模型、存储方案、并发控制策略；
- 明确错误处理、安全、性能等非功能性设计要点。

读者读完后应能够：理解队列子系统全貌，独立承担所负责模块的详细设计与编码，并知道模块如何与现有工作流调度协作。

### 1.2 项目背景

详见《工作流队列管理系统需求规格说明书》第 1.2 节。本子系统在不动摇 V1.2 混合架构（单机 exe + SQLite + TTLCache + 云函数）的前提下，为工作流调度层引入：

1. **优先级队列**：替代 TTLCache 互斥锁，支持任务排队与优先级调度；
2. **多频道管理**：新增 Channel 实体，支持按内容分类频道独立产出节目；
3. **并行执行**：支持串行/并行执行模式配置，并行模式下限制最大并发数；
4. **可视化队列管理**：前端队列管理页面，支持任务 CRUD、实时状态、详情查看。

### 1.3 术语与缩略语

继承 SRS V1.1 术语，新增：

| 术语 | 含义 |
| --- | --- |
| HLD | High Level Design，概要设计 |
| LLD | Low Level Design，详细设计 |
| 队列条目 | PriorityQueue 中的元素，包含 workflow_id、priority、created_at、cancelled 标记 |
| 信号量延迟重建 | 配置变更后不立即重建 Semaphore，等待当前任务完成后重建的策略 |

### 1.4 设计原则

继承 SRS V1.1 设计原则，补充：

1. **复用优先**：最大化复用现有 `_run_workflow` / `_run_step` / EventBus / NotifierHub 机制，仅替换触发入口与并发控制层；
2. **单一真相源**：队列状态以 SQLite `workflow` 表为权威源，PriorityQueue 为内存加速层，重启后从 DB 重建；
3. **渐进增强**：Channel 为轻量分组标签，不绑定业务配置，后续迭代扩展为完整频道配置；
4. **故障安全**：Semaphore 泄漏防护（try/finally）、PriorityQueue 重启恢复、配置延迟生效避免竞态。

## 2. 系统总体设计

### 2.1 子系统定位

队列管理子系统是生产端（单机 exe）内部的工作流调度增强层，定位如下：

│  │  │  │ Service  │ │ Scheduler│ │ 前端页面         │ │  │  │
│  │  │  └──────────┘ └─────┬────┘ └──────────────────┘ │  │  │

**关键边界**：
- 队列子系统**仅增强调度层**，不改造 AI 工作流内部逻辑（crawl/rewrite/tts/stitch/review）；
- 队列子系统**不涉及消费端**（云函数、小程序、COS）；
- Episode 表仅新增 `channel_id` 字段做最小适配，完整频道化改造为后续迭代。

### 2.4 关键设计决策

| 决策点 | 方案 | 理由 |
| --- | --- | --- |
| 队列实现 | asyncio.PriorityQueue + asyncio.Semaphore | 单进程异步架构，无需引入 Redis/RabbitMQ；PriorityQueue 原生支持优先级排序 |
| 并发控制 | asyncio.Semaphore(max_concurrent) | 比 TTLCache 互斥锁更灵活，支持 N 并发而非仅 1 |
| 配置热生效 | 延迟重建 Semaphore（标记 `_config_dirty`） | 避免直接替换 Semaphore 导致等待中任务泄漏 |
| 队列状态权威源 | SQLite workflow 表 | 重启后从 DB 重建 PriorityQueue，不丢失排队任务 |
| 频道深度 | 轻量标签（id/name/description/is_active） | MVP 阶段不绑定业务配置，降低复杂度，后续迭代扩展 |
| CHECK 约束 | 移除 DB 层 CHECK，仅靠 ORM 枚举约束 | SQLite create_all 不修改已存在表的约束，避免复杂迁移脚本 |
| 条目移除 | 标记 `_cancelled=True`，worker 出队时跳过 | asyncio.PriorityQueue 不支持随机删除，标记法简单可靠 |
| workflow_id 并发安全 | 入队操作加 asyncio.Lock 串行化 | 防止多频道并发触发时序号冲突，入队耗时 < 100ms 不影响性能 |

### 3.2 队列调度服务（WorkflowScheduler 改造）

#### 3.2.1 职责

管理优先级队列的入队、出队、并发控制、重启恢复、配置热生效。

#### 3.2.2 核心属性

```python
class WorkflowScheduler:
    # 队列与并发控制
    _queue: asyncio.PriorityQueue          # 优先级队列
    _semaphore: asyncio.Semaphore          # 并发信号量
    _trigger_lock: asyncio.Lock            # 入队串行化锁（防 workflow_id 冲突）
    _config_dirty: bool                    # 配置变更标记（延迟重建 Semaphore）
    _entry_map: dict[str, QueueEntry]      # workflow_id → 队列条目映射（支持取消/改优先级）

    # 当前配置
    _execution_mode: str                   # "serial" | "parallel"
    _max_concurrent: int                   # 1-5
```

#### 3.2.3 队列条目设计

```python
@dataclass(order=True)
class QueueEntry:
    """PriorityQueue 条目。

    order=True 使 PriorityQueue 按 sort_priority 排序。
    sort_priority 为负数实现 DESC（PriorityQueue 是最小堆）。
    """
    sort_priority: int                     # -priority（实现 DESC）
    created_at: float                      # 入队时间戳（同优先级 FIFO）
    workflow_id: str = field(compare=False)
    channel_id: int | None = field(compare=False)
    priority: int = field(compare=False)
    cancelled: bool = field(compare=False, default=False)
```

#### 3.2.4 核心流程

**入队流程：**

```
trigger_workflow(channel_id, priority)
  │
  ├─ async with _trigger_lock:           # P0-4: 串行化防 ID 冲突
  │   ├─ 生成 workflow_id（日期 + DB当日最大序号+1）
  │   ├─ 写 DB: Workflow(status=queued, channel_id, priority)
  │   ├─ 创建 QueueEntry(sort_priority=-priority, created_at=now)
  │   ├─ _entry_map[workflow_id] = entry
  │   └─ await _queue.put(entry)
  └─ 返回 workflow_id
```

**消费流程：**

```
_queue_worker（后台协程，应用启动时 create_task）
  │
  loop:
    ├─ await _semaphore.acquire()         # 等待并发许可
    ├─ entry = await _queue.get()         # 取最高优先级条目
    ├─ if entry.cancelled:                # P1-3: 跳过已取消条目
    │   ├─ _semaphore.release()
    │   └─ continue
    ├─ task = create_task(_run_workflow_with_release(entry))
    └─ _running_tasks.add(task)

_run_workflow_with_release(entry):
    try:
        await _run_workflow(entry.workflow_id)  # 复用现有逻辑
    finally:
        _semaphore.release()             # P0-2: 强制释放防泄漏
        _running_tasks.discard(current_task)
        if _config_dirty:                # P1-2: 延迟重建 Semaphore
            _rebuild_semaphore()
```

**重启恢复流程：**

```
start():
    ├─ 从 DB 查 status=queued 的 workflow
    │   按 priority DESC, started_at ASC 排序（P1-4）
    ├─ 依次创建 QueueEntry 入队
    ├─ 初始化 _semaphore = Semaphore(max_concurrent)
    ├─ create_task(_queue_worker)
    └─ 注册 cron 任务
```

**配置热生效流程：**

```
update_queue_config(mode, max_concurrent):
    ├─ 写 DB: queue_config 表
    ├─ _execution_mode = mode
    ├─ _max_concurrent = max_concurrent
    └─ _config_dirty = True              # 标记待生效，不立即重建

_rebuild_semaphore():
    ├─ _semaphore = Semaphore(_max_concurrent)
    └─ _config_dirty = False
```

#### 3.2.5 移除项

| 移除内容 | 原位置 | 理由 |
| --- | --- | --- |
| `acquire_lock("workflow:lock")` | `_run_workflow` 第 279-287 行 | Semaphore 替代并发控制 |
| `release_lock("workflow:lock")` | `_run_workflow` 第 379-384 行 finally | 同上 |
| `WorkflowConflictError` 抛出 | `trigger_workflow` | 改为入队，不拒绝并发 |
| `cache.set("workflow:current", wf_id)` | `_run_workflow` | 改为 `_running_tasks` 集合记录所有执行中任务 |

#### 3.2.6 保留不变

- `_run_workflow` 内部 6 步串行编排逻辑（crawl → rewrite → tts → stitch → review → publish）
- `_run_step` 重试机制（3 次，5s/10s 退避）
- EventBus 事件发布
- NotifierHub 告警
- workflow_id 生成（日期 + 当日序号，DB 校正）
- 备播机制（改造为按频道分组，见 3.2.7）

### 3.3 队列查询服务（QueueService）

#### 3.3.1 职责

提供队列统计、任务列表、取消/改优先级/重试操作。

#### 3.3.2 类设计

```python
class QueueService:
    """队列查询与操作服务。"""

    @staticmethod
    async def get_queue_stats() -> dict:
        """各状态任务数统计：{queued: N, running: N, success: N, failed: N}"""

    @staticmethod
    async def list_queue_tasks(
        status: str | None = None,
        channel_id: int | None = None,
        priority: int | None = None,

    @staticmethod
    async def cancel_task(workflow_id: str) -> None:
        """取消排队中任务。status=queued → cancelled，标记 _entry_map 条目 cancelled=True。"""

    @staticmethod
    async def update_priority(workflow_id: str, priority: int) -> None:
        """修改优先级（仅 queued 状态）。旧条目标记 cancelled，新条目重新入队。"""

    @staticmethod
    async def retry_task(workflow_id: str) -> str:
        """重试失败任务。status=failed → queued，重新入队，返回新 workflow_id。"""

    @staticmethod
    async def get_queue_config() -> dict:
        """获取执行模式配置。"""

    @staticmethod
    async def update_queue_config(mode: str, max_concurrent: int) -> None:
        """更新配置并标记 _config_dirty（延迟生效）。"""
```

#### 3.3.3 条目取消/改优先级机制

由于 `asyncio.PriorityQueue` 不支持随机删除，采用标记法：

```
cancel_task(workflow_id):
    ├─ DB: UPDATE workflow SET status='cancelled' WHERE id=? AND status='queued'
    ├─ entry = _entry_map.get(workflow_id)
    └─ if entry: entry.cancelled = True      # worker 出队时跳过

update_priority(workflow_id, new_priority):
    ├─ DB: UPDATE workflow SET priority=? WHERE id=? AND status='queued'
    ├─ old_entry = _entry_map.get(workflow_id)
    ├─ old_entry.cancelled = True            # 旧条目标记取消
    ├─ new_entry = QueueEntry(-new_priority, now, workflow_id, ...)
    ├─ _entry_map[workflow_id] = new_entry   # 替换映射
    └─ await _queue.put(new_entry)           # 重新入队
```

## 6. 关键流程设计

### 6.1 多频道 cron 触发流程

```
05:00 APScheduler 触发
  │
  ├─ ChannelService.list_channels(active_only=True)
  │   → [科技频道, 财经频道, 娱乐频道]
  │
  ├─ for channel in channels:
  │   ├─ scheduler.trigger_workflow(channel_id=channel.id, priority=5)
  │   │   ├─ async with _trigger_lock:
  │   │   │   ├─ 生成 workflow_id (wf-20260711-0001, 0002, 0003)
  │   │   │   ├─ DB: INSERT workflow(status=queued, channel_id, priority=5)
  │   │   │   └─ PriorityQueue.put(QueueEntry(-5, now, wf_id, channel_id))
  │   │   └─ 返回 workflow_id
  │
  └─ _queue_worker 消费：
      ├─ serial 模式：依次执行 wf-0001 → wf-0002 → wf-0003
      └─ parallel 模式(max=2)：同时执行 wf-0001 + wf-0002，wf-0003 等待
```

### 6.2 任务取消流程

```
前端点击"取消" → ElMessageBox.confirm
  │
  ├─ POST /admin/api/v1/queue/tasks/{id}/cancel
  ├─ QueueService.cancel_task(id)
  │   ├─ DB: UPDATE workflow SET status='cancelled' WHERE id=? AND status='queued'
  │   ├─ entry = scheduler._entry_map.get(id)
  │   └─ if entry: entry.cancelled = True
  │
  └─ _queue_worker 出队时检查 entry.cancelled：
      ├─ True → 跳过，release semaphore，continue
      └─ False → 正常执行
```

### 6.3 配置热生效流程

```
前端修改配置 → PUT /admin/api/v1/queue/config
  │
  ├─ QueueService.update_queue_config("parallel", 3)
  │   ├─ DB: UPDATE queue_config SET execution_mode='parallel', max_concurrent=3
  │   ├─ scheduler._execution_mode = "parallel"
  │   ├─ scheduler._max_concurrent = 3
  │   └─ scheduler._config_dirty = True        # 标记待生效
  │
  └─ 当前执行任务完成后：
      ├─ _run_workflow_with_release finally:
      │   ├─ _semaphore.release()
      │   └─ if _config_dirty:
      │       ├─ _semaphore = Semaphore(3)     # 重建
      │       └─ _config_dirty = False
      └─ 下次 acquire 使用新 Semaphore(3)
```

### 6.4 重启恢复流程

```
应用启动 → scheduler.start()
  │
  ├─ 从 DB 查 status=queued 的 workflow
  │   SELECT * FROM workflow WHERE status='queued'
  │   ORDER BY priority DESC, started_at ASC
  │
  ├─ for wf in workflows:
  │   ├─ entry = QueueEntry(-wf.priority, wf.started_at.timestamp(), wf.id, ...)
  │   ├─ _entry_map[wf.id] = entry
  │   └─ _queue.put(entry)
  │
  ├─ 读 queue_config 表初始化 _execution_mode + _max_concurrent
  ├─ _semaphore = Semaphore(_max_concurrent)
  └─ create_task(_queue_worker)
```

## 7. 非功能性设计

### 7.1 并发安全

| 设计点 | 措施 |
| --- | --- |
| workflow_id 冲突 | `_trigger_lock` 串行化入队操作 |
| Semaphore 泄漏 | `_run_workflow_with_release` 的 try/finally 强制释放 |
| PriorityQueue 竞态 | asyncio 单线程事件循环，无需额外锁 |
| 配置重建竞态 | 延迟生效策略，仅在任务完成回调中重建 |
| 条目取消竞态 | `_entry_map` 字典读写均在事件循环中，无竞态 |

### 7.2 可靠性

| 设计点 | 措施 |
| --- | --- |
| 重启不丢失 | queued 状态持久化在 SQLite，启动时重建 PriorityQueue |
| 条目移除 | 标记法（cancelled=True），worker 出队时跳过 |
| 删除排队任务 | batch_delete 检查 queued 状态拒绝直接删除 |
| 备播多频道 | 按 channel_id 分组查询，避免 MultipleResultsFound |

### 7.3 性能

| 设计点 | 指标 |
| --- | --- |
| 入队延迟 | ≤ 100ms（DB 写入 + PriorityQueue put，串行化锁不影响） |
| 队列页加载 | ≤ 1s |
| 任务列表查询 | ≤ 200ms（含索引 idx_workflow_channel, idx_workflow_priority） |
| 配置热生效 | ≤ 下一个任务完成周期（延迟生效策略） |

### 7.4 兼容性

| 设计点 | 措施 |
| --- | --- |
| 历史数据 | channel_id nullable，历史 workflow 无频道不受影响 |
| 现有接口 | `/workflows/trigger` 不传 channel_id 时默认 NULL，priority 默认 5 |
| 架构 | 不引入新中间件，仍用 SQLite + TTLCache + 单机 exe |
| CHECK 约束 | 移除 DB 层 CHECK，ORM 枚举约束足够 |

## 8. 错误处理设计

### 8.1 队列操作错误

| 错误场景 | 处理方式 |
| --- | --- |
| 取消非 queued 状态任务 | 返回 400 + "仅排队中任务可取消" |
| 改优先级非 queued 状态任务 | 返回 400 + "仅排队中任务可修改优先级" |
| 重试非 failed 状态任务 | 返回 400 + "仅失败任务可重试" |
| 频道名称重复 | 返回 400 + "频道名称已存在" |
| 频道不存在 | 返回 404 |
| 并发数超出范围 | 返回 422 + "并发数范围 1-5" |

### 8.2 调度异常

| 错误场景 | 处理方式 |
| --- | --- |
| _run_workflow 异常 | 现有 try/except 捕获，status=failed，finally 释放 Semaphore |
| _queue_worker 异常 | catch + log，不退出循环，继续消费下一个 |
| Semaphore 重建异常 | catch + log，保留旧 Semaphore，下次重试 |
| DB 写入失败 | 抛异常给调用方，不入队 |

### 8.3 前端错误处理

| 错误场景 | 处理方式 |
| --- | --- |
| API 请求失败 | ElMessage.error 提示，不崩溃页面 |
| 轮询失败 | 静默重试，下次轮询继续 |
| 权限不足 | 401 跳转登录，403 提示无权限 |
