## 1. 引言

### 1.1 编写目的

本说明书在《概要设计说明书 V1.6》基础上，将架构与模块设计细化到可直接编码的程度。文档目标：

- 给出**可直接执行的 DDL 脚本**（SQLite 方言），包含字段类型、索引、外键、CHECK 约束；
- 给出**完整的 OpenAPI 接口定义**（B 端单机 + C 端云函数 SCF），可直接导入 Swagger/Postman；
- 给出**模块级伪代码**，明确类/函数签名、调用关系、关键分支；
- 给出**关键算法实现**（SimHash、热度公式、敏感词过滤、重试策略）；
- 给出**可复制的配置文件与部署文件**（YAML、PyInstaller spec、Inno Setup、PowerShell 脚本）。

读者读完后应能够：直接搭建开发环境、按章节实现对应模块、无需再向架构师确认细节即可编码。

### 1.2 项目背景

详见《需求规格说明书》第 1.2 节与《概要设计说明书》第 1.2 节。本项目核心是一套**全自动 AI 内容生产工作流**：每日凌晨爬取前一日全网资讯 → LLM 改写为可播报稿 → 阿里云 TTS API 语音合成 → FFmpeg 拼接三段式广告 → 人工审核后 07:00 发布到微信小程序。系统采用**混合架构**：

- **生产端**：单机 Windows exe（FastAPI + APScheduler + 内部模块函数调用），SQLite 数据库 + 内存缓存（cachetools.TTLCache），无外部中间件依赖；
- **消费端**：腾讯云函数 SCF（5 个函数承载全部 C 端 API），COS 对象存储（音频/元数据/黑名单），CDN 加速；
- **数据层**：14 张 SQLite 表（11 业务 + 3 辅助：jwt_blacklist、crawler_dedup、play_progress）。

**与 V1.0 的核心差异**（详见变更记录 13.10）：
1. 数据库 MySQL → SQLite（移除 aiomysql，改用 aiosqlite + SQLAlchemy ORM）；
2. 缓存 Redis → 内存 TTLCache（移除 redis-py，改用 cachetools）；
3. 部署 Docker 4 容器 → 单机 exe（PyInstaller + Inno Setup）+ 云函数 SCF；
4. 反向代理 Nginx → 移除（单机直接暴露 FastAPI 端口）；
5. 新增发布服务模块、云函数 SCF 模块；
6. JWT 黑名单 Redis → COS 对象 `jwt_blacklist/{jti}.json`（云函数启动时加载到内存缓存，TTL 5 分钟）。

#### 1.4.4 接口响应规范

所有 HTTP 接口统一响应格式（继承 HLD 6.1）：

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

错误响应：

```json
{
  "code": 40001,
  "message": "参数错误：date 不能为空",
  "data": null
}
```

`code = 0` 表示成功；非 0 表示错误，错误码定义见 LLD 13.1。

#### 1.4.5 时间与时区约定

- 数据库时间字段统一 `TEXT`（ISO 8601 字符串），应用层写入 UTC 时间，显示时按 `Asia/Shanghai` 转换；
- APScheduler Cron 表达式按 `Asia/Shanghai` 时区配置（如 `05:00` 触发即北京时间凌晨 5 点）；
- API 入参/出参时间字段统一 ISO 8601 字符串（如 `2026-07-07T05:00:00+08:00`）；
- SQLite 不支持原生 DATETIME，全部时间字段使用 TEXT 存储 ISO 8601 字符串，由 ORM 层负责序列化/反序列化。

## 2. 完整 DDL 脚本

> 本章给出 14 张表（11 业务 + 3 辅助）的完整 DDL，可直接在 SQLite 3.40+ 执行。SQLite 方言改造规则：
>
> - 主键统一 `INTEGER PRIMARY KEY AUTOINCREMENT`（SQLite 自增长）；
> - `ENUM(...)` 改为 `TEXT + CHECK` 约束；
> - `JSON` 改为 `TEXT`（应用层 JSON 序列化）；
> - `DATETIME / DATE / TIMESTAMP` 改为 `TEXT`（ISO 8601 字符串）；
> - `TINYINT / INT UNSIGNED / BIGINT UNSIGNED` 统一为 `INTEGER`；
> - `DECIMAL(3,2)` 改为 `REAL`；
> - 行内 `COMMENT` 移除（SQLite 不支持，改用 `--` 注释）；
> - `ON UPDATE CURRENT_TIMESTAMP` 移除（由应用层 ORM 或触发器维护 `updated_at`）；
> - `ENGINE/CHARSET` 子句移除（SQLite 单文件库）；
> - 分区不适用，改为按月归档（见 2.15）；
> - 启用 `PRAGMA foreign_keys = ON` 与 `PRAGMA journal_mode = WAL`。

### 2.1 数据库初始化

```sql
-- 文件位置：%APPDATA%/20News/data/news.db（生产）或 ./data/news.db（开发）
-- 由 app/launcher.py 启动时自动创建并执行下述建表脚本
-- 通过 SQLAlchemy create_all() 或本 DDL 脚本初始化

PRAGMA foreign_keys = ON;        -- SQLite 默认关闭外键，必须显式开启
PRAGMA journal_mode = WAL;       -- Write-Ahead Logging，提升并发读性能
PRAGMA synchronous = NORMAL;     -- WAL 模式下的推荐同步级别
PRAGMA encoding = "UTF-8";       -- 字符集统一 UTF-8
PRAGMA busy_timeout = 5000;      -- 写锁等待 5 秒，避免 SQLITE_BUSY
```

> **为什么不用 MySQL**：单机 exe 部署需零外部依赖，SQLite 嵌入式数据库无需安装服务、无端口、无账号管理，与 PyInstaller 打包完美兼容。WAL 模式下并发读 + 单写足以支撑本项目 QPS（详见 HLD 7.1）。

### 2.14 V1.2 新增辅助表

#### 2.14.1 jwt_blacklist 表（B 端 JWT 黑名单 - 单机端备用）

```sql
-- 用途：B 端单机应用 JWT 登出黑名单（本地 SQLite 备用，主存于 COS 对象）
-- C 端鉴权由云函数 SCF 处理，黑名单存于 COS 对象 jwt_blacklist/{jti}.json
CREATE TABLE IF NOT EXISTS jwt_blacklist (
  jti         TEXT    PRIMARY KEY,                          -- JWT 唯一标识
  user_type   TEXT    NOT NULL
              CHECK (user_type IN ('user','admin')),        -- C 端 / B 端
  user_id     INTEGER,                                      -- 关联用户 ID
  expires_at  TEXT    NOT NULL,                             -- JWT 原始过期时间（到期后可清理）
  created_at  TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))
);
CREATE INDEX IF NOT EXISTS idx_jwt_blacklist_expires_at ON jwt_blacklist(expires_at);
```

> **为什么双写 COS + SQLite**：C 端云函数读 COS 黑名单（共享访问），B 端单机读 SQLite 黑名单（本地快速访问）。登出时由 B 端单机写本地 SQLite，C 端登出由云函数写 COS 对象。两者通过发布服务异步同步（容许短暂不一致）。

#### 2.14.2 crawler_dedup 表（爬虫去重）

```sql
-- 用途：替代 Redis Set 的 URL 与 SimHash 去重
-- 7 天滑动窗口：由定时任务每日清理 7 天前的记录
CREATE TABLE IF NOT EXISTS crawler_dedup (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  dedup_type  TEXT    NOT NULL
              CHECK (dedup_type IN ('url','simhash')),      -- 去重类型
  category    TEXT,                                         -- simhash 类型时按品类分桶，url 类型为 NULL
  value       TEXT    NOT NULL,                             -- URL 原文 或 SimHash 指纹（十六进制）
  created_at  TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))
);
CREATE INDEX IF NOT EXISTS idx_crawler_dedup_type_value    ON crawler_dedup(dedup_type, value);
CREATE INDEX IF NOT EXISTS idx_crawler_dedup_type_category ON crawler_dedup(dedup_type, category);
CREATE INDEX IF NOT EXISTS idx_crawler_dedup_created_at    ON crawler_dedup(created_at);
```

> **为什么不用 Bloom Filter**：MVP 单日 URL 量 50-100，7 天累积 < 1000，SQLite 索引查询性能足够（< 1ms）。Bloom Filter 有假阳性，去重场景要求精确，且引入额外依赖。

#### 2.14.3 play_progress 表（播放进度 - 单机端备用）

```sql
-- 用途：替代 Redis Hash 的播放进度存储（本地备用）
-- C 端进度主存于 COS 对象 play_progress/{user_id}/{episode_id}.json（云函数读写）
-- 此表为单机端备用：B 端运营查看用户进度时使用
-- 每用户每节目仅一条记录（UNIQUE 约束）
CREATE TABLE IF NOT EXISTS play_progress (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id      INTEGER NOT NULL,
  episode_id   INTEGER NOT NULL,
  position     INTEGER NOT NULL DEFAULT 0,                  -- 当前播放位置（秒）
  duration     INTEGER NOT NULL DEFAULT 0,                  -- 节目总时长（秒）
  completed    INTEGER NOT NULL DEFAULT 0
               CHECK (completed IN (0,1)),                  -- 1 完播

  UNIQUE (user_id, episode_id),
  FOREIGN KEY (user_id) REFERENCES user(id)
    ON DELETE CASCADE ON UPDATE CASCADE,
  FOREIGN KEY (episode_id) REFERENCES episode(id)
```

> **play_log vs play_progress 区别**：
> - `play_log`：播放日志（统计用），每条记录一次播放会话的上报，可有多条；
> - `play_progress`：播放进度（断点续播用），每用户每节目仅一条记录，C 端走 COS 为主，此表为单机端备用。

### 2.16 索引与归档策略

**SQLite 不支持分区**，play_log 表数据量增长最快，采用按月归档策略：

```sql
-- 每月 1 号由 APScheduler 触发归档脚本（scripts/backup.ps1）
-- 1. 将 3 个月前的 play_log 数据导出到归档文件
--    ATTACH DATABASE 'data/backup/play_log_202607.db' AS archive;
--    CREATE TABLE archive.play_log AS SELECT * FROM play_log
--      WHERE played_at < '2026-08-01';
-- 2. 删除已归档数据
--    DELETE FROM play_log WHERE played_at < '2026-08-01';
-- 3. VACUUM 回收空间
--    VACUUM;
```

**索引补充说明**：

| 表 | 索引 | 用途 |
| --- | --- | --- |
| play_log | idx_play_log_played_at | 按时间范围查询日志（统计） |

**updated_at 自动维护**（SQLite 无 ON UPDATE 触发器，使用 TRIGGER）：

```sql
-- 为所有含 updated_at 字段的表创建更新触发器
CREATE TRIGGER IF NOT EXISTS trg_user_updated_at
AFTER UPDATE ON user FOR EACH ROW
BEGIN
  UPDATE user SET updated_at = strftime('%Y-%m-%dT%H:%M:%fZ','now') WHERE id = OLD.id;
END;

-- 同理为 admin_user, script, episode, play_progress 等表创建对应触发器
-- 实际编码中由 SQLAlchemy ORM 事件监听统一处理，此处 DDL 仅作兜底
```

## 3. 缓存与 COS 对象设计

> 本章给出 V1.2 架构下的缓存层（TTLCache 内存缓存）与 COS 对象存储设计，可直接指导编码。
>
> **核心变更（V1.0 → V1.2）**：
> - Redis 缓存 → `cachetools.TTLCache` 内存缓存（单机进程内）
> - Redis 黑名单 → COS 对象 `jwt_blacklist/{jti}.json`（C 端共享） + SQLite `jwt_blacklist` 表（B 端本地）
> - Redis 播放进度 → COS 对象 `play_progress/{user_id}/{episode_id}.json`（C 端） + SQLite `play_progress` 表（B 端备用）
> - Redis 去重 → SQLite `crawler_dedup` 表（见 2.14.2）
> - Redis 限流 → TTLCache 滑动窗口
> - Redis 日志队列 → COS 对象 `playlogs/{yyyymmdd}/{session_id}.json` + APScheduler 批量聚合
> - Redis Bitmap DAU → SQLite `play_log` 聚合查询（COUNT DISTINCT user_id WHERE DATE(played_at)=?）

### 3.1 内存缓存设计（TTLCache）

#### 3.1.1 命名规范

**统一格式**：`{namespace}:{subnamespace}:{id}[:{sub_id}]`

- 全小写，冒号分隔；
- namespace 表示业务域（episode/script/ad/workflow/rate_limit）；
- 变长 ID 用具体值替换；
- 避免特殊字符与空格。

#### 3.1.2 缓存清单总览

| 缓存键模式 | 类型 | 用途 | TTL | 写入方 | 读取方 |
| --- | --- | --- | --- | --- | --- |
| `episode:today` | dict(JSON) | 今日节目元数据缓存 | 1 小时 | 内容服务（发布服务） | B 端 episodes 接口 |
| `episode:list:page:{n}` | dict(JSON) | 历史列表分页缓存 | 10 分钟 | 内容服务 | B 端 episodes 接口 |
| `episode:detail:{id}` | dict(JSON) | 节目详情缓存 | 30 分钟 | 内容服务 | B 端 episodes 接口 |
| `script:detail:{id}` | dict(JSON) | 稿件详情缓存（懒加载） | 30 分钟 | 内容服务 | B 端 episodes/script 接口 |
| `ad:placement:{date}` | dict(JSON) | 当日广告投放缓存 | 25 小时 | 广告服务 | 拼接模块、广告服务 |
| `workflow:lock` | str | 工作流触发互斥锁 | 30 分钟 | 工作流调度服务 | 工作流调度服务 |

> **C 端缓存去哪了**：V1.2 架构下，C 端接口由云函数 SCF 承载，直接从 COS 读取 `episodes/index.json` 和 `episodes/{date}/meta.json`，**不再走单机内存缓存**。单机内存缓存仅服务于 B 端运营后台接口（本地访问，低 QPS）。

### 3.2 CacheManager 封装

```python
# app/cache/manager.py
from cachetools import TTLCache
from threading import Lock
from typing import Any, Optional

class CacheManager:
    """TTLCache 单例封装

    为什么不用 Redis：
    1. 单机部署无外部中间件依赖，降低用户安装门槛；
    2. B 端运营后台 QPS 极低（< 10），内存缓存足够；
    3. PyInstaller 打包时无需 bundle redis-py 依赖。

    为什么用单例模式：
    TTLCache 非线程安全，通过全局单例 + Lock 保证并发安全。
    FastAPI 异步框架下，事件循环单线程，但 APScheduler 线程池会并发访问。
    """

    _instance = None
    _lock = Lock()

    def __new__(cls):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
                    cls._instance._cache = TTLCache(maxsize=1000, ttl=3600)
                    cls._instance._op_lock = Lock()
        return cls._instance

    def get(self, key: str) -> Optional[Any]:
        with self._op_lock:
            return self._cache.get(key)

    def set(self, key: str, value: Any, ttl: Optional[int] = None) -> None:
        with self._op_lock:
            self._cache[key] = value
            # cachetools 不支持单 key 设置独立 TTL，需重建缓存或使用 expire_time
            # 实际编码中通过新建 TTLCache 实例实现独立 TTL（见 3.3.1）

    def delete(self, key: str) -> None:
        with self._op_lock:
            self._cache.pop(key, None)

    def delete_pattern(self, pattern: str) -> int:
        """通配符删除（本地实现，无 SCAN 阻塞问题）"""
        import fnmatch
        with self._op_lock:
            keys_to_delete = [k for k in self._cache.keys() if fnmatch.fnmatch(k, pattern)]
            for k in keys_to_delete:
                self._cache.pop(k, None)
            return len(keys_to_delete)

cache = CacheManager()
```

> **TTLCache 局限性**：`cachetools.TTLCache` 不支持单 key 独立 TTL（全局 TTL 统一）。实际编码中：
> - 对需独立 TTL 的缓存（如 `blacklist:admin:{jti}` 剩余有效期），用独立 `TTLCache` 实例或记录 `expire_at` 时间戳；
> - 对 `rate_limit:api:{ip}` 滑动窗口，使用 `cachetools.TTLCache(maxsize=10000, ttl=60)` 简化实现。

#### 3.3.3 `workflow:lock` — 工作流互斥锁

```python
# app/services/workflow_scheduler.py
WORKFLOW_LOCK = "workflow:lock"

async def acquire_workflow_lock(workflow_id: str) -> bool:
    """抢锁，30 分钟自动释放（防死锁）

    为什么需要互斥锁：
    APScheduler 可能因系统时间跳变重复触发，运营也可能在 05:00 误点手动触发。
    锁保证同一时刻只有一个工作流运行。
    """
    existing = cache.get(WORKFLOW_LOCK)
    if existing:
        logger.warning(f"工作流锁已被 {existing} 持有，拒绝重复触发")
        return False

    cache.set(WORKFLOW_LOCK, workflow_id)
    # 注意：进程崩溃会导致锁泄漏，需配合 workflow 表 status='running' 状态做兜底校验
    # 启动时检查：若 workflow 表有 running 记录但 last_heartbeat > 30 分钟，强制释放锁
    return True

async def release_workflow_lock():
    cache.delete(WORKFLOW_LOCK)
```

> **与 Redis SET NX 的差异**：TTLCache 的 `set` 非原子操作，但单机进程内 + Python GIL 保证并发安全。APScheduler 线程池并发通过 `CacheManager._op_lock` 串行化。

#### 3.3.4 `rate_limit:api:{user_ip}` — 接口限流

```python
# app/middleware/rate_limit.py
from cachetools import TTLCache
from fastapi import Request, Response
from fastapi.responses import JSONResponse

# 独立 TTLCache，1 分钟窗口，最多 10000 个 IP
rate_limit_cache = TTLCache(maxsize=10000, ttl=60)

RATE_LIMIT_THRESHOLD = 60  # 单 IP 每分钟 60 次

async def rate_limit_middleware(request: Request, call_next):
    # 运营后台 IP 白名单豁免
    client_ip = request.client.host
    if client_ip in settings.RATE_LIMIT_WHITELIST:
        return await call_next(request)

    count = rate_limit_cache.get(client_ip, 0) + 1
    rate_limit_cache[client_ip] = count

    if count > RATE_LIMIT_THRESHOLD:
        return JSONResponse(
            status_code=429,
            content={"code": 42901, "message": "请求过于频繁，请稍后再试", "data": None},
            headers={"Retry-After": "60"},
        )

    return await call_next(request)
```

**限流策略**：单 IP 每分钟 60 次，超限返回 429；运营后台 IP 白名单可豁免。

#### 3.3.5 `blacklist:admin:{jti}` — B 端 JWT 黑名单（本地）

```python
# app/services/review_service.py（登出时调用）
ADMIN_BLACKLIST_PREFIX = "blacklist:admin"

async def logout_admin(jti: str, expires_at: datetime):
    """B 端登出：写入 SQLite jwt_blacklist 表 + 内存缓存"""
    # 1. 持久化到 SQLite（单机重启后仍有效）
    await jwt_blacklist_repo.create(
        jti=jti, user_type='admin', expires_at=expires_at
    )
    # 2. 写入内存缓存（加速校验）
    remaining_ttl = (expires_at - datetime.utcnow()).total_seconds()
    if remaining_ttl > 0:
        cache.set(f"{ADMIN_BLACKLIST_PREFIX}:{jti}", True)

# app/deps.py（鉴权中间件）
async def verify_admin_token(request: Request):
    token = extract_bearer_token(request)
    payload = jwt_decode(token)  # 1. 本地 JWT 验签（O(1)）

    # 2. 查黑名单：先查内存缓存，未命中查 SQLite
    jti = payload['jti']
    if cache.get(f"{ADMIN_BLACKLIST_PREFIX}:{jti}"):
        raise HTTPException(401, "token 已失效（已登出）")

    if await jwt_blacklist_repo.exists(jti):
        cache.set(f"{ADMIN_BLACKLIST_PREFIX}:{jti}", True)
        raise HTTPException(401, "token 已失效（已登出）")

    request.state.admin = payload
```

**为什么用 JWT + 黑名单**：JWT 本地验签性能优（O(1)），仅登出/强制下线时写黑名单。避免"JWT + 全量 session 双写"的双重真相反模式。

```python
# scf/common/blacklist_cache.py（云函数端）
from cos_python_sdk_v5 import CosS3Client
from cachetools import TTLCache

# 云函数启动时加载黑名单到内存，TTL 5 分钟
_blacklist_cache = TTLCache(maxsize=10000, ttl=300)
_last_load_time = None

def load_blacklist_from_cos(cos_client, bucket):
    """从 COS 加载所有未过期黑名单到内存

    为什么 TTL 5 分钟：
    云函数冷启动时全量加载 COS 黑名单目录，5 分钟后自动失效重建。
    新登出的 jti 最多 5 分钟后生效，可接受。
    """
    global _last_load_time
    objects = cos_client.list_objects(Bucket=bucket, Prefix='jwt_blacklist/')
    for obj in objects.get('Contents', []):
        jti = obj['Key'].split('/')[-1].replace('.json', '')
        _blacklist_cache[jti] = True
    _last_load_time = datetime.utcnow()

def is_blacklisted(jti: str, cos_client, bucket) -> bool:
    """检查 jti 是否在黑名单"""
    # 1. 先查内存缓存
    if _blacklist_cache.get(jti):
        return True

    # 2. 缓存未命中，查 COS 对象（兜底，处理刚登出但缓存未刷新的情况）
    try:
        cos_client.head_object(Bucket=bucket, Key=f'jwt_blacklist/{jti}.json')
        _blacklist_cache[jti] = True
        return True
    except CosServiceError as e:
        if e.get_status_code() == 404:
            return False
        raise
```

### 3.6 缓存失效策略

| 场景 | 策略 | 实现 |
| --- | --- | --- |
| 节目发布 | 主动失效 | `cache.delete("episode:today"); cache.delete_pattern("episode:*")` + 刷新 COS `episodes/index.json` |
| 稿件审核通过 | 主动失效 | `cache.delete(f"script:detail:{id}")` |
| 广告投放修改 | 主动失效 | `cache.delete(f"ad:placement:{today}")` |
| 工作流重新触发 | 主动失效 | 同节目发布 |
| 缓存命中过期 | 被动失效 | TTLCache 自动过期 |
| 缓存数据错误 | 紧急失效 | 运营后台"刷新缓存"接口，调用 `cache.clear()` |

> **通配符删除优势**：TTLCache 本地实现通配符删除无阻塞风险，无需 Redis 的 SCAN 操作。

```python
async def _run_workflow(self, workflow_id: str, episode_date: date) -> None:
    """工作流主流程：6 步串行执行"""
    # 步骤定义（顺序、对应模块函数）
    STEPS = [
        ("crawl",   1, crawler.run),
        ("rewrite", 2, llm.rewrite),
        ("tts",     3, tts.synthesize),
        ("stitch",  4, stitch.concat),
        ("review",  5, self._create_review),       # 内置：创建 review 记录
        ("publish", 6, self.publish),               # 仅审核通过后执行
    ]

    try:
        # 抢内存互斥锁，防止并发触发（V1.2：TTLCache 替代 Redis SET NX）
        existing = self.cache.get("workflow:lock")
        if existing:
            raise WorkflowConflictError(f"已有工作流 {existing} 在运行")
        self.cache.set("workflow:lock", workflow_id)

        await self._update_workflow_status(workflow_id, "running")

        context = {"workflow_id": workflow_id, "episode_date": episode_date}

        # 前 4 步：crawl → rewrite → tts → stitch
        for step_name, seq, func in STEPS[:4]:
            await self._run_step(workflow_id, step_name, seq, func, context)

        # 第 5 步：创建审核记录（内部方法，不调用外部模块）
        await self._run_step(workflow_id, "review", 5, self._create_review, context)

        # 第 6 步 publish 由审核通过后异步触发，不在主流程内串行执行
        # 主流程到 review 创建即结束，状态置 success
        await self._update_workflow_status(workflow_id, "success")

    except StepFailedError as e:
        # 某步重试耗尽仍失败
        await self._update_workflow_status(workflow_id, "failed", error=str(e))
        await self._alert_operators(f"工作流 {workflow_id} 失败于步骤 {e.step_name}: {e}")
        # 不立即启用备播，等到 06:30 由 _check_backup 统一处理
    finally:
        self.cache.delete("workflow:lock")


async def _run_step(self, workflow_id, step_name, seq, func, context):
    """执行单步：记录状态、调用函数、失败重试 3 次"""
    step_record = await self._create_step_record(workflow_id, step_name, seq)
    await self._update_step_status(step_record.id, "running")

    last_error = None
    for attempt in range(3):  # 最多 3 次（含首次）
        try:
            result = await func(context)            # 调用工作流模块函数
            await self._update_step_status(
                step_record.id, "success",
                result=result, retry_count=attempt,
                duration_ms=int((time.time() - step_record.started_at.timestamp()) * 1000)
            )
            context.update(result or {})            # 将本步产出合并到上下文供后续步骤使用
            return
        except Exception as e:
            last_error = e
            await self._update_step_status(step_record.id, "retrying", retry_count=attempt + 1)
            if attempt < 2:
                await asyncio.sleep(5 * (attempt + 1))   # 指数退避 5s/10s

    # 3 次均失败
    await self._update_step_status(step_record.id, "failed", error=str(last_error))
    raise StepFailedError(step_name, last_error)
```

```python
async def _check_backup(self) -> None:
    """06:30 检查今日 episode 是否已发布；未发布则启用备播"""
    today = date.today()
    episode = await self.db.execute(
        select(Episode).where(Episode.date == today, Episode.status == "published")
    )
    if episode:
        return  # 已正常发布，无需备播

    # 查询前一日已发布节目
    yesterday = today - timedelta(days=1)
    prev = await self.db.execute(
        select(Episode).where(Episode.date == yesterday, Episode.status == "published")
    )
    if not prev:
        await self._alert_operators("前一日节目也不存在，无法备播！需人工介入")
        return

    # 创建备播 episode
    backup = Episode(
        date=today,
        title=f"{today.month}月{today.day}日 · 今日要闻（备播）",
        duration=prev.duration,
        audio_url=prev.audio_url,                    # 复用前一日音频
        cover_url=prev.cover_url,
        is_backup=True,
        status="published",
        published_at=datetime.now(),
    )
    self.db.add(backup)
    await self.db.commit()

    # 刷新缓存（V1.2：TTLCache 内存缓存 + COS 对象）
    self.cache.delete("episode:today")
    self.cache.delete_pattern("episode:*")
    await self._alert_operators(f"已启用备播（复用 {yesterday} 节目音频），请事后排查原因")
```

```python
async def run(context: dict) -> dict:
    workflow_id = context["workflow_id"]
    sources = _load_sources()                       # 从 rss.yaml + lists.yaml 加载配置
    all_materials = []

    # 并发爬取所有源（每源独立容错，单源失败不影响其他源）
    tasks = [_crawl_one_source(src, workflow_id) for src in sources]
    results = await asyncio.gather(*tasks, return_exceptions=True)

    for src, result in zip(sources, results):
        if isinstance(result, Exception):
            logger.warning(f"源 {src['name']} 爬取失败: {result}")
            continue
        all_materials.extend(result)

    # 去重（URL + SimHash，V1.2：基于 SQLite crawler_dedup 表）
    deduped = await _dedup(all_materials, workflow_id)

    # 落库（V1.2：SQLite，INSERT OR IGNORE 容错）
    await _save_to_sqlite(deduped)

    return {"material_count": len(deduped), "materials": deduped[:5]}  # 上下文只传前 5 条预览


async def _crawl_one_source(src: dict, workflow_id: str) -> list[dict]:
    """爬取单个源（V1.2：httpx + feedparser/selectolax，移除 Scrapy/Playwright）"""
    if src["type"] == "rss":
        return await rss_spider.crawl(src, workflow_id)      # httpx + feedparser
    elif src["type"] == "list":
        return await list_spider.crawl(src, workflow_id)     # httpx + selectolax
    else:
        raise ValueError(f"未知源类型: {src['type']}")


async def _dedup(materials: list[dict], workflow_id: str) -> list[dict]:
    """URL 去重 + SimHash 近似去重（V1.2：SQLite crawler_dedup 表替代 Redis Set）"""
    result = []
    for m in materials:
        # URL 去重（查 SQLite crawler_dedup 表）
        if await crawler_dedup_repo.exists_by_url(m["url"]):
            continue
        # SimHash 计算 + 近似去重
        m["simhash"] = simhash.compute(m["title"])
        is_dup = False
        # 查询同品类已有指纹
        existing_hashes = await crawler_dedup_repo.get_simhash_by_category(m["category"])
        for h in existing_hashes:
            if simhash.hamming_distance(m["simhash"], h) <= 3:
                is_dup = True
                break
        if is_dup:
            continue

        # 标记已处理（写入 SQLite crawler_dedup 表）
        await crawler_dedup_repo.create_url(m["url"])
        await crawler_dedup_repo.create_simhash(m["category"], m["simhash"])
        result.append(m)

    return result


async def _save_to_sqlite(materials: list[dict]) -> None:
    """批量插入 material 表（V1.2：SQLite INSERT OR IGNORE 容错唯一 URL）"""
    async with db_session.begin():
        await db_session.execute(
            insert(Material),
            materials,
        )
```

```python
async def rewrite(context: dict) -> dict:
    workflow_id = context["workflow_id"]
    episode_date = context["episode_date"]

    # 1. 拉取当日全部素材
    materials = await _fetch_materials(episode_date)

    # 2. 选题：按品类分组，每品类选 1-2 篇热度最高
    selected = _select_top_materials(materials, top_n=6)

    # 3. 并发改写（5-6 条同时调用 LLM）
    tasks = [_rewrite_one(m) for m in selected]
    results = await asyncio.gather(*tasks, return_exceptions=True)

    # 4. 过滤失败项 + 敏感词扫描
    segments = []
    for m, r in zip(selected, results):
        if isinstance(r, Exception):
            logger.warning(f"素材 {m['id']} 改写失败: {r}")
            continue
        if sensitive_filter.contains(r["content"]):
            # 命中敏感词，重新生成一次（带约束 prompt）
            r = await _rewrite_one(m, retry_with_constraint=True)
        segments.append({**r, "seq": len(segments) + 1, "material_ids": [m["id"]]})

    if len(segments) < 3:
        raise LLMError(f"有效改写段数 {len(segments)} < 3，无法生成节目")

    # 5. 组装整稿（开场白 + 改写段 + 结尾）
    full_text, segments_with_intro = _assemble_script(segments, episode_date)

    # 6. 时长估算（210 字/分钟）
    total_words = sum(len(s["content"]) for s in segments_with_intro)
    estimated_duration = int(total_words / 210 * 60)

    # 7. 落库 script 表
    script = await _save_script(
        workflow_id=workflow_id,
        episode_date=episode_date,
        full_text=full_text,
        segments=segments_with_intro,
        total_words=total_words,
        estimated_duration=estimated_duration,
        referenced_materials=[{"title": m["title"], "url": m["url"]} for m in selected],
        categories=list({m["category"] for m in selected}),
    )

    return {"script_id": script.id, "segments": segments_with_intro, "estimated_duration": estimated_duration}


def _select_top_materials(materials: list[dict], top_n: int = 6) -> list[dict]:
    """按品类分组，每品类选 1-2 篇热度最高

    热度 = 源权威度 × 0.3 + 标题关键词热度 × 0.4 + 发布时间近度 × 0.3
    """
    by_category = defaultdict(list)
    for m in materials:
        by_category[m["category"]].append(m)

    selected = []
    for cat, items in by_category.items():
        items.sort(key=lambda m: _heat_score(m), reverse=True)
        selected.extend(items[:2])                  # 每品类最多 2 篇
        if len(selected) >= top_n:
            break
    return selected[:top_n]


def _heat_score(material: dict) -> float:
    """热度计算：源权威度 30% + 标题关键词热度 40% + 发布时间近度 30%"""
    authority = material["source_authority"]                    # 0-1
    keyword_heat = _keyword_heat(material["title"])            # 0-1
    recency = _recency_score(material["published_at"])         # 0-1，越近越高
    return authority * 0.3 + keyword_heat * 0.4 + recency * 0.3
```

```python
    if not 570 <= duration <= 630:
        raise StitchError(f"拼接后时长 {duration}s 超出 9:30-10:30 范围")

    # 7. 上传 COS
    final_url = await upload_to_cos(
        open(final_mp3, "rb").read(),
        key=f"episodes/{episode_date.strftime('%Y%m%d')}/final.mp3",
    )

def _build_full_concat_cmd(*inputs, output) -> list[str]:
    """构造 7 段拼接的 FFmpeg 命令：静音+广告+静音+主音频+静音+广告+静音"""
    cmd = ["ffmpeg"]
    for path in inputs[:-1]:
        cmd.extend(["-i", path])
    cmd.extend([
        "-filter_complex", "concat=n=7:v=0:a=1[out]",
        "-map", "[out]",
        "-acodec", "libmp3lame",
        "-b:a", "128k",
        "-ar", "44100",
        "-ac", "1",                            # 单声道
        output,
    ])
    return cmd
```

**设计目的**：V1.2 新增模块，将审核通过的节目发布到 COS 对象存储，供 C 端云函数 SCF 读取。替代 V1.1 直接写 MySQL + 本地文件的方式，实现 C 端与 B 端解耦。

```python
# app/services/publish_service.py
# 节目发布服务：审核通过后将 episode 元数据 + 音频 URL 发布到 COS
# C 端云函数 SCF 通过读取 COS 对象获取今日节目、历史列表、详情
import json
import logging
from datetime import date

from app.cache.manager import cache
from app.cos.client import cos_client
from app.models.episode import Episode

logger = logging.getLogger(__name__)

# COS 对象路径规范（详见 3.3 COS 路径规范）
EPISODES_TODAY_KEY = "episodes/today/{yyyymmdd}.json"          # 今日节目单例对象
EPISODES_HISTORY_KEY = "episodes/history/{yyyymmdd}.json"       # 历史列表分页对象
EPISODE_DETAIL_KEY = "episodes/detail/{episode_id}.json"        # 节目详情对象


async def publish_episode_to_cos(episode: Episode) -> None:
    """审核通过后发布节目到 COS（供 C 端 SCF 读取）

    发布流程：
    1. 序列化 episode + script + segments 为 JSON
    2. 写入 COS episodes/detail/{episode_id}.json（详情对象）
    3. 更新 COS episodes/today/{yyyymmdd}.json（今日节目单例）
    4. 追加 COS episodes/history/{yyyymmdd}.json（当月历史列表）
    5. 失效 B 端缓存（episodes:today:{date}、episodes:history:*）

    幂等性：同一 episode 重复发布会覆盖同名 COS 对象，不会产生重复数据。
    """
    today = date.today()
    yyyymmdd = today.strftime("%Y%m%d")

    # 1. 序列化节目详情（含稿件与分段）
    detail_payload = {
        "episode_id": episode.id,
        "title": episode.title,
        "audio_url": episode.audio_url,
        "duration": episode.duration,
        "published_at": episode.published_at.isoformat(),
        "script": _serialize_script(episode.script),
        "segments": [_serialize_segment(s) for s in episode.script.segments],
    }

    # 2. 写入详情对象
    detail_key = EPISODE_DETAIL_KEY.format(episode_id=episode.id)
    await cos_client.put_object(
        Key=detail_key,
        Body=json.dumps(detail_payload, ensure_ascii=False).encode("utf-8"),
        ContentType="application/json; charset=utf-8",
    )
    logger.info(f"[publish] 节目详情已发布: cos://{detail_key}")

    # 3. 更新今日节目单例对象
    # 今日节目为单例：每天只有一个 episode，直接覆盖写入
    today_key = EPISODES_TODAY_KEY.format(yyyymmdd=yyyymmdd)
    today_payload = {
        "episode_id": episode.id,
        "title": episode.title,
        "audio_url": episode.audio_url,
        "duration": episode.duration,
        "published_at": episode.published_at.isoformat(),
    }
    await cos_client.put_object(
        Key=today_key,
        Body=json.dumps(today_payload, ensure_ascii=False).encode("utf-8"),
        ContentType="application/json; charset=utf-8",
    )
    logger.info(f"[publish] 今日节目已发布: cos://{today_key}")

    # 4. 追加历史列表对象（当月聚合）
    await _append_to_history(episode, yyyymmdd)

    # 5. 失效 B 端缓存（运营后台今日/历史接口的 TTLCache）
    await cache.delete(f"episodes:today:{today.isoformat()}")
    await cache.delete_pattern("episodes:history:*")

    logger.info(f"[publish] 节目 {episode.id} 发布完成")


async def _append_to_history(episode: Episode, yyyymmdd: str) -> None:
    """追加到当月历史列表对象
    历史列表按月聚合，每月一个 JSON 对象，避免每日一个对象的碎片化。
    """
    year_month = yyyymmdd[:6]  # YYYYMM
    history_key = EPISODES_HISTORY_KEY.format(yyyymmdd=year_month)

    # 读取现有历史列表（首次发布时为空）
    try:
        existing = await cos_client.get_object(Key=history_key)
        history_list = json.loads(existing["Body"].read())
    except Exception:
        history_list = {"episodes": [], "month": year_month}

    # 追加新节目（去重：同一 episode_id 不重复追加）
    existing_ids = {e["episode_id"] for e in history_list["episodes"]}
    if episode.id not in existing_ids:
        history_list["episodes"].append({
            "episode_id": episode.id,
            "title": episode.title,
            "published_at": episode.published_at.isoformat(),
            "duration": episode.duration,
        })
        # 按发布时间倒序排列（最新在前）
        history_list["episodes"].sort(key=lambda e: e["published_at"], reverse=True)

    await cos_client.put_object(
        Key=history_key,
        Body=json.dumps(history_list, ensure_ascii=False).encode("utf-8"),
        ContentType="application/json; charset=utf-8",
    )


def _serialize_script(script) -> dict:
    """序列化稿件（不含分段，分段单独序列化）"""
    return {
        "script_id": script.id,
        "episode_id": script.episode_id,
        "total_duration": script.total_duration,
        "word_count": script.word_count,
    }


def _serialize_segment(segment) -> dict:
    """序列化分段（含音频 URL 与时间戳）"""
    return {
        "seq": segment.seq,
        "title": segment.title,
        "content": segment.content,
        "start_sec": segment.start_sec,
        "end_sec": segment.end_sec,
        "duration": segment.end_sec - segment.start_sec,
        "audio_url": segment.audio_url,
    }
```

> **发布服务设计要点**：
> - **C 端与 B 端解耦**：C 端 SCF 直接读 COS 对象，不访问单机 SQLite，避免跨网络访问数据库；
> - **幂等发布**：同一 episode 重复发布覆盖同名 COS 对象，无需事务回滚；
> - **今日节目单例**：每日仅一个 episode，COS 对象 `episodes/today/{yyyymmdd}.json` 为单例，SCF 一次 GET 即得；
> - **历史列表按月聚合**：避免每日一个 COS 对象导致碎片化，按月聚合减少对象数量；
> - **缓存失效**：发布后主动删除 B 端 TTLCache 中的今日/历史缓存，确保运营后台下次请求获取最新数据。

```python
class UserService:

    async def login_by_code(self, code: str) -> dict:

        流程：
        1. 用 code 调微信 code2session 换 openid
        2. 查 user 表，不存在则新建（首次登录自动注册）
        3. 生成 JWT（含 jti、user_id、openid、exp），本地签发不写缓存
        4. 返回 token + 用户基本信息
        """

        wx_resp = await self._call_wx_code2session(code)
        openid = wx_resp["openid"]
        unionid = wx_resp.get("unionid")

        # 2. 查或建用户（V1.2：SQLite，INSERT OR IGNORE）
        user = await self.db.execute(
            select(User).where(User.openid == openid)
        )
        user = user.scalar_one_or_none()
        if user is None:
            user = User(openid=openid, unionid=unionid, created_at=datetime.utcnow())
            self.db.add(user)
            await self.db.commit()
            await self.db.refresh(user)

        # 3. 更新最近活跃时间
        user.last_active_at = datetime.utcnow()
        await self.db.commit()

        # 4. 生成 JWT（无状态；jti 用于登出黑名单）
        import jwt as pyjwt
        import uuid
        jti = uuid.uuid4().hex
        payload = {
            "jti": jti,
            "user_id": user.id,
            "openid": user.openid,
            "nickname": user.nickname,
            "exp": int((datetime.utcnow() + timedelta(days=7)).timestamp()),
            "iat": int(datetime.utcnow().timestamp()),
        }
        token = pyjwt.encode(payload, settings.JWT_SECRET, algorithm="HS256")

        return {
            "token": token,
            "expires_in": 7 * 86400,
            "user": {
                "openid": user.openid,
                "nickname": user.nickname,
                "avatar": user.avatar,
            },

        B 端登出由本方法写本地 SQLite + 内存缓存。
        """
        import jwt as pyjwt
        try:
            payload = pyjwt.decode(token, settings.JWT_SECRET, algorithms=["HS256"])
        except pyjwt.PyJWTError:
            return  # token 已过期或无效，无需写黑名单

        exp = payload["exp"]

        if remaining_ttl > 0:
            # 1. 持久化到 SQLite jwt_blacklist 表
            await jwt_blacklist_repo.create(
                jti=jti, user_type='admin', expires_at=expires_at

            self.cache.set(f"blacklist:admin:{jti}", True)

        """中间件鉴权用：JWT 本地验签 + 查黑名单"""

            payload = pyjwt.decode(token, settings.JWT_SECRET, algorithms=["HS256"])
        except pyjwt.PyJWTError:

        jti = payload["jti"]

            self.cache.set(f"blacklist:admin:{jti}", True)
            return None

            "user_id": payload["user_id"],
            "openid": payload["openid"],
            "nickname": payload.get("nickname"),
        }
```

```python
        """趋势图（7d/30d/90d）

        V1.2 改造：DAU 由 Redis Bitmap BITCOUNT 多日循环改为 SQLite 按日聚合，
        一次 GROUP BY 查询返回所有日期，消除 N 次 Redis 往返。
        """
        end_date = date.today()
        start_date = end_date - timedelta(days=range_days - 1)

        # 按指标选择聚合表达式，DAU 用 COUNT(DISTINCT user_id)
        metric_expr = {
            "dau": func.count(func.distinct(PlayLog.user_id)),

            "completion_rate": func.avg(PlayLog.completed),
            "avg_listen_duration": func.avg(PlayLog.duration),
        }[metric]

            .order_by("d")

        return {"dates": [r.d for r in rows], "values": [r.v for r in rows]}
```

### 7.1 SimHash 标题去重

**模块路径**：`app/core/simhash.py`

**用途**：爬虫模块对素材标题做近似去重，避免不同源转发同一新闻重复爬取。

**算法选择理由**：相比严格 hash（一字之差判为不同），SimHash 对局部修改不敏感，相似输入产生相似指纹；通过汉明距离阈值即可判定近似重复，适合 MVP 的 50-100 条标题规模。

```python
import hashlib
import jieba

# 64 位 SimHash，对应 16 位十六进制字符串
BITS = 64


def compute(text: str) -> str:
    """计算文本的 SimHash 指纹

    流程：
    1. jieba 分词，得到词列表
    2. 每个词 MD5 哈希得 64 位整数
    3. 对每一位：该位为 1 则 +词频权重，为 0 则 -词频权重
    4. 累加后每一位 > 0 取 1，否则取 0，得 64 位指纹
    5. 转十六进制字符串返回
    """
    words = jieba.lcut(text)
    if not words:
        return "0" * 16

    # 词频统计（重复词权重更高）
    from collections import Counter
    word_weights = Counter(words)

    # 64 个位置的累加器
    accum = [0] * BITS

    for word, weight in word_weights.items():
        # MD5 取前 8 字节 = 64 位
        h = int(hashlib.md5(word.encode("utf-8")).hexdigest()[:16], 16)
        for i in range(BITS):
            if h & (1 << i):
                accum[i] += weight
            else:
                accum[i] -= weight

    # 累加结果符号化 → 64 位指纹
    fingerprint = 0
    for i in range(BITS):
        if accum[i] > 0:
            fingerprint |= (1 << i)

    # 转十六进制字符串（16 字符）
    return f"{fingerprint:016x}"


def hamming_distance(hash1: str, hash2: str) -> int:
    """计算两个 SimHash 指纹的汉明距离

    异或后统计 1 的个数即为汉明距离
    """
    n1 = int(hash1, 16)
    n2 = int(hash2, 16)
    return bin(n1 ^ n2).count("1")


def is_similar(hash1: str, hash2: str, threshold: int = 3) -> bool:
    """判断两个指纹是否近似重复

    64 位 SimHash 经验阈值：汉明距离 ≤ 3 视为相似
    阈值越小越严格（误判少但漏判多），越大越宽松（漏判少但误判多）
    MVP 取 3 是业界常用值，对中文新闻标题效果良好
    """
    return hamming_distance(hash1, hash2) <= threshold
```

**性能**：单次计算约 1ms（50 字符标题），50-100 篇素材两两比较 < 0.1s，可接受。

### 7.2 热度计算公式

**模块路径**：`app/workflow/llm/rewriter.py::_heat_score`

**公式**：

```
热度 = 源权威度 × 0.3 + 标题关键词热度 × 0.4 + 发布时间近度 × 0.3
```

**三项权重设计理由**：
- 标题关键词热度权重最高（0.4），因为标题最能反映新闻重要性；
- 源权威度与时间近度权重相当（0.3），保证权威源 + 时效性的基础分；
- 三项均归一化到 [0, 1]，最终热度也在 [0, 1]。

```python
from datetime import datetime, timedelta

# 热点关键词词表（运营维护，可配置）
HOT_KEYWORDS = {
    "突破": 0.9, "首发": 0.85, "独家": 0.8, "重磅": 0.95,
    "发布": 0.6, "上市": 0.7, "收购": 0.75, "融资": 0.65,
    "政策": 0.7, "改革": 0.65, "制裁": 0.85, "合作": 0.55,
    # ... 运营按热度定期更新
}


def _keyword_heat(title: str) -> float:
    """标题关键词热度：取标题中命中的最热关键词的分值

    多个关键词命中取最大值（避免叠加导致偏差）
    无命中返回 0.3（基础分，避免完全无分）
    """
    max_score = 0.0
    for keyword, score in HOT_KEYWORDS.items():
        if keyword in title:
            max_score = max(max_score, score)
    return max_score if max_score > 0 else 0.3


def _recency_score(published_at: datetime) -> float:
    """发布时间近度：越近分越高

    24 小时内：1.0 → 0.5 线性衰减
    24-48 小时：0.5 → 0.2 线性衰减
    48 小时以上：0.2 → 0.0 线性衰减
    """
    if not published_at:
        return 0.5                       # 无发布时间取中值
    delta = datetime.utcnow() - published_at
    hours = delta.total_seconds() / 3600
    if hours <= 24:
        return 1.0 - (hours / 24) * 0.5  # 1.0 → 0.5
    elif hours <= 48:
        return 0.5 - ((hours - 24) / 24) * 0.3  # 0.5 → 0.2
    elif hours <= 72:
        return 0.2 - ((hours - 48) / 24) * 0.2  # 0.2 → 0.0
    else:
        return 0.0


def _heat_score(material: dict) -> float:
    """综合热度计算

    三项加权：
    - 源权威度 30%：来源在 rss.yaml 配置，权威媒体如新华/人民 0.9，自媒体 0.5
    - 关键词热度 40%：标题命中热点关键词
    - 时间近度 30%：发布越近分越高
    """
    authority = material.get("source_authority", 0.5)
    keyword_heat = _keyword_heat(material["title"])
    recency = _recency_score(material.get("published_at"))
    return authority * 0.3 + keyword_heat * 0.4 + recency * 0.3
```

### 7.3 敏感词过滤

**模块路径**：`app/workflow/llm/sensitive_filter.py`

**算法选择**：MVP 用 AC 自动机（Aho-Corasick）多模式匹配，O(N) 一次扫描全文命中所有敏感词，比朴素遍历快几个数量级。

```python
import ahocorasick

# 敏感词表加载（启动时一次性构建自动机，运行时只查询）
_automaton = ahocorasick.Automaton()


def load_words(file_path: str) -> None:
    """从敏感词文件加载，构建 AC 自动机

    文件格式：每行一个敏感词，# 开头为注释
    启动时调用一次，敏感词更新后需重启应用或调 reload
    """
    global _automaton
    _automaton = ahocorasick.Automaton()
    with open(file_path, encoding="utf-8") as f:
        for idx, line in enumerate(f):
            word = line.strip()
            if word and not word.startswith("#"):
                _automaton.add_word(word, (idx, word))
    _automaton.make_automaton()


def contains(text: str) -> bool:
    """快速判断文本是否包含任一敏感词

    用于 LLM 改写结果扫描：命中即重新生成
    """
    for _, (_, word) in _automaton.iter(text):
        return True
    return False


def find_all(text: str) -> list[str]:
    """找出文本中所有敏感词

    用于运营后台展示具体命中位置
    """
    return [word for _, (_, word) in _automaton.iter(text)]


def replace(text: str, mask: str = "*") -> str:
    """将敏感词替换为掩码字符

    用于 LLM 二次生成仍命中时的兜底处理
    """
    result = list(text)
    for end_idx, (_, word) in _automaton.iter(text):
        start_idx = end_idx - len(word) + 1
        for i in range(start_idx, end_idx + 1):
            result[i] = mask
    return "".join(result)
```

**双层过滤策略**：

```python
# 第一层：生成前 prompt 约束
PROMPT_CONSTRAINT = """
重要约束：
- 严禁出现以下类型词汇：政治敏感、暴力、色情、歧视性表达
- 严禁编造未经证实的信息
- 严禁出现具体人名负面评价
"""

# 第二层：生成后词表扫描
async def _rewrite_one(material: dict, retry_with_constraint: bool = False) -> dict:
    prompt = build_prompt(material, extra_constraint=PROMPT_CONSTRAINT if retry_with_constraint else None)
    text = await call_llm(prompt)
    if sensitive_filter.contains(text):
        if retry_with_constraint:
            # 二次生成仍命中，做替换兜底（不完美但保证可用）
            text = sensitive_filter.replace(text)
            logger.warning(f"素材 {material['id']} 二次生成仍含敏感词，已替换")
        else:
            # 首次命中，标记后重新生成
            raise SensitiveHitError("首次生成命中敏感词")
    return {"title": ..., "content": text, ...}
```

### 7.4 重试策略（tenacity）

**模块路径**：分散在 `app/workflow/llm/rewriter.py`、`app/workflow/tts/synthesizer.py`

**设计原则**：
- 仅对**可重试错误**重试（网络超时、API 限流、临时不可用）；
- **不可重试错误**（参数错误、内容审核拒绝、鉴权失败）立即失败；
- 指数退避避免雪崩；最大重试 3 次（含首次），总耗时上限可控。

```python
from tenacity import (
    retry, stop_after_attempt, wait_exponential,
    retry_if_exception_type, before_sleep_log,
)
import logging

logger = logging.getLogger(__name__)


# 通义千问 API 可重试错误
class LLMRateLimitError(Exception):
    """API 限流（429）"""
class LLMTimeoutError(Exception):
    """请求超时"""
class LLMServiceError(Exception):
    """服务端 5xx"""

# 不可重试错误
class LLMAuthError(Exception):
    """鉴权失败（API key 错误）"""
class LLMContentError(Exception):
    """内容审核拒绝（输入或输出违规）"""


# LLM 重试装饰器
llm_retry = retry(
    stop=stop_after_attempt(3),                              # 最多 3 次
    wait=wait_exponential(min=1, max=10, multiplier=1),      # 1s, 2s, 4s... 上限 10s
    retry=retry_if_exception_type(
        (LLMRateLimitError, LLMTimeoutError, LLMServiceError)
    ),
    before_sleep=before_sleep_log(logger, logging.WARNING),  # 重试前打日志
    reraise=True,                                            # 重试耗尽后抛出原异常
)


@llm_retry
async def call_llm(prompt: str) -> str:
    """LLM 调用，带重试

    异常映射：
    - HTTP 429 → LLMRateLimitError（重试）
    - HTTP 401 → LLMAuthError（不重试）
    - HTTP 400 含 "content_filter" → LLMContentError（不重试）
    - 超时 → LLMTimeoutError（重试）
    - HTTP 5xx → LLMServiceError（重试）
    """
    try:
        resp = await client.chat.completions.create(...)
        return resp.choices[0].message.content
    except openai.RateLimitError as e:
        raise LLMRateLimitError(str(e))
    except openai.AuthenticationError as e:
        raise LLMAuthError(str(e))
    except openai.APITimeoutError as e:
        raise LLMTimeoutError(str(e))
    except openai.APIConnectionError as e:
        raise LLMServiceError(str(e))
    except openai.InternalServerError as e:
        raise LLMServiceError(str(e))


# TTS 模块类似配置
tts_retry = retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(min=1, max=10),
    retry=retry_if_exception_type(
        (TTSRateLimitError, TTSTimeoutError, TTSServiceError)
    ),
    reraise=True,
)
```

**重试场景对照表**：

| 错误类型 | 是否重试 | 重试次数 | 退避策略 | 失败后处理 |
| --- | --- | --- | --- | --- |
| 网络超时 | 是 | 3 | 1s, 2s, 4s | 步骤失败，启用备播 |
| API 限流 429 | 是 | 3 | 1s, 2s, 4s | 步骤失败，启用备播 |
| 服务端 5xx | 是 | 3 | 1s, 2s, 4s | 步骤失败，启用备播 |
| 鉴权失败 401 | 否 | — | — | 立即失败，告警运维 |
| 内容审核拒绝 | 否 | — | — | 改用约束 prompt 重生成一次 |
| 参数错误 400 | 否 | — | — | 立即失败，记录 bug |
| SQLite BUSY/LOCKED | 是 | 3 | 50ms, 100ms, 200ms | 步骤失败，告警 |
| FFmpeg 失败 | 是 | 2 | 5s, 10s | 步骤失败，启用备播 |

> **V1.2 改造说明**：原 MySQL 死锁（InnoDB 行锁冲突）替换为 SQLite `SQLITE_BUSY`（写事务串行化冲突）。
> SQLite 在 WAL 模式下读不阻塞写、写不阻塞读，仅写-写冲突触发 BUSY。
> 通过 `PRAGMA busy_timeout = 5000` 让 SQLite 自动重试 5 秒，应用层 tenacity 仅作兜底。

### 7.5 APScheduler 触发容错

**解决方案**：

```python
self.scheduler.add_job(
```

### 9.2 `app/launcher.py` — 单机 exe 入口脚本（V1.2 替换 Dockerfile）

```python
# app/launcher.py
# 单机 exe 入口：注册 APScheduler 任务、启动 uvicorn、处理 Windows 信号优雅关闭
# PyInstaller 打包入口（见 8.6 20_news.spec 的 Analysis[0]）
import asyncio
import signal
import sys

import uvicorn
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from dotenv import load_dotenv

from app.config import settings
from app.paths import resolve_env_path
from app.workflow.scheduler import register_workflow_jobs


async def main():
    # 加载 .env（exe 同级目录，由 paths.py 解析）
    env_path = resolve_env_path()
    load_dotenv(env_path)

    # 注册 APScheduler 任务（工作流 + 备播检查 + 播放日志聚合 + 去重表清理）
    scheduler = AsyncIOScheduler(timezone=settings.APP_TIMEZONE)
    register_workflow_jobs(scheduler)
    scheduler.start()

    # 注册 Windows 信号处理（SIGINT=Ctrl+C, SIGTERM=停止）
    # PyInstaller 打包后需显式注册，否则无法优雅关闭
    stop_event = asyncio.Event()

    def _signal_handler(signum, frame):
        print(f"\n[launcher] 收到信号 {signum}，开始优雅关闭...")
        stop_event.set()

    signal.signal(signal.SIGINT, _signal_handler)
    signal.signal(signal.SIGTERM, _signal_handler)

    # 启动 uvicorn（嵌入方式，避免子进程）
    config = uvicorn.Config(
        "app.main:app",
        host=settings.APP_HOST,          # 127.0.0.1，仅本地监听
        port=settings.APP_PORT,
        workers=1,                        # 单 worker，避免 APScheduler 重复触发
        log_level=settings.LOG_LEVEL.lower(),
        access_log=True,
    )
    server = uvicorn.Server(config)

    # 并行运行 uvicorn 与 stop_event 等待
    server_task = asyncio.create_task(server.serve())
    stop_task = asyncio.create_task(stop_event.wait())

    # 任一任务完成即退出
    await asyncio.wait({server_task, stop_task}, return_when=asyncio.FIRST_COMPLETED)

    # 优雅关闭：停止调度器 → 停止 uvicorn
    scheduler.shutdown(wait=True)
    server.should_exit = True
    await server_task


if __name__ == "__main__":
    # PyInstaller 打包后 sys.frozen=True，开发态直接运行 python app/launcher.py
    if getattr(sys, 'frozen', False):
        print(f"[launcher] 打包模式启动，exe 路径: {sys.executable}")
    else:
        print("[launcher] 开发模式启动")
    asyncio.run(main())
```

> **关键设计点**：
> - **单 worker**：APScheduler 在多 worker 下会重复触发，必须 `workers=1`；
> - **嵌入 uvicorn**：避免 `uvicorn.run()` 创建子进程导致 PyInstaller 打包后信号传递异常；
> - **信号处理**：Windows 下 SIGTERM 由服务管理器或 `Stop-Process` 发送，需显式捕获；
> - **参考实现**：D:\code\otherProjects\17_xianyu\app\launcher.py 已验证此模式可行。

### 9.4 `app/paths.py` — 路径解析模块（V1.2 新增，替代 MySQL my.cnf）

```python
# app/paths.py
# 统一管理打包态与开发态的路径解析
# 核心问题：PyInstaller 打包后 __file__ 路径指向临时解压目录，
#   用户数据（SQLite、日志、.env）必须放在 exe 同级目录，否则升级后丢失
import os
import sys
from pathlib import Path


def is_frozen() -> bool:
    """是否为 PyInstaller 打包模式"""
    return getattr(sys, 'frozen', False)


def get_app_root() -> Path:
    """获取应用根目录
    - 打包态：exe 所在目录（如 C:\\Program Files\\20_News\\）
    - 开发态：项目根目录（app/ 的父目录）
    """
    if is_frozen():
        return Path(sys.executable).parent.resolve()
    # 开发态：app/paths.py 的上两级
    return Path(__file__).parent.parent.resolve()


def resolve_data_dir() -> Path:
    """数据目录（SQLite 数据库、WAL 文件）"""
    data_dir = get_app_root() / "data"
    data_dir.mkdir(parents=True, exist_ok=True)
    return data_dir


def resolve_db_path() -> Path:
    """SQLite 数据库文件路径"""
    return resolve_data_dir() / "news.db"


def resolve_log_dir() -> Path:
    """日志目录"""
    log_dir = get_app_root() / "logs"
    log_dir.mkdir(parents=True, exist_ok=True)
    return log_dir


def resolve_env_path() -> Path:
    """.env 配置文件路径（exe 同级）"""
    return get_app_root() / ".env"


def resolve_ffmpeg_path() -> str:
    """FFmpeg 可执行文件路径
    - 打包态：随 Inno Setup 安装到 ./ffmpeg/bin/ffmpeg.exe
    - 开发态：依赖系统 PATH
    """
    if is_frozen():
        bundled = get_app_root() / "ffmpeg" / "bin" / "ffmpeg.exe"
        if bundled.exists():
            return str(bundled)
    # 回退到系统 PATH
    return "ffmpeg"


def resolve_admin_dist() -> Path | None:
    """B 端运营后台静态资源目录（Vue 构建产物）
    - 打包态：嵌入 PyInstaller datas（见 8.6 spec）
    - 开发态：app/static/admin/dist
    """
    if is_frozen():
        # PyInstaller 打包后资源在 _MEIPASS 临时目录
        return Path(sys._MEIPASS) / "app" / "static" / "admin" / "dist"
    dev_dist = get_app_root() / "app" / "static" / "admin" / "dist"
    return dev_dist if dev_dist.exists() else None
```

> **设计要点**：
> - **`sys.frozen` 区分模式**：PyInstaller 打包后设置此属性，开发态为 False；
> - **`sys._MEIPASS`**：PyInstaller onefile 模式解压临时目录，只读资源（YAML、前端静态文件）从此读取；
> - **可写数据与只读资源分离**：`data/`、`logs/`、`.env` 在 exe 同级（可写），前端资源在 `_MEIPASS`（只读）；
> - **参考实现**：D:\code\otherProjects\17_xianyu\app\paths.py 已验证此模式。

```python
from app.models import (  # noqa: F401

async def init_database(engine: AsyncEngine) -> None:
    """初始化 SQLite 数据库
    - 首次启动：创建所有表（14 张）
    - 已存在：跳过建表（create_all 默认 checkfirst=True）
    - PRAGMA 配置：WAL 模式 + busy_timeout + synchronous
    """
    db_path = resolve_db_path()
    logger.info(f"[init_db] SQLite 数据库路径: {db_path}")

    # 通过 PRAGMA 配置 SQLite（每个连接独立设置，需在连接建立时执行）
    # 这里通过 SQLAlchemy 事件监听器统一注入（见 app/db/session.py 的 _set_pragma）
    async with engine.begin() as conn:
        # 建表（幂等，已存在则跳过）
        await conn.run_sync(Base.metadata.create_all)
        logger.info("[init_db] 表结构检查完成（14 张表）")

        # 初始化种子数据（admin_user 默认账号，仅首次创建）
        await _seed_default_admin(conn)


async def _seed_default_admin(conn) -> None:
    """种子数据：默认管理员账号（首次启动）
    账号：admin / 密码：admin123（首次登录强制修改）
    """
    from sqlalchemy import select
    from app.models.admin_user import AdminUser
    from app.services.auth_service import hash_password

    result = await conn.execute(select(AdminUser).where(AdminUser.username == "admin"))
    if result.scalar_one_or_none() is None:
        admin = AdminUser(
            username="admin",
            password_hash=hash_password("admin123"),
            display_name="系统管理员",
            role="super_admin",
            must_change_password=True,    # 首次登录强制改密
        )
        await conn.execute(admin.__table__.insert().values(admin.__dict__))
        logger.warning("[init_db] 已创建默认管理员 admin/admin123，请尽快修改密码！")
```

> **与 MySQL init.sql 的差异**：
> - **无需授权语句**：SQLite 是嵌入式数据库，无账号管理，移除 `CREATE USER`、`GRANT`；
> - **无需字符集配置**：SQLite 默认 UTF-8，移除 `CHARACTER SET utf8mb4`；
> - **PRAGMA 替代 my.cnf**：SQLite 的 `journal_mode=WAL`、`busy_timeout`、`synchronous` 通过连接级 PRAGMA 设置（见 2.18）；
> - **表结构由 ORM 管理**：`Base.metadata.create_all` 自动建表，无需 `init.sql` 脚本。

### 10.2 `miniprogram/services/api.js` — API 封装

```javascript
// services/api.js
// 统一请求封装：token 注入、401 自动重登、统一响应格式处理
const { getToken, refreshToken } = require('./auth');

const BASE_URL = 'https://api.example.com/api/v1';

async function request(options) {
  const { url, method = 'GET', data, header = {} } = options;

  // 注入 token
  const token = getToken();
  if (token) {
    header.Authorization = `Bearer ${token}`;
  }

  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + url,
      method,
      data,
      header: { 'Content-Type': 'application/json', ...header },
      success: async (res) => {
        // 401 自动重登一次
        if (res.statusCode === 401) {
          try {
            await refreshToken();
            // 重试原请求
            const retry = await request(options);
            resolve(retry);
          } catch (e) {
            reject(new Error('登录已失效，请重新打开小程序'));
          }
          return;
        }
        // 业务错误（code != 0）
        if (res.data.code !== 0) {
          reject(new Error(res.data.message || '请求失败'));
          return;
        }
        resolve(res.data.data);
      },
      fail: (err) => reject(new Error('网络异常')),
    });
  });
}

// 各接口封装
const fetchTodayEpisode = () => request({ url: '/episodes/today' });
const fetchEpisodeDetail = (id) => request({ url: `/episodes/${id}` });
const fetchEpisodeScript = (id) => request({ url: `/episodes/${id}/script` });
const fetchHistory = (page, size = 20) =>
  request({ url: '/episodes/history', data: { page, size } });
const reportPlayProgress = (data) =>
  request({ url: '/playlogs/progress', method: 'POST', data });
const fetchPlayProgress = (episodeId) =>
  request({ url: `/playlogs/progress/${episodeId}` });

module.exports = {
  request, fetchTodayEpisode, fetchEpisodeDetail,
```

### 10.3 `miniprogram/services/auth.js` — 登录鉴权

```javascript
// services/auth.js
// 微信登录流程：wx.login → 后端换 token → 本地缓存
const STORAGE_KEY_TOKEN = 'news_token';
const STORAGE_KEY_USER = 'news_user';

function getToken() {
  return wx.getStorageSync(STORAGE_KEY_TOKEN);
}

function setToken(token, user) {
  wx.setStorageSync(STORAGE_KEY_TOKEN, token);
  wx.setStorageSync(STORAGE_KEY_USER, user);
}

function clearToken() {
  wx.removeStorageSync(STORAGE_KEY_TOKEN);
  wx.removeStorageSync(STORAGE_KEY_USER);
}

// 登录：wx.login 获取 code → 调后端换 token
function login() {
  return new Promise((resolve, reject) => {
    wx.login({
      success: async (res) => {
        if (!res.code) {
          reject(new Error('wx.login 未返回 code'));
          return;
        }
        // 调后端 /auth/login
        wx.request({
          url: 'https://api.example.com/api/v1/auth/login',
          method: 'POST',
          data: { code: res.code },
          success: (resp) => {
            if (resp.data.code === 0) {
              setToken(resp.data.data.token, resp.data.data.user);
              resolve(resp.data.data);
            } else {
              reject(new Error(resp.data.message));
            }
          },
          fail: (err) => reject(err),
        });
      },
      fail: (err) => reject(err),
    });
  });
}

// 刷新 token（401 时自动调用，实际是重新 wx.login）
async function refreshToken() {
  clearToken();
  const { token, user } = await login();
  return { token, user };
}

// 登出
async function logout() {
  // 调后端登出接口（写 COS jwt_blacklist/{jti}.json + SQLite jwt_blacklist 表）
  const token = getToken();
  if (token) {
    wx.request({
      url: 'https://api.example.com/api/v1/auth/logout',
      method: 'POST',
      header: { Authorization: `Bearer ${token}` },
      complete: () => {
        clearToken();
      },
    });
  }
}

module.exports = { getToken, setToken, clearToken, login, refreshToken, logout };
```

### 10.4 `miniprogram/services/audio.js` — 全局播放器

```javascript
// services/audio.js
// 全局音频播放器：基于 wx.getBackgroundAudioManager 单例
// 支持：锁屏播放、断点续播、进度上报、来电暂停
const { reportPlayProgress, fetchPlayProgress } = require('./api');

let audioManager = null;
let progressTimer = null;     // 进度上报定时器
let currentEpisode = null;    // 当前播放的节目

function initPlayer() {
  if (audioManager) return audioManager;

  audioManager = wx.getBackgroundAudioManager();

  // 播放结束：标记完播，上报
  audioManager.onEnded(() => {
    if (currentEpisode) {
      reportPlayProgress({
        episode_id: currentEpisode.id,
        position: audioManager.duration,
        duration: audioManager.duration,
        completed: true,
      });
    }
    stopProgressReport();
  });

  // 播放暂停：停止进度上报
  audioManager.onPause(() => {
    stopProgressReport();
    // 暂停时立即上报一次当前位置
    if (currentEpisode) {
      reportPlayProgress({
        episode_id: currentEpisode.id,
        position: audioManager.currentTime,
        duration: audioManager.duration,
        completed: false,
      });
    }
  });

  // 播放恢复：重启进度上报
  audioManager.onPlay(() => {
    startProgressReport();
  });

  // 播放错误
  audioManager.onError((err) => {
    console.error('播放错误', err);
    wx.showToast({ title: '音频加载失败', icon: 'none' });
  });

  return audioManager;
}

// 播放指定节目（自动断点续播）
async function playEpisode(episode) {
  currentEpisode = episode;

  // 查询上次播放进度（断点续播）
  let startPosition = 0;
  try {
    const progress = await fetchPlayProgress(episode.id);
    if (progress && progress.position > 0 && !progress.completed) {
      startPosition = progress.position;
    }
  } catch (err) {
    console.warn('获取播放进度失败，从开头播放', err);
  }

  // 设置播放源（title 必填，否则锁屏不显示）
  audioManager.title = episode.title;
  audioManager.epname = episode.title;
  audioManager.src = episode.audio_url;

  // 跳转到上次位置（需等待音频元数据加载完成）
  if (startPosition > 0) {
    audioManager.onCanplay(() => {
      audioManager.seek(startPosition);
    });
  }
}

// 启动进度上报（每 5 秒一次）
function startProgressReport() {
  stopProgressReport();
  progressTimer = setInterval(() => {
    if (currentEpisode && audioManager.duration > 0) {
      reportPlayProgress({
        episode_id: currentEpisode.id,
        position: Math.floor(audioManager.currentTime),
        duration: Math.floor(audioManager.duration),
        completed: false,
      });
    }
  }, 5000);
}

function stopProgressReport() {
  if (progressTimer) {
    clearInterval(progressTimer);
    progressTimer = null;
```

```javascript
import axios from 'axios';
import { useUserStore } from '../stores/user';
import router from '../router';

const api = axios.create({
  baseURL: '/admin/api/v1',
  timeout: 15000,
});

// 请求拦截：注入 token
api.interceptors.request.use((config) => {
  const userStore = useUserStore();
  if (userStore.token) {
    config.headers.Authorization = `Bearer ${userStore.token}`;
  }
  return config;
});

// 响应拦截：统一错误处理
api.interceptors.response.use(
  (response) => {
    if (response.data.code !== 0) {
      return Promise.reject(new Error(response.data.message));
    }
    return response.data.data;
  },
  (error) => {
    if (error.response?.status === 401) {
      // token 失效，跳转登录
      const userStore = useUserStore();
      userStore.clearToken();
      router.push('/login');
    } else if (error.response?.status === 403) {
      ElMessage.error('无权限执行此操作');
    } else {
      ElMessage.error(error.response?.data?.message || '请求失败');
    }
    return Promise.reject(error);
  }
);

export default api;
```

```javascript
export const useUserStore = defineStore('user', {
  state: () => ({
    token: localStorage.getItem('admin_token') || '',
    username: localStorage.getItem('admin_username') || '',
    role: localStorage.getItem('admin_role') || '',
  }),

  },

      this.username = data.username;
      this.role = data.role;

      localStorage.setItem('admin_username', data.username);
      localStorage.setItem('admin_role', data.role);

        await api.post('/auth/logout');

        this.clearToken();
      }

      this.username = '';
```

### 13.6 云函数 SCF 设计（V1.2 新增）

**设计目的**：C 端 5 个高频接口由云函数 SCF 承载，直接读写 COS 对象，与单机 exe 解耦。避免小程序直连单机 exe 的网络延迟与 NAT 穿透问题。

**函数清单**：

| 函数名 | 对应接口 | COS 对象路径 | 说明 |
| --- | --- | --- | --- |
| episodes_today | GET /episodes/today | `episodes/today/{yyyymmdd}.json` | 今日节目单例对象 |
| episodes_history | GET /episodes/history | `episodes/history/{yyyymm}.json` | 当月历史列表 |
| episodes_detail | GET /episodes/{id} | `episodes/detail/{episode_id}.json` | 节目详情（含稿件+分段） |
| playlogs | POST /playlogs/progress、GET /playlogs/progress/{id} | `play_progress/{user_id}/{episode_id}.json`、`playlogs/{yyyymmdd}/{session_id}.json` | 播放进度读写 + 日志异步聚合 |
| feedbacks | POST /feedbacks | `feedbacks/{feedback_id}.json` | 用户反馈提交 |

**通用架构**（5 个函数共享）：

```python
# scf/common/handler_base.py
# 云函数通用基类：JWT 验证 + COS 客户端 + 黑名单缓存
import json
import time
from functools import lru_cache

import jwt
from qcloud_cos import CosConfig, CosS3Client

# SCF 冷启动时初始化（全局单例，复用连接）
_config = CosConfig(
    Region=os.environ["COS_REGION"],
    SecretId=os.environ["COS_SECRET_ID"],
    SecretKey=os.environ["COS_SECRET_KEY"],
)
cos_client = CosS3Client(_config)
JWT_SECRET = os.environ["JWT_SECRET"]
COS_BUCKET = os.environ["COS_BUCKET"]

# JWT 黑名单内存缓存（TTL 5 分钟，过期后重新拉取 COS）
_blacklist_cache = {"data": set(), "expires_at": 0}
BLACKLIST_TTL_SEC = int(os.environ.get("JWT_BLACKLIST_CACHE_TTL_SEC", 300))


def verify_token(event: dict) -> dict:
    """验证 JWT token，返回 payload
    1. 从 Authorization header 提取 token
    2. jwt.decode 验证签名与有效期
    3. 检查 jti 是否在黑名单中（内存缓存 + COS 拉取）
    """
    auth_header = event.get("headers", {}).get("Authorization", "")
    token = auth_header.replace("Bearer ", "")
    payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])

    # 检查黑名单缓存是否过期
    now = time.time()
    if now > _blacklist_cache["expires_at"]:
        _refresh_blacklist_cache()

    if payload["jti"] in _blacklist_cache["data"]:
        raise Exception("token已失效（黑名单）")

    return payload


def _refresh_blacklist_cache():
    """从 COS 拉取当前所有黑名单 jti
    黑名单对象路径：jwt_blacklist/{jti}.json
    通过 COS list_objects 列举前缀，汇总未过期的 jti
    """
    response = cos_client.list_objects(
        Bucket=COS_BUCKET, Prefix="jwt_blacklist/"
    )
    blacklist = set()
    for obj in response.get("Contents", []):
        # 对象名为 jwt_blacklist/{jti}.json，提取 jti
        jti = obj["Key"].split("/")[-1].replace(".json", "")
        blacklist.add(jti)
    _blacklist_cache["data"] = blacklist
    _blacklist_cache["expires_at"] = time.time() + BLACKLIST_TTL_SEC


def json_response(data: dict, status_code: int = 200) -> dict:
    """SCF 标准响应格式（与 FastAPI 统一）"""
    return {
        "statusCode": status_code,
        "headers": {"Content-Type": "application/json; charset=utf-8"},
        "body": json.dumps({"code": 0, "data": data}, ensure_ascii=False),
    }


def error_response(message: str, code: int = -1, status_code: int = 400) -> dict:
    """错误响应"""
    return {
        "statusCode": status_code,
        "headers": {"Content-Type": "application/json; charset=utf-8"},
        "body": json.dumps({"code": code, "message": message}, ensure_ascii=False),
    }
```

**今日节目函数示例**：

```python
# scf/episodes_today.py
# C 端接口：GET /episodes/today
# 直接读取 COS 对象 episodes/today/{yyyymmdd}.json，无需访问单机 SQLite
from datetime import date
from scf.common.handler_base import cos_client, COS_BUCKET, json_response, verify_token


def handler(event, context):
    """SCF 入口：返回今日节目"""
    # 1. 验证 token（C 端接口需登录）
    try:
        verify_token(event)
    except Exception as e:
        return error_response(str(e), status_code=401)

    # 2. 从 COS 读取今日节目对象
    today = date.today().strftime("%Y%m%d")
    key = f"episodes/today/{today}.json"
    try:
        response = cos_client.get_object(Bucket=COS_BUCKET, Key=key)
        body = response["Body"].read().decode("utf-8")
        import json
        episode_data = json.loads(body)
        return json_response(episode_data)
    except Exception:
        # 今日节目尚未发布（工作流未完成或备播未启用）
        return json_response(None, status_code=200)
```

> **云函数 SCF 设计要点**：
> - **冷启动优化**：全局单例初始化 COS 客户端与 JWT 配置，避免每次请求重复创建；
> - **黑名单缓存**：内存缓存 TTL 5 分钟，过期后批量拉取 `jwt_blacklist/` 前缀对象，避免每次请求都查 COS；
> - **幂等读取**：COS GET 幂等，今日节目未发布时返回 `null`，小程序端处理空状态；
> - **与单机 exe 解耦**：SCF 仅读 COS 对象，不访问单机 SQLite，单机 exe 离线时 C 端仍可正常读历史节目；
> - **播放进度写入**：`playlogs` 函数直接写 COS 对象 `play_progress/{user_id}/{episode_id}.json`，单机 exe 的 APScheduler 定时任务（`_flush_playlogs_from_cos`）批量拉取并聚合到 SQLite `play_log` 表（详见 5.1）。
