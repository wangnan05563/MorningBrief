| 日期 | 2026-08-11 |

## 1. 背景与目标

### 1.1 背景
当前运营端管理系统（`admin-web`，基于 Vue 3 + Element Plus）**仅面向 PC 桌面端**，核心运维动作（数据查看、内容审批、告警接收、用户反馈处理）均需在固定工位完成。随着运营节奏外移化，以下现实诉求长期未被满足：

- 运营/审核人员需在通勤、出差、会议间隙随时 **查看核心数据**、**处理待审内容**、**接收系统告警**；
- 现有后台已沉淀完整后端能力（`/admin/api/v1/*` 共 21 个路由前缀，覆盖统计、审核、通知、频道、素材、广告、工作流、队列、系统、备份等），移动端可**复用既有 API 与服务层**，无需重建业务逻辑；
- 现有 `notification` 模块仅面向**终端用户**下发消息，**缺少运营人员自身的消息收件箱与推送通道**，是移动化必须补齐的缺口。

### 1.2 目标
1. 在现有工程中**新增移动端适配模式**，复用鉴权、API 服务层与 Pinia stores，PC 包体不受影响（路由级 code-split）。
2. 明确 **PC ↔ 移动** 功能差异边界，按"全功能迁移 / 简化适配 / 仅 PC 保留"三类划分，避免盲目全量搬运。
3. 定义移动端**交互设计规范**（触摸友好布局、手势、导航、响应式断点）。
4. 输出**可追踪、可验收**的需求清单，作为研发直接开发依据。

### 1.3 非目标（明确排除）
- 不重建后端业务逻辑，仅按需**新增少量移动专属接口**（收件箱、推送注册、设备登记、应急停服）。
- 不做终端用户（C 端小程序）改造，仅限运营后台。
- 首版不实现离线完整编辑、不实现复杂多维数据下钻。

## 2. 用户角色与使用场景

### 2.1 角色定义
| 角色 | 说明 | 移动端主要动作 |
|---|---|---|
| 超级管理员（super_admin） | 拥有全部权限，含系统应急与配置 | 健康看板、应急停服、全局审批 |
| 运营管理员（ops_admin） | 负责日常运营、频道/广告/数据 | 数据概览、频道/广告启停、用户管理 |
| 内容审核员（reviewer） | 负责内容审核与自动审核策略巡查 | 待审列表、通过/驳回、批量审批 |
| 客服/反馈处理员（support） | 负责终端用户反馈处理 | 反馈列表、状态流转、用户检索 |

> 角色与权限继承现有 `admin_user.role` 体系，移动端不做独立 RBAC，仅按角色过滤可见模块。

### 2.2 典型使用场景
| 场景 | 触发 | 移动端价值 | 对应模块 |
|---|---|---|---|
| S1 通勤看数 | 每日早间 | 秒级查看昨日 DAU/播放/完播 | M2 数据概览 |
| S2 外出审批 | 收到待审推送 | 随时随地通过/驳回，不积压 | M3 审批中心 |
| S3 告警响应 | 服务异常推送 | 即时查看健康看板、必要时应急停服 | M4 消息中心 + M9 应急 |
| S4 反馈处理 | 用户投诉推送 | 检索用户、处理反馈闭环 | M5 用户与反馈 |
| S5 现场启停 | 活动临时调整 | 频道/广告一键启停 | M6 / M7 |
| S6 任务监控 | 生产队列积压 | 查看任务状态、重试/取消 | M8 工作流/队列 |

## 3. 移动端与 PC 端功能差异边界

依据"使用频率、交互复杂度、操作风险"三维评估，将现有模块划入三类。**所有"仅 PC 保留"模块在移动端路由层不可达（返回引导回 PC 的提示）。**

| 现有模块（admin-web view / 后端 prefix） | 类别 | 移动端范围 | 划分依据 |
|---|---|---|---|
| 数据概览 `stats` | **全功能迁移** | 核心指标卡片 + 趋势迷你图 + 区间筛选 | 高频外勤查看，移动优先场景 |
| 审批中心 `reviews` / `auto-review` | **全功能迁移（交互简化）** | 待审列表 / 详情 / 通过拒绝 / 批量 / 自动审核启停 | 移动最高频动作 |
| 消息中心（**新增** admin inbox） | **全功能迁移** | 消息列表 / 未读 / 标记已读 / 分类跳转 | 移动天然适配推送 |
| 用户与反馈 `feedbacks` + 终端用户视图 | **简化适配** | 用户检索 / 启停 / 反馈列表处理 | 处理动作移动可做，深度画像 PC |
| 频道速览 `channels` | **简化适配** | 状态 / 开关 / 今日产量 | 新建与复杂配置 PC |
| 广告速览 `ads` | **简化适配** | 广告位状态 / 成效卡片 / 启停 | 创意编辑 PC |
| 工作流/队列监控 `workflows` `/queue` | **简化适配** | 任务状态 / 重试 / 取消 / 队列健康 | 编排编辑 PC |
| 系统告警与应急 `system` `/maintenance` | **简化适配（只读 + 应急）** | 健康状态 / 告警 / 一键停服（强确认） | 危险操作需二次验证 |
| 素材管理 `materials` | **简化适配（仅查看）** | 上传状态 / 列表 | 编辑/切块 PC |
| AI 配置 `ai` | **仅 PC 保留** | — | 复杂表单、模型选择 |
| 云端存储 `cos` | **仅 PC 保留** | — | 文件管理重交互 |
| 脚本/工具 `scripts` `/tools` | **仅 PC 保留** | — | 运维专用 |
| 数据库管理 `db-admin` | **仅 PC 保留** | — | 高危 |
| 备份/恢复 `backups` | **仅 PC 保留** | — | 高危 |
| 隧道 `tunnel` | **仅 PC 保留** | — | 专用通道 |
| 关于/帮助 `about` `/help` | **简化适配** | 静态页 | 低风险 |

## 5. 非功能性需求

| ID | 类别 | 需求 |
|---|---|---|
| NFR-M101 | 性能 | 首屏 ≤ 3s（3G 等效网络）；路由切换 ≤ 1s；列表接口 p95 ≤ 800ms；`/m` 分包 gzip ≤ 300KB；图片 WebP + 懒加载；禁重型图表/表格库 |
| NFR-M102 | 兼容性 | iOS Safari 14+、Android Chrome 90+；企业微信 / 钉钉 WebView；主适配宽度 320–480 逻辑像素，平板 768 做响应式双列；`safe-area-inset` 适配刘海/底部条 |
| NFR-M103 | 安全性 | JWT 短期化（access ≤ 15min + refresh）；移动端 token **不落明文 localStorage**，走 HttpOnly Cookie 或系统安全存储；敏感操作（启停/应急/用户禁用）二次认证；设备绑定；全链路 TLS1.2+；越权防护复用 `get_current_admin` 守卫；操作审计复用 `audit_log` |
| NFR-M104 | 可用性 | 关键指标离线可读缓存；弱网自动重试（指数退避）；操作失败可回退、可重试；空/错/加载三态完备 |
| NFR-M105 | 可维护性 | 复用现有 API/store；移动组件库（建议 Vant 4）与 PC（Element Plus）**物理隔离**，互不影响；移动端总开关走配置（feature flag），契合既有"新功能需配置开关门禁"纪律（`R230`） |

## 6. 交互设计规范

| ID | 维度 | 规范 |
|---|---|---|
| IDD-M101 | 布局 | 移动优先单列；底部 Tab Bar（4–5 项）；顶部 App Bar（标题 + 返回）；内容区卡片化；遵循 `safe-area-inset` |
| IDD-M102 | 手势 | 下拉刷新、上拉加载更多、左滑列表项操作（删除/批量）、右滑返回、长按弹出菜单；**禁用 hover 依赖** |
| IDD-M103 | 导航 | 栈式导航 + 底部 Tab；支持深链（消息 → 审批详情）；面包屑简化为"返回" |
| IDD-M104 | 响应式断点 | `<480` 手机单列；`481–768` 大屏手机/小平板（列宽微调）；`>768` 引导回 PC 或响应式双列 |
| IDD-M105 | 组件 | 触控目标 ≥ 44×44pt；正文字号 ≥ 14sp；主色沿用品牌；支持暗色模式（可选） |
| IDD-M106 | 表单 | 分步/折叠；大输入框；优先选择器代替手输；提交前校验 + 确认弹窗；错误内联提示 |

| `/admin/api/v1/queue` (status) | 队列健康 | FR-M802 |
| `/admin/api/v1/system` `/maintenance` | 健康看板 | FR-M901 |
| `/admin/api/v1/auth` (login/logout) | 移动登录 | FR-M102 |

### 7.2 新增接口清单
| ID | 接口 | 方法 | 说明 | 对应 FR |
|---|---|---|---|---|
| INT-M101 | `/admin/api/v1/m/inbox` | GET | 运营消息收件箱：列表 / `unread_count` / `mark_read` | FR-M401 |
| INT-M102 | `/admin/api/v1/m/push/register` | POST | 登记设备 push token（平台 + token + 设备指纹） | FR-M402, FR-M103 |
| INT-M103 | `/admin/api/v1/m/device/register` | POST | 设备登记与绑定（新设备风控） | FR-M103 |
| INT-M104 | `/admin/api/v1/m/dashboard-summary` | GET | 移动首页聚合（待办数 + 今日指标 + 未读），减少首屏并发请求 | FR-M104 |
| INT-M105 | `/admin/api/v1/m/emergency/stop` | POST | 一键应急停服（super_admin + 二次验证 + 审计） | FR-M902 |

> 新增接口的阈值/上限（如批量审批上限、推送频率）全部走配置，零硬编码（`R230` 纪律）。

### 7.3 推送方案
- 复用现有 `notification_log` / `notification_template` 记录触达；新增 `AdminDevice` 表登记设备与 token。
- 通道：iOS APNs、安卓厂商通道、企业微信应用消息（运营系统多经企业微信访问，优先对接）。

### 7.4 鉴权
- 复用 JWT + `get_current_admin` 守卫；移动端新增可选 `require_mobile` 作用域以区分来源。
- Token 存储：优先 HttpOnly Cookie（防 XSS 窃取）；若走 App WebView，使用系统安全存储，禁止明文 `localStorage`。

### 7.5 数据模型（新增 / 复用）
| 模型 | 类型 | 说明 |
|---|---|---|
| `AdminDevice` | **新增** | 设备登记表：admin_id、platform、push_token、device_fingerprint、bound_at |
| `AdminMessage` / `AdminInbox` | **新增** | 运营消息：type、level、payload、read、created_at |
| `notification_log` / `notification_template` | 复用 | 触达记录与模板 |
| `audit_log` | 复用 | 敏感操作审计 |
| `admin_user`(role/status) | 复用 | 角色与可见模块过滤 |

## 8. 验收标准

### 8.1 功能验收

## 9. 附录

### 9.1 术语表
- **admin-web**：运营端 PC 前端（Vue 3 + Element Plus）。
- **/m 命名空间**：本方案新增的移动端路由隔离前缀。
- **收件箱（Inbox）**：运营人员自身消息中心，区别于面向终端用户的 `notification` 下发。
- **二次验证**：新设备/敏感操作时的额外身份确认。

### 9.2 待确认决策（需评审拍板）
1. **移动端形态**：独立 H5（`/m` 路由）vs 内嵌 WebView vs 微信/企业微信小程序？建议首版独立 H5，复用工程最低成本。
2. **推送通道**：优先企业微信应用消息，还是自建 APNs/厂商通道？
3. **离线范围**：首版是否需离线可读关键指标（影响缓存架构）？
4. **设备级 RBAC**：是否需在 `admin_user.role` 之外增加设备/地点维度风控？
5. **终端用户管理接口**：`FR-M501` 复用还是新建 admin 用户视图（现有 `api/users.py` 为 C 端）。
