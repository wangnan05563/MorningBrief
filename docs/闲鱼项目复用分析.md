## 六、不建议复用的模块

| 模块 | 原因 |
|---|---|
| SheetWorkspace 多标签页 | React 专有设计，Vue 3 无直接对应；20_News 后台页面数量少（9 个），标签页收益低 |

| 移动端独立路由 | 17_xianyu 是 React PWA，20_News 是微信小程序原生开发，架构不同 |
| 菜单元数据 SSOT | 20_News 后台菜单固定（9 页），无动态菜单需求 |

## 九、总结

17_xianyu 项目在**基础设施层**（日志、密钥、事件总线、LRU、AI 用量）、**通知体系**（注册表 + 多渠道 + 免打扰）、**前端工程化**（API 模块化、Store 拆分、实时刷新、配置 Diff）三方面有大量成熟实践可直接借鉴。

**不建议复用**的业务专有模块（闲鱼反爬、Cookie 自愈、智能客服 RAG、多标签页工作区）已明确排除。

**推荐优先级**：先完成 P0 基础设施增强（日志 + 请求 ID + 健康检查 + 限流 + AI 预算），再推进 P1 安全与配置增强（keyring + YAML + 事件总线 + 通知器），前端工程化与文档结构化可独立并行迭代。

**已确认的硬约束**（见 `project_memory.md`）：所有改动须保持 V1.2 架构（SQLite + TTLCache + 单机 exe，不引入 MySQL/Redis/Docker）；`.bat` GBK + chcp 936 + CRLF；`.ps1` UTF-8 BOM + CRLF；Python 3.12 优先。
